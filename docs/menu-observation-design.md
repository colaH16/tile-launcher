# 외부 메뉴 자동 수집

갱신일: 2026-10-13. R79의 검토를 거쳐 R80–R82에서 **실험 기능으로 구현**했다. 아래 구현 설명과 실제 외부 앱 수신 검증은 구분하며 최신 결과는 validation.md를 확인한다.

## 가능성

사용자는 메뉴를 마우스로 누르면 해당 단축키를 알려주는 앱을 예전에 사용한 경험을 근거로 들었다. 그 앱 이름은 확인하지 못했지만, 현재 [Keysi 제작사](https://keysi.io/press.html)는 접근성 API로 메뉴를 읽고 마우스로 선택한 명령의 단축키를 알려주는 Shortcut Coach를 설명한다. 기능이 실제로 구현된 비교 사례이며 우리 앱의 지원률을 검증한 결과는 아니다.

Apple은 [메뉴 선택 알림](https://developer.apple.com/documentation/applicationservices/kaxmenuitemselectednotification?language=objc)과 [AXObserver 등록 API](https://developer.apple.com/documentation/applicationservices/1462089-axobserveraddnotification)를 제공한다. 로컬 Xcode beta SDK에도 AXMenuOpened/AXMenuClosed/AXMenuItemSelected가 있다. 따라서 **지원하는 앱의 메뉴 선택을 자동으로 기록하는 구현은 가능하다**고 판단한다.

모든 앱의 모든 메뉴 동작을 동일하게 수집한다는 보장은 없다. AXObserver 등록은 notificationUnsupported 등으로 실패할 수 있다. [Keysi의 지원 관련 설명](https://keysi.io/privacy.html)에도 앱에 따라 메뉴 열림 알림을 받지 못하는 사례가 나온다. 해당 제품의 내부 구현 코드나 Finder/Excel의 현 OS 실기 동작까지 확인한 것은 아니다.

## 구현 범위 · R80–R82

1. 사용자가 앱별 사전 선택 없이 모든 앱의 메뉴 막대를 요청했다. 설정 → 메뉴의 전체 수집은 기본 켜기다. 일반 앱의 파일/편집/이동/도움말 메뉴가 대상이며 리본/우클릭/상태 막대 전용 앱은 제외한다. 전체 끄기·앱별 중단을 제공한다.
2. 전경 일반 앱 하나의 메뉴 열림/선택 알림을 관찰하고 앱 전환 시 관찰 대상을 교체한다. R87에서 사용자가 이 방식을 확정했으며, 안정성 점검은 대상 전환과 연결 실패·재시작 복구에 집중한다. 알림이 없을 때도 클릭 위치의 접근성 항목으로 보완한다. 메뉴 전체를 주기적으로 스캔하지 않는다.
3. 메뉴 항목 안에서 마우스를 놓거나 열린 메뉴/Help에서 Return·키패드 Enter로 확정한 입력과 접근성 항목을 연결한다. 알림만으로 횟수를 올리지 않는다. 메뉴 막대까지 이어지는 부모 경로를 확인하고 활성 leaf 항목만 기록한다.
4. 앱 ID·메뉴 경로를 저장하고 최근 목록에 자동 추가한다. 경로가 같으면 기존 ID/핀/수동 순서를 유지하며 외부 선택 횟수·최근 시각을 갱신한다. 복사·붙여넣기도 같은 규칙으로 수집한다. Command/Option/Control 조합으로 직접 실행한 동작과 Esc/키 반복은 제외한다.
5. 기존 작은/가로형·빈도·고정 배치에 연결한다. 고정하면 수동 순서를 유지하고 자동 수집 갱신이 사용자의 선택 중 타일을 재배치하지 않도록 한다.
6. 자동 목록 비우기·삭제한 명령 재수집 제외·숨긴 메뉴 복원·앱별 중단을 제공한다. 전체 해제/권한 상실 시 수집용 입력 모니터/관찰자를 정리한다. 수동 등록과 고정은 보존한다.
7. R83이 초기 개수 제한을 대체한다. 앱별 최근 30일 또는 최근 5개를 유지하고, 자주 사용은 최근 90일 내 3회다. 두 기간은 설정에서 변경한다. 고정 메뉴는 최근 5개 자리를 소비하지 않는다. 숨겨진 메뉴는 설정에서 재고정/기간 확대로 복구할 수 있다. 고정/미사용 수동 등록도 유지한다.

## 구현할 때 구분해야 할 것

- 메뉴 선택 알림은 문서 저장/내보내기 등의 **최종 작업 성공**을 알려주는 이벤트가 아니다. 외부 선택 기록과 런처의 AXPress 요청 성공 기록을 구분하고 중복으로 세지 않는다.
- hover/메뉴 탐색/취소를 실행 횟수로 잘못 세지 않도록 앱별 실기로 확인해야 한다. 상위 메뉴 열기만으로 최근 사용에 넣지 않는다.
- R82에 따라 기본 편집 명령의 이름/단축키 필터는 넣지 않는다. 단축키 입력은 수집하지 않고 메뉴에서 고른 Copy/Paste도 수집한다. 입력 감시는 keyCode/보조키/Return/Esc 여부만 분류하며 characters나 Help 검색어/텍스트 값은 읽어 저장하지 않는다.
- ‘최근 문서’, 창 제목, 최근 폴더처럼 내용이 변하는 항목은 안정된 명령 경로와 구분한다. 재실행 시 다른 문서를 가리킬 수 있으므로 첫 범위에서는 동적 항목을 제외하는 편이 낫다.
- AX 객체는 메뉴가 닫히거나 앱이 재시작하면 무효가 될 수 있다. 오래된 객체를 실행에 재사용하지 않고 선택 시 현재 메뉴 경로·활성 상태를 다시 확인한다.
- 불완전한 수집은 표시하고 수동 등록을 유지한다. 지원되지 않는 앱을 지원한다고 표시하거나 누락을 실제 미사용으로 해석하지 않는다.

## 검증 순서

Finder의 ‘폴더로 이동…’처럼 경로가 안정적인 메뉴를 첫 대상으로 삼는다. 마우스 클릭/키보드 메뉴 탐색/단축키/취소를 나누고 한 동작당 한 기록인지 검사한다. 이후 사용자에게 필요한 Excel 메뉴 등으로 확대한다. 등록 API가 성공했다는 사실만으로 실제 알림 수신을 판정하지 않는다.

정렬·중복 제거·제외·보존은 합성 입력으로 먼저 테스트한다. 자동 UI로 외부 앱을 클릭하지 않았다. 2026-10-13 사용자가 재시작 후 Finder 메뉴가 수집됐다고 확인했다. Help/키보드 메뉴/취소/다른 앱은 추가 실기 검증이 필요하다.

## 조회와 보수적 동작

- AX 조회는 별도 직렬 큐에서 메시지당 25ms 제한을 설정하고 일반 입력 조회 0.18초, 알림 조회 0.2초, Help 경로 열거 0.35초의 경계로 중단한다. 개별 IPC가 지연될 수 있어 엄밀한 전체 응답 시간 보장은 아니다.
- Help는 전체 열거가 범위 내에서 완료되고 대상 제목의 경로가 하나일 때만 연결한다. 깊이 12/800노드/노드당 100자식 한계를 넘거나 조회가 실패하면 중간 결과의 유일성을 추정하지 않고 생략한다. 큰 메뉴 앱에서는 Help 수집이 누락될 수 있다.
- 일반 클릭은 닫히기 전 항목 정보와 release 위치를 연결한다. 늦거나 부족한 정보는 버리며 앱별로 메뉴 드래그 선택/키보드 탐색이 모두 포착된다고 보장하지 않는다. 짧은 입력 유효 기간과 한 입력 한 기록 정책으로 중복/과거 이벤트를 차단한다.
- 런처에서 같은 명령을 실행하는 동안 짧게 관찰 중복을 억제한다. 이벤트 감지 결과는 ‘메뉴 선택’이며 문서 저장/내보내기 등의 최종 성공 확인이 아니다.
- 외부 전송/원격 분석은 추가하지 않는다. 경로·횟수·제외 설정은 앱의 로컬 UserDefaults에만 저장한다.

## R83–R84 · 날짜 통계와 관찰 수명

- 최근 5개는 앱별 고정하지 않은 사용 메뉴를 마지막 사용 시각 내림차순으로 계산한다. 6번째 이후라도 최근 기간 이내면 남긴다. 자주 사용은 별도 기간 안의 3회 이상이며 같은 통합 영역에 표시한다. 기간은 하루=24시간 경과 기준, 경계 시각은 포함한다.
- 메뉴별 마지막 사용 시각과 최근 사용 시각 최대 3개로 저장량을 제한한다. 고정된 >=3 임계값에는 이전 모든 이벤트가 필요하지 않다. 과거 누적 카운터는 날짜를 모르므로 마지막 사용 1회만 이전한다. 임계값을 4회 이상으로 늘리는 미래 기능은 저장 형식도 다시 검토해야 한다.
- 오래된 항목을 자동 삭제하지 않아 기간 확대 시 다시 계산할 수 있다. 메타데이터 수가 매우 많은 장기 사용자의 저장 비용은 실제 측정 후 점검한다. 전체 이벤트 로그/메뉴 전체의 상시 프리로드는 추가하지 않는다.
- 시작 때 이미 실행 중인 전경 앱에 연결하고, 먼저 켜 둔 다른 앱도 활성화 시 연결한다. [실행 알림](https://developer.apple.com/documentation/appkit/nsworkspace/didlaunchapplicationnotification)은 일반 앱 연결 보완에 사용한다. Apple 문서상 LSUIElement/백그라운드 앱은 해당 알림 대상이 아니므로 상태 막대 전용 앱 지원으로 확대 해석하지 않는다.
- 초기 AXMenuBar가 없으면 제한 재시도한다(0.25/0.75/2/5/15초 지연). 다음 활성화/명시적 새로고침에서 다시 시작할 수 있다. 성공하면 재시도를 멈춘다. PID+시작 시각 및 세대 값으로 재시작/종료/오래된 예약을 구분한다. 모든 runningApplications의 메뉴를 동시에 관찰할 필요는 없다.
- 워커 큐·메시지당 25ms 제한은 유지한다. 응답 지연이 실제로 메뉴 선택 누락을 일으키는지는 별도 실기/측정 사항이며 정책 단위 테스트로 성공률을 보장하지 않는다.

## R89 · 두 경로의 사용 횟수 표시

- 런처에서 성공한 AXPress와 메뉴 막대에서 관찰한 선택은 각각 useCount/observedCount로 저장하고, 두 경로 모두 lastUsed와 recentUses에 반영한다. 설정에는 고정 여부에 관계없이 누적 합계와 각 경로의 횟수를 표시한다. 타일 툴팁/접근성 설명도 같은 값을 쓴다.
- 누적 합계는 두 카운터의 계산값이며 기간 내 정확한 실행 횟수를 뜻하지 않는다. 최근 3개 날짜로 판정하는 자주 사용 조건과 구분한다. 초기화/새 카운터로의 이전은 없고 기존 기록을 그대로 표시한다.
- 자동 수집 중단은 외부 선택 관찰만 중단한다. 타일런처에서 직접 실행한 메뉴는 계속 최근·자주 사용에 포함한다. 실행 실패·확정 전 취소를 기록하지 않고, 런처 실행으로 발생한 관찰 알림의 중복 억제를 유지한다.
