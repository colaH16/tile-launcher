# R209 · Help 검색 결과 클릭 수집 수정

2026-10-16. 개발 소스1.9.2(41)이며 공개·설치·실행본은1.9.1(40)이다.

## 사용자 확인과 원인

사용자는 iTerm의 Shell → New Window 직접 클릭과 Help 검색 결과의 Enter 실행은 수집되지만 검색 결과 마우스 클릭은 수집되지 않는다고 확인했다. 사용자가 결과창을 열어 둔 상태에서 AX 메타데이터만 읽었다. Help 결과는 AXTable → AXRow → AXCell → AXStaticText/AXImage로 노출되며 행과 글자에 AXPress가 없다. 기존 MenuAXReader.hit는 AXMenuItem과 AXPress를 필수로 요구하므로 이 구조를 거절한다. 입력 검색어와 터미널 본문은 읽지 않았고 메뉴를 실행하지 않았다.

## 수정

- 같은 프로세스의 Help 메뉴 아래인 표/행만 확인한다. 표시된 결과의 정적 글자와 행 크기를 읽고, 실제 메뉴 목록에서 하나로 연결될 때만 수집 후보로 삼는다. 일반 표나 입력 필드 값은 읽지 않는다.
- 글자·아이콘·행 여백 클릭을 같은 행 좌표로 판정한다. 기존 물리 마우스 해제/Enter 게이트를 유지해 하이라이트만으로 저장하지 않고, 행 밖에서 놓거나 취소한 경우·중복 알림은 기록하지 않는다.
- `bonjour > Open All in New Window`처럼 상위 메뉴가 표시된 결과는 실제 경로의 끝 부분과 대조한다. 원래 제목 자체에 ` > `가 포함된 경우도 후보로 남기며, 두 해석이 서로 다른 경로와 맞으면 추측하지 않는다.
- Apple 메뉴 제외, 사용자 제외, 직접 단축키 미수집, 런처 실행 중복 억제와 기존 Enter/일반 메뉴 경로를 보존한다. 폴링이나 전체 앱 감시는 추가하지 않는다.

## 검증과 제한

- XCTest197개/Python 배포 검사23개 통과. 두 iTerm 명령·행의 글자/아이콘/빈 공간·음수 모니터 좌표·마우스 해제/중복·다른 표/Apple/분리된 경로·읽기 실패·모호한 글자·잘못된 크기·breadcrumb 모호성을 검사했다. 새 검사에서 음수 크기의 CGRect가 표준화되는 점을 발견해 원시 size로 확인하도록 고쳤다.
- 실제 MenuAXReader 코드를 별도 읽기 전용 도구로 컴파일해 iTerm 메뉴431개를 약106ms에 읽었고 New Window 결과 행을 약4ms에 Shell → New Window로 연결했다. 사용자 메뉴가 닫힌 뒤 후속 조회에서는 결과 행도 사라졌다. 이를 전체 마우스 이벤트/저장 성공 검사로 대신하지 않는다.
- 격리된 /tmp/tile-r209-validation에서 앱 전체 테스트와 release 빌드를 통과했다. /tmp/tile-r209-products/Tile Launcher.app은1.9.2(41) 개발용 ad-hoc 서명이며 생산 앱을 실행하거나 교체하지 않았다.
- 로그: /tmp/tile-r209-tests.log, /tmp/tile-r209-build.log. 사용자 열림 상태의 AX 진단은 /tmp/tile-help-open.jsonl에만 보관한다. 원본 진단 로그를 저장소에 복사하지 않는다.
- 현재 설치된1.9.1의 실제 이벤트 감시기를 수정본으로 바꿔 사용자가 클릭·저장까지 확인하는 단계는 아직이다.
