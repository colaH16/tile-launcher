# R388 회사 집중 모드 프로필 로그 분석

기준일: 2026-11-08 (Asia/Seoul). 두 독립 분석의 일치 결과다.
회사 설정·앱·코드·빌드·배포를 변경하지 않았으며 clean cdf17e95는 동결한다.

## 결론

이번 로그는 필터 프로필이 없는 구간에 유효한 수동 선택으로 돌아가는 동작을 보여 준다.
macOS 집중 모드 Work → 런처 오마는 정상 매핑이라는 사용자 정정을 적용했다.
그 수동 선택이 오마라는 판단은 사용자 보고를 결합한 추론이며 로그에 이름은 없다.
새로 표시한 오버레이가 잘못된 activeProfile을 골랐다는 증거는 이번 기록에 없다.
다음은 저장된 수동 fallback을 원하는 구성으로 지정한 뒤 자동 선택을 다시 켜는 설정 확인 단계다.
추가 로그·수정·검증용 빌드는 지금 필수가 아니다.

- R387 전체 재현 안내와 실제 첨부에서 수행된 동작을 구분한다.

## 직접 관측한 상태

32개 snapshot 모두 아래 값이 유지됐다.

- followFocus=true, profileCount=2.
- manualMember=true: 저장된 수동 선택은 현재 프로필 목록에 있다.
- activeMatchesReason=true: 실제 activeProfile은 코드의 선택 우선순위와 맞는다.

관찰 전용 조회는7회 완료됐고 모두 returnedMatchesCached=true였다.
결과는 noProfile5회, 유효한 member profile2회이며 읽은 값과 캐시가 일치했다.
기존 entity 조회3회는 각각 requestedCount=1/resolvedCount=1이었다.

26.930초의 Focus 알림은 프로필 값 존재·member=true였고 panelVisible=false였다.
35.658초의 Focus 알림은 프로필 값이 nil이었고 panelVisible=false였다.
이 두 경우의 필터 상태 변화는 런처에 정상 수신된 것으로 기록됐다.
nil을 macOS 집중 모드 전체 OFF로 단정하지 않는다.
다른 집중 모드에 Tile Launcher 필터가 설정되지 않은 경우도 가능하다.
예배 모드에 별도 Tile Launcher 필터가 연결돼 있는지는 이 로그에서 관측하지 않았다.

새 present6회는 모두 presentationMatchesActive=true였다.
전체 불일치 snapshot6개는 temporaryCycle3회와 각각 직후 hide에만 있었다.
이는 휠/키 임시 프로필 전환의 의도된 동작과 일치한다.
일시적으로 보인 프로필이 다음 호출의 저장된 수동 선택으로 바뀌었다고 해석하지 않는다.

## 입증하지 못한 것

제품의 current 조회(queryStarted/queryCompleted) 이벤트는0건이다.
고정해 열린 상태에서 Focus 알림이 들어온 기록도0건이다.
따라서 앞선 소스 조사에서 본 열린 presentation 미갱신 경로나 조회 race를 입증하지 못한다.
특정 메뉴/설정 동작을 모두 안내대로 수행했다고 주장하지 않는다.
Focus 모드 전체 상태·필터별 설정·이름 매핑의 전체 목록도 확인하지 않았다.

## 최소 설정 확인 안내

1. 런처 오버레이의 프로필 드롭다운에서 Work 외에 쓸 원하는 프로필을 직접 클릭한다.
   이 동작은 자동 추종을 일시적으로 끄고 manualProfileID를 저장한다.
2. 같은 메뉴의 **집중 모드에 따라 자동 선택**을 다시 선택한다.
   자동 추종을 켜고 현재 필터를 조회하되 저장된 manualProfileID는 유지한다.
3. 필터 프로필이 없는 구간에서는 방금 저장한 수동 구성이 fallback이 되는지 확인한다.

휠이나 ⌥A/S/D/F는 이번 표시만 바꾸는 임시 전환이므로 fallback 저장에 쓰지 않는다.
특정 집중 모드에서 별도 프로필을 원하면 그 모드의 Tile Launcher 필터 연결은 별개다.
이 안내는 회사 설정을 에이전트가 조작했다는 뜻이 아니며 사용자 확인 전이다.

## 현재 상태

분석은 완료됐고 사용자에게 위 설정 방법을 안내하는 단계다.
회사 실제 원인을 이름까지 독립 확정한 수정 완료 보고가 아니다.
추가 로그는 지금 필수가 아니며 코드 수정·새 빌드·배포를 시작하지 않는다.
원본 증거와 기존83/84자산·설정·실행 상태를 유지한다.


## R389 반례로 가설 재검토

사용자는 Work 외 상태에서 기본 프로필을 직접 선택하면 기본이 기본값이지만, 자동 선택을 다시 누르면 기본값까지 오마가 되어 Work처럼 동작한다고 보고했다. UI 관측과 manualProfileID의 실제 저장 변경은 구분하며 후자는 아직 미관측이다. 위 R388 로그의 fallback 근거와 오마라는 사용자 보고 결합 추론만으로 이 반례를 충분히 설명하지 못해 분석을 재개한다. 기존 결론은 당시 로그 범위로 보존하고 원인 확정으로 확대하지 않는다. 현재 읽기 전용 코드 재조사 중이며 회사 설정·앱·소스·새 빌드·원격은 변경하지 않는다.
