# 2.1.8 시험본 · Claude 구현과 상호 검증

**현재 상태: 2.1.8(74) 공증·정식 릴리스와 Homebrew cask 갱신 완료.** 아래 시험/보류 표시는 당시 기록이며 최종 결과는 마지막 절을 따른다.

아래 73 검증 뒤 사용자가 최근 창 누락을 보고해 74로 보완했다. 74의 내용과 검증은 마지막 절에 기록한다.

2026-10-27. R340 요청으로 Claude Opus 5.5/high가 실제 제품 코드와 회귀 검사를 작성했다. Codex가 차이·범위·검사를 대조하고 개선점을 전달했으며, Claude가 수정한 뒤 최종 소스와 검사 증거를 다시 검증했다. 현재는 이 Mac의 **미공증 Developer ID CloudKit 서명 시험본**이고 최신 정식 공개/기존 Homebrew cask는 2.1.7(72)다. 사용자 오케이 전 GitHub 소스 푸시·릴리스·cask 갱신·공증은 진행하지 않는다. iCloud 빌드 전달도 하지 않았다.

## 구현과 코드 제안

1. `OverlayPresentation.dismisses`가 호출 방식과 실제 Option 상태를 함께 받는다. 창 선택과 Space 변경의 AppDelegate 호출은 `dismissesFollowingOptionHold` 한곳을 쓴다. Option 호출은 유지 후 해제로 닫고, 수동 호출의 창 선택/Space 변경은 이전 닫기로 복귀한다. 고정·Esc·앱 실행 보존 정책은 유지한다.
2. `ApplicationLaunchIdentity.matches`의 지연 공급자가 앱 ID를 먼저 검사한다. 다른 ID면 번들/실행 파일 경로를 조회하지 않는다. 기대 ID가 없을 때는 기존 경로·실행 파일 판별을 보존한다. exact가 있으면 fallback을 생략하고, 진행 요청이 없으면 창 준비 확인 조회를 생략한다.
3. fallback의 ID·주 실행 파일 이름 규칙도 생산 코드가 실제 사용하는 helper로 옮겼다. Codex는 최초 제안이 ID 검사 전 executableURL을 평가하는 점을 찾아 반송했고, Claude가 이름 공급자까지 지연시켜 기존 short-circuit를 보존하고 0회 호출 검사를 추가했다.

제품 작성 파일은 `Sources/DeckCore/ApplicationLaunchIdentity.swift`, `OverlayPresentation.swift`, `Sources/TileLauncher/ApplicationLaunchMonitor.swift`, `main.swift`다. Debug 전용 native 검사와 호출은 `PreviewFixtures.swift`, 단위 검사는 `Tests/DeckCoreTests/ApplicationLaunchIdentityTests.swift`, `OverlayPresentationTests.swift`에 있다. WindowTracker와 제품 드래그 코드는 변경하지 않았다.

## 검증 결과

- 최종 소스의 XCTest **306개**, Python 배포 검사 **30개** 통과.
- 수동/Option 호출 × Option up/down × 고정 여부의 8조합, 실제 HoldMonitor→생산 onHide 연결, 다른 생존 PID의 gate 해제 거부, 실행 완료/창 준비 의미, 심볼릭 링크·복사본 키를 검사했다.
- 임시 체크아웃에서 두 수정을 각각 되돌리자 새 판정 매트릭스/경로 호출 횟수 검사가 실제로 실패했다. 정확한 원본 바이트로 복원한 뒤 최종 검사 전부 재통과했다. 원래 저장소에는 반례용 변경을 하지 않았다.
- 전체 native export가 **131개 PNG와 회귀 검사**를 완료했다. 실제 사용자 Space 전환·물리 입력 검증과 구별한다.
- 실제 생산 lazy helper를 사용한 준비 실행 제외/교차 각 40회 측정: 탐색 평균 **5.315ms → 0.270ms**, 같은 STP 본체 선택. 159개 실행 프로세스의 warm-cache 탐색 부분이며 전체 앱 실행·프레임 성능 수치가 아니다.
- Release에서 임시 logger와 native/preview 검사 문자열 제외를 확인했고 Developer ID·CloudKit 프로파일/원본·ZIP 재추출 검증을 통과했다.

## 전체 native 검사에서 확인한 기존 가정 정정

처음 전체 검사는 배경 1물리픽셀(2×에서 0.5pt) 이동의 정확한 창 원점 비교에서 실패했다. 별도 최소 AppKit 프로그램도 창을 표시하지 않고 x=5.5pt 요청을 x=5.0pt로 정렬하는 것을 재현했다. 이 검사와 제품 드래그 구현은 이번 두 수정에서 변경되지 않은 부분이다.

Claude가 Debug fixture만 1논리포인트 이동의 정확한 비교로 정정했다. Retina에서 2물리픽셀이므로 타일의 7픽셀 문턱보다 작고, 클릭 비실행·실제 창 이동을 계속 검사한다. 계산 계층의 기존 단위 검사는 여전히 0.5pt 이동이 즉시 반영되는지 확인한다. 제품 드래그 문턱이나 동작을 바꾼 해결책이 아니다. 정정 뒤 전체 native export가 통과했다.

검토 중 ‘별도로 포장된 두 실행 파일의 바이트가 같다’는 전달 문구와 비교 결과(false)가 불일치해 Claude도 지적했다. 기록을 바로잡았고 최종 검증에서는 바이트 동일성을 주장하지 않는다. 서명 전 BuildID 기록은 같지만 패키지별 소스 메타데이터·서명이 달라 전체 서명 파일 해시가 다를 수 있다. 승인 근거는 정확한 소스/Release 제외 검사·서명·최종 산출물/설치 해시 검증이다.

## 설치와 남은 실기 확인

최종 앱 소스는 `40aa95f99c7838a5338ff5fc9131c23092134185`, 전체 tree는 `8f3de18db410d926a0e2df0bb4724a9296457255`다. 원래 Git tree와 같은 임시 체크아웃을 검증해 빌드했다. 이전 공증72는 정상 종료·백업하고 같은 사용자 응용 프로그램 경로에73을 설치·실행했다. 실제 PID의 경로·버전·BuildID와 최종 번들 해시가 일치한다. Claude의 마지막 읽기 전용 검증도 로컬 실기 진행을 막는 코드 이슈가 없다고 확인했다.

사용자 확인:

1. Option으로 열고 STP를 실행한 뒤 Option을 유지한 채 최근 창 첫 선택: 로딩이 풀리고 뒤쪽 앱/데스크탑이 전환되며 오버레이는 유지. Option을 놓으면 닫힘.
2. 메뉴 막대 → 열기 후 Option을 누른 채 최근 창 선택: 고정하지 않았다면 오버레이가 닫힘.
3. 핀을 켠 경우 창 선택·Option 해제에도 유지되고 Esc로 닫힘.

설정 창이 다른 Space에 있을 때 활성화가 끼어들 가능성은 여전히 미재현 가설이며 이번에 제품 변경하지 않았다. 계정·Remote Control 세션·원문/수정 제안·검사 로그/설치 영수증은 ignored evidence에만 둔다.


## R341 · 2.1.8(74) 초기 최근 창 수집 보완

사용자는 73에서 등록 STP의 실행 로딩은 풀리지만, Option을 유지하면 최근 창이 목록 맨 아래까지도 없고 오버레이를 다시 열면 나타난다고 확인했다. 첨부 화면도 STP가 활성 메뉴 대상인 상태에서 최근 창 목록에는 없는 모습을 보였다. 이 Mac의 최근 창 개수는 자동 설정이었다. 독립적인 새 창 목록 조회는 STP의 창 ID를 읽었으므로 당시 목록이 영구적으로 읽기 불가능한 상태였다고 볼 수 없다. 다만 최초 실패 시점의 내부 로그가 없어 빈 AX 응답과 알림 등록 실패 중 어느 것이 실제 발단인지는 확정하지 않았다.

Claude Opus 5.5/high가 다음 보완을 작성하고, Codex가 호출 순서·범위·검사와 산출물을 대조했다. 새로 실행되거나 활성화된 일반 앱에 실제 창이 없을 때 해당 프로세스만 0.3 / 0.8 / 1.6 / 3.2초의 완료 후 간격으로 최대 네 번 다시 읽는다. 창이 발견되면 즉시 중단하고, 같은 생존 프로세스의 반복 알림은 횟수를 늘리지 않는다. 프로세스 종료·교체·권한 상실 시 예약된 작업은 읽기를 수행하지 않는다. 앱 수준 AX 알림 등록 중 일시 실패한 이름만 다음 기존 이벤트/재조회에서 다시 등록하며 성공·미지원 이름은 반복 등록하지 않는다.

대상 앱의 AX 창만 다시 읽고 비용이 큰 창별 ordering 조회도 그 앱으로 한정한다. WindowServer API가 제공하는 전역 메타데이터 스냅샷은 여전히 한 번 읽는다. 기존 앱 활성화·Space 이동·Option 유지·드래그·최근 순위 알고리즘은 변경하지 않았다. 활성 앱의 새 포커스 창을 기존 규칙으로 최근 순위에 반영하는 동작은 유지한다. STP와 같은 번들 경로를 가진 accessory 보조 프로세스는 새 실행 재조회 대상에서 제외한다.

검증:

- XCTest 316개와 Python 배포 검사 30개 통과. 새 검사는 빈 응답 후 창 발견, 네 번 상한, 중복 예약 억제, 대상 PID 제한, 종료·PID 교체·권한 상실 취소와 등록 결과 분류를 다룬다.
- 실제 WindowTracker의 settle → scheduler → read → publish → onChange 연결에 합성 창을 늦게 제공해, synchronize나 오버레이 재열기 없이 목록 갱신이 발행되는 것을 확인했다. 실제 AX/WindowServer 읽기 직전에 합성값을 넣은 Debug 검사이며 macOS의 실제 준비 시점을 검증한 것은 아니다.
- 빠른 native 검사와 전체 131개 PNG/입력 회귀 검사 통과. Release에서 preview/임시 진단 및 새 fixture 문자열 제외 확인.
- Claude 최종 읽기 전용 검토에서 새로 입증한 차단 결함 없음. Codex가 검토 당시 작업 트리와 커밋이 동일함을 확인했다. 실제 workspace 알림 수신, 좁힌 ordering 조회의 실환경 실행 및 STP 준비 시점은 사용자 실기로 남는다.

앱 소스는 `947ed1ffa68a9800e84637a92b20e15297829a96`, 전체 tree는 `9861f979fc3521f77a9315d6f5239c8ec7633942`다. 원래 저장소의 전체 Git tree와 동일한 임시 체크아웃에서 Release 빌드하고 Developer ID·CloudKit 서명과 원본/ZIP 재추출 검증을 마쳤다. 기존 73을 정상 종료·백업하고 같은 사용자 Applications 경로에 74를 설치·실행했다. 실제 실행 PID의 경로·버전·BuildID와 최종 번들 해시 일치를 확인했다. 현재 설치는 미공증 74이며, 위 73 설치 결과는 이전 기록이다. 공증·GitHub 소스 푸시/릴리스·Homebrew 갱신은 사용자 확인 전 보류하며 iCloud 빌드 전달은 하지 않는다.

실기 확인: STP 정상 종료 → Option을 유지한 채 런처의 등록 항목으로 실행 → 오버레이를 닫지 않고 최근 창이 나타나는지 확인 → 첫 선택으로 뒤쪽 창/데스크탑 전환 및 오버레이 유지 확인 → Option 해제로 닫힘 확인.


## R342 · 사용자 확인과 공증·정식 배포 완료

사용자는 74에서 오버레이를 닫지 않아도 최근 창이 바로 나타나고 전환도 잘 된다고 확인했다. 이에 따라 동일 앱 소스/BuildID를 유지해 재빌드·재서명 없이 Apple 공증을 진행했다. Apple Accepted 후 티켓·Gatekeeper·원본/ZIP 재추출 검증을 통과했고 2026-10-27 17:38:32 KST에 [v2.1.8](https://github.com/colaH16/tile-launcher/releases/tag/v2.1.8)을 최신 정식으로 공개했다. main에는 실제 소스와 검증 문서를 정상 푸시했고 v2.1.8 태그는 앱 소스 `947ed1ffa68a9800e84637a92b20e15297829a96`를 가리킨다.

공개 자산 세 개를 인증 없이 재다운로드해 SHA256, 정확한 태그·소스, 최신 정식 표시, 앱 서명·공증·최종 번들 해시를 확인했다. [Homebrew cask](https://github.com/colaH16/homebrew-tap/blob/main/Casks/tile-launcher.rb)는 2.1.8과 같은 ZIP SHA256으로 갱신했고 원격 파일을 다시 읽어 일치를 확인했다.

이 Mac 설치본은 백업 후 티켓만 첨부했다. 기존 모든 파일·실행 코드/BuildID·PID가 유지되고 배포본과 최종 번들 해시가 일치한다. 기존 릴리스/초안·태그와 백업은 보존했고 iCloud 배포파일 전달은 하지 않았다.

최종 ZIP SHA256: `eee0c8ac41bf0e84342c0343bea65b3b1b273335d431c247226350f3c3f16f25`. 공증 제출/설치/공개 다운로드/cask 갱신의 운영 영수증과 원본 로그는 ignored evidence에 보존한다.
