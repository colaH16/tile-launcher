# 2.1.8(73) · Claude 구현과 상호 검증

2026-10-27. R340 요청으로 Claude Opus 5.5/high가 실제 제품 코드와 회귀 검사를 작성했다. Codex가 차이·범위·검사를 대조하고 개선점을 전달했으며, Claude가 수정한 뒤 최종 소스와 검사 증거를 다시 검증했다. 현재는 이 Mac의 **미공증 Developer ID CloudKit 서명 시험본**이고 최신 정식 공개/기존 Homebrew cask는 2.1.7(72)다. 사용자 오케이 전 GitHub 소스 푸시·릴리스·cask 갱신·공증은 진행하지 않는다. iCloud 빌드 전달도 하지 않았다.

## 구현과 코드 제안

1. `OverlayPresentation.dismisses`가 호출 방식과 실제 Option 상태를 함께 받는다. 창 선택과 Space 변경의 AppDelegate 호출은 `dismissesFollowingOptionHold` 한곳을 쓴다. Option 호출은 유지 후 해제로 닫고, 수동 호출의 창 선택/Space 변경은 이전 닫기로 복귀한다. 고정·Esc·앱 실행 보존 정책은 유지한다.
2. `ApplicationLaunchIdentity.matches`의 지연 공급자가 앱 ID를 먼저 검사한다. 다른 ID면 번들/실행 파일 경로를 조회하지 않는다. 기대 ID가 없을 때는 기존 경로·실행 파일 판별을 보존한다. exact가 있으면 fallback을 생략하고, 진행 요청이 없으면 창 준비 확인 조회를 생략한다.
3. fallback의 ID·주 실행 파일 이름 규칙도 생산 코드가 실제 사용하는 helper로 옮겼다. Codex는 최초 제안이 ID 검사 전 executableURL을 평가하는 점을 찾아 반송했고, Claude가 이름 공급자까지 지연시켜 기존 short-circuit를 보존하고 0회 호출 검사를 추가했다.

제품 작성 파일은 `Sources/DeckCore/ApplicationLaunchIdentity.swift`, `OverlayPresentation.swift`, `Sources/TileLauncher/ApplicationLaunchMonitor.swift`, `main.swift`다. Debug 전용 native 검사와 호출은 `PreviewFixtures.swift`, 단위 검사는 `Tests/DeckCoreTests/ApplicationLaunchIdentityTests.swift`, `OverlayPresentationTests.swift`에 있다. WindowTracker와 제품 드래그 코드는 변경하지 않았다.

## 검증 결과

- 최종 소스의 XCTest **306개**, Python 배포 검사 **30개** 통과.
- 수동/Option 호출 × Option up/down × 고정 여부의 8조합, 실제 HoldMonitor→생산 onHide 연결, 다른 생존 PID의 gate 해제 거부, 실행 완료/창 준비 의미, 심볼릭 링크·복사본 키를 검사했다.
- 임시 체크아웃에서 두 수정을 각각 되돌리자 새 판정 매트릭스/경로 호출 횟수 검사가 실제로 실패했다. 정확한 원본 바이트로 복원한 뒤 최종 검사 전부 재통과했다. 원래 저장소에는 반례용 변경을 하지 않았다.
- 전체 native export가 **131개 PNG와 회귀 검사**를 완료했다. 실제 사용자 Space 전환·물리 입력 검증과 구별한다.
- 실제 생산 lazy helper를 사용한 준비 실행 제외/교차 각 40회 측정: 탐색 평균 **5.315ms → 0.270ms**, 같은 STP 본체 선택. 159개 실행 프로세스의 warm-cache 탐색 부분이며 전체 앱 실행·프레임 성능 수치가 아니다.
- Release에서 임시 logger와 native/preview 검사 문자열 제외를 확인했고 Developer ID·CloudKit 프로파일/원본·ZIP 재추출 검증을 통과했다.

## 전체 native 검사에서 확인한 기존 가정 정정

처음 전체 검사는 배경 1물리픽셀(2×에서 0.5pt) 이동의 정확한 창 원점 비교에서 실패했다. 별도 최소 AppKit 프로그램도 창을 표시하지 않고 x=5.5pt 요청을 x=5.0pt로 정렬하는 것을 재현했다. 이 검사와 제품 드래그 구현은 이번 두 수정에서 변경되지 않은 부분이다.

Claude가 Debug fixture만 1논리포인트 이동의 정확한 비교로 정정했다. Retina에서 2물리픽셀이므로 타일의 7픽셀 문턱보다 작고, 클릭 비실행·실제 창 이동을 계속 검사한다. 계산 계층의 기존 단위 검사는 여전히 0.5pt 이동이 즉시 반영되는지 확인한다. 제품 드래그 문턱이나 동작을 바꾼 해결책이 아니다. 정정 뒤 전체 native export가 통과했다.

검토 중 ‘별도로 포장된 두 실행 파일의 바이트가 같다’는 전달 문구와 비교 결과(false)가 불일치해 Claude도 지적했다. 기록을 바로잡았고 최종 검증에서는 바이트 동일성을 주장하지 않는다. 서명 전 BuildID 기록은 같지만 패키지별 소스 메타데이터·서명이 달라 전체 서명 파일 해시가 다를 수 있다. 승인 근거는 정확한 소스/Release 제외 검사·서명·최종 산출물/설치 해시 검증이다.

## 설치와 남은 실기 확인

최종 앱 소스는 `40aa95f99c7838a5338ff5fc9131c23092134185`, 전체 tree는 `8f3de18db410d926a0e2df0bb4724a9296457255`다. 원래 Git tree와 같은 임시 체크아웃을 검증해 빌드했다. 이전 공증72는 정상 종료·백업하고 같은 사용자 응용 프로그램 경로에73을 설치·실행했다. 실제 PID의 경로·버전·BuildID와 최종 번들 해시가 일치한다. Claude의 마지막 읽기 전용 검증도 로컬 실기 진행을 막는 코드 이슈가 없다고 확인했다.

사용자 확인:

1. Option으로 열고 STP를 실행한 뒤 Option을 유지한 채 최근 창 첫 선택: 로딩이 풀리고 뒤쪽 앱/데스크탑이 전환되며 오버레이는 유지. Option을 놓으면 닫힘.
2. 메뉴 막대 → 열기 후 Option을 누른 채 최근 창 선택: 고정하지 않았다면 오버레이가 닫힘.
3. 핀을 켠 경우 창 선택·Option 해제에도 유지되고 Esc로 닫힘.

설정 창이 다른 Space에 있을 때 활성화가 끼어들 가능성은 여전히 미재현 가설이며 이번에 제품 변경하지 않았다. 계정·Remote Control 세션·원문/수정 제안·검사 로그/설치 영수증은 ignored evidence에만 둔다.
