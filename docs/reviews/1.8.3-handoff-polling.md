# R199 · Handoff 조회 완료 후 0.4초 대기

2026-10-15. 기준 소스 `817d76e`의 1.8.2에서 시작한 버그 수정 **1.8.3(38)**이다. 사용자가 리뷰2의 조회 누적 방지를 승인하고, 고정 주기에 건너뛰는 방식보다 완료 후0.4초 대기를 선택했다.

## 동작

- 오버레이 표시를 시작할 때 조회한다. Option 준비 때 이미 진행 중인 조회가 있으면 그대로 공유한다. 준비 조회는 자체적으로 반복하지 않는다.
- **조회 완료 → 0.4초 대기 → 다음 조회** 순이다. 조회와 결과 전달을 마친 뒤 단발 타이머를 예약한다. 조회가0.5초 걸리면 시작 간격은 약0.9초다. 타이머는 실시간 보장이 아니므로 Mac의 작업 상황에 따라 더 늦어질 수 있다.
- 진행 중 또는 반복 대기 중 들어온 추가 조회 요청은 버린다. 누락된 주기 수를 세거나 나중에 몰아서 실행하지 않는다. 시작 요청도 중복 반복을 만들지 않는다.
- 닫힘/Option 준비 취소/앱 종료 시 다음 예약을 취소한다. 진행 중인 AX 호출 자체를 강제로 끊지는 않으며, 그 조회가 늦게 반환한 결과는 버린다.
- 닫았다가 바로 다시 열어도 이전 조회가 완료되기 전에는 새 조회를 시작하지 않는다. 이전 결과는 새 화면에 반영하지 않고, 완료 후0.4초 뒤 새로 읽는다.
- 아이콘 목록의 뒤에서부터 Handoff를 찾고 발견 즉시 끝내는 기존 방식을 유지한다. 없을 때는 전체 후보를 확인한다.

`CompletionPoller`가 위 규칙을 관리하고 `DockHandoff`가 기존 전용 작업 큐에서 AX 읽기를 수행한다. AppDelegate의0.5초 반복 Timer는 제거했다. 메인 스레드는 읽기를 기다리지 않는다.

## 응답 제한과 유지한 정책

기존0.3초 제한은 Dock 루트 객체에만 설정되어 있었다. Apple SDK `AXUIElement.h`의 `AXUIElementSetMessagingTimeout` 설명대로 제한은 설정한 객체에만 적용되므로 목록과 각 아이콘 읽기에도 같은 제한을 적용했다. 첫 `.cannotComplete`에서 이번 순회를 중단한다. 이는 개별 읽기의 응답 제한이며 전체 순회가 반드시0.3초 안에 끝난다는 보장은 아니다.

읽기 뒤에는 해당 객체의 제한을0으로 되돌려 기본값을 쓰게 한다. 따라서 Handoff를 누르는 `AXPress`에 짧은 읽기용 제한이 남지 않는다. 클릭 때 현재 Dock 항목을 다시 찾고 한 번만 누르는 기존 동작은 유지한다. 진행 중인 읽기 하나를 기다릴 수는 있지만 반복 조회가 여러 개 쌓인 뒤를 기다리는 문제는 없어진다.

- 리뷰3: 같은 앱의 기기가 바뀌면 현재 Dock 제안을 누르는 정책 유지.
- 리뷰4: 읽기 실패에 별도 유지 시간/추가 확인을 넣지 않음. 이번에도 읽기 실패는 기존처럼 항목 없음으로 반영할 수 있다.
- 리뷰8: 전환 알림 전달은 여전히 미확인. 알림 기반으로 대체하지 않음.
- 메뉴 내용/실행 대상/타일 배치/색/사용자 설정 저장 형식은 변경하지 않음.

## 검증

- 최종 소스로 격리 빌드 성공. XCTest **187개**, Python 배포 검사 **23개** 통과. 새 스케줄러 검사8개를 포함한다.
- 가상 시계에서0.500000001초에 완료한 조회의 다음 시작은0.900000001초였다. 고정0.5초 틱을 기다리지 않는다.
- 조회를 지연시킨 채100회의 추가 요청/시작 요청을 보내도 진행 중 조회는 하나다. 완료 후에도 밀린 요청을 실행하지 않는다.
- 조회 중 닫기, 빠르게 닫고 다시 열기, 취소 후 늦게 도착한 타이머 콜백, 준비 조회 공유, 결과 없음, 결과 콜백에서 중단을 검사했다.
- 실제 RunLoop 타이머와 백그라운드 완료 콜백으로도 완료 이후 대기 시간을 확인했다. 이 검사는 Dock/Handoff를 누르지 않는다.
- 임시 빌드: `/tmp/tile-r199-build`; 로그: `/tmp/tile-r199-tests.log`.
- 실제 Dock을 고의로 멈추거나 사용자 기기의 Handoff를 전환/클릭해 시험하지 않았다. 통신 실패 순회 중단/응답 제한 적용은 코드 검토 및 컴파일로 확인했으며, 실제 OS의 지연 상한을 측정했다고 주장하지 않는다.

개발 소스와 누적 릴리스 노트를 정리했다. 새 서명 ZIP·공증·설치·GitHub 바이너리 공개는 하지 않았다. 개발 Mac 설치본1.2.0, 전달한 시험 ZIP1.8.1, 정식 공개1.4.3은 그대로다.
