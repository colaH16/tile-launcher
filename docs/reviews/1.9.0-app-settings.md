# R201 · 공통 앱 설정 타일

2026-10-15. 기존1.8.3 수정에 사용자가 요청한 공통 설정 기능을 추가한 **1.9.0(39)**이다. R200의 서명·공증·GitHub 공개 승인을 이어간다.

## 사용자 결정

- 앱마다 메뉴를 수집하거나 고정 저장해야 하는 방식은 원하지 않는다. 처음 쓰는 앱에도 같은 공통 규칙을 적용한다.
- 표준⌘, 또는Settings/설정처럼 확인할 수 있는 설정 항목이 있는 앱에서만 표시한다. 찾지 못하면 숨긴다.
- 앱별 메뉴 뒤의 마지막 행에4×2 고정 강조 타일을 둔다. 기존 순차 배치 알고리즘은 변경하지 않는다. 메뉴가 길면 기존처럼 스크롤하며, 공통 타일도 마지막 항목으로 함께 스크롤한다.
- 실제SF Symbol 비교 후 가운데 세 갈래가 있는 **gear**를 선택했다. gearshape 또는 첨부JPG 확대가 아니다.

## 구현과 한계

`ApplicationSettingsMenu`는 현재 앱의 메뉴 막대에서 Apple 메뉴 다음의 앱 메뉴만 읽는다. 직접 실행 가능한 항목 중 유일한⌘, 항목을 먼저 찾고, 없으면Settings/Preferences/설정/환경설정/일본어·중국어 설정 이름과 정확히 맞는 항목을 찾는다. 일반명칭 앞뒤의 공백과 생략점은 정리하되 부분 문자열 검색은 하지 않는다. 후보가 중복되거나 비활성/하위 메뉴이면 사용하지 않는다. 문서·프로젝트·Services 하위 메뉴는 순회하지 않는다.

Apple은 [설정 지침](https://developer.apple.com/design/human-interface-guidelines/settings)과 [SwiftUI 설정 예제](https://developer.apple.com/tutorials/app-dev-training/displaying-app-settings)에서⌘,를 표준 설정 단축키로 설명한다. 모든 앱이 공유하는 공개 설정 메뉴ID를 전제로 하지 않는다. 비표준 메뉴 구조, 접근성 정보가 없는 앱, 다른 이름에 다른 단축키를 쓰는 앱은 지원하지 않을 수 있다. 앱이⌘,를 전혀 다른 동작으로 재정의한 경우까지 의미를 증명할 수는 없다.

- 조회는 오버레이 준비/열기 및 표시 중 활성 앱 전환에만 수행한다. 앱 전체나 전체 메뉴 트리를 상시 폴링하지 않는다.1초의 메모리 캐시는 준비와 표시 요청을 공유하고 디스크에 앱별 매핑을 저장하지 않는다.
- 한 번에 조회 하나만 진행한다. 대상이 바뀌면 마지막 대상 하나만 이어 읽고 오래된 결과는 표시하지 않는다. 목록 최대100개, 조회 전체 검사 기한0.8초, 개별AX 읽기 제한0.08초다. 기한은 OS 호출의 엄격한 실시간 완료 보장이 아니다.
- `OverlayMenuEntry.appSettings`는 표시 전용 항목이다. 사용자MenuCommand 목록/UUID/핀/사용 기록/리소스 아이콘 저장 형식을 변경하지 않는다. 표시 여부를 실제행 높이 계산에도 포함한다.
- 클릭 때 원래 앱/창을 복원하고 현재 설정 메뉴를 다시 찾는다. Handoff 앱이나 Tile Launcher의 설정을 대신 열지 않는다. 실행 전 자동 수집 억제를 설치해 공통 타일 사용만으로 앱별 메뉴가 새로 등록되지 않게 한다.
- 오래된AX대상을 저장해 재사용하지 않으며 실행은 한 번만 요청한다. 읽기용 timeout은AXPress 전에 해제한다. 실패 후 임의의⌘, 키 입력이나 다른 후보를 실행하지 않는다.

## 검증

- XCTest **192개**, Python 배포 검사 **23개** 통과. 표준단축키/낯선 언어/예전 이름/사용자 단축키 변경/추가수정키/문서·프로젝트 이름 제외/중복 후보를 검사했다.
- 실제 Finder, CotEditor, Notes의앱 메뉴에서각각 `Settings…`를읽기만 해확인했다. 로컬 관측 소요는각각38/32/34ms다. 다른 앱의 동작이나항상 같은성능을보장하는측정은 아니다. 앱 활성화·설정 열기·클릭은 보내지 않았다.
- 네이티브 비표시 렌더 검사에서공통타일이 마지막4×2이고미지원 시 사라지며저장메뉴를 바꾸지 않음을확인했다. 전체샘플에서네 번째행이 생기면3.3줄 viewport 계산에반영되며,아이콘 확인용이미지는앱별 메뉴를5개로 줄인합성입력이다.
- 기존 설정·행 배치·앱 실행 상태·Handoff 메뉴 대상보존 검사도 함께 통과했다. 제한된 실행환경에서는기존NSRunningApplication 상태 검사가실패해, 화면을조작하지 않는동일 렌더명령을일반 실행권한으로재검증했다.
- 임시 빌드 `/tmp/tile-r201-build`, XCTest/Python 로그 `/tmp/tile-r201-tests.log`, 네이티브 로그 `/tmp/tile-r201-previews.log`, 이미지 `/tmp/tile-r201-previews/common-app-settings.png`.

최종 서명·공증·게시 결과는 CHANGELOG와 request-log의R200–R201 완료 기록을 따른다. 개발 Mac의 설치 앱은 별도 요청 없이 교체하거나 실행하지 않는다.

사용자가첫 미리보기의설정 타일 부재/3줄 높이를지적했다. 해당비표시샘플은상태만바꾸고고정frame을다시맞추지않아4번째행이잘렸다. 실제앱은availability갱신→workRows→refittingContent로연결되어공통타일을포함한4행을3.3줄로계산하며검사도통과했다. 사용자는소스확인후추가렌더를생략하고릴리스를이어가도록했다.
