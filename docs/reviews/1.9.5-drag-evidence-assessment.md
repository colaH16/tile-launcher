# 드래그 증거 검토와 조치 판단 · 2026-10-17

R265 사용자는 Tile-Launcher-drag-evidence-20261017-1024의 로그·조사 결과를 검토해 API 폐기/동작 통일 공지 여부와 제품 조치/대기 중 무엇이 나은지 판단해 달라고 요청했다. 이번은 읽기·분석이며 제품 수정 승인이 아니다.

## 원본 교차 확인

manifest의26개 파일 크기/SHA256을 검증했다. .DS_Store는 수신 폴더에 없으며 진단 결과와 무관하다. 원본 JSONL은V1 666행/V2 627행으로 파싱되며 session.end를 확인했다. 모드 시작 이전 배치 이동은 집계에서 제외했다.

- V1 기본 제목 표시줄/배경은 실제frame 변화 및 didMove30/32건. C~F 명시적performDrag 호출/반환21/20/21/19회에서 실제 이동0.
- V2 일반창/비활성 패널 기본배경은 실제frame 변화 및 didMove25/19건. C명시적performDrag27호출/반환에서 이동0. SwiftUI H/I는 이동0.
- 명시적performDrag 합계108호출 모두 호출전movable=true/currentEvent객체동일성true다. 호출 횟수/이동 알림을 물리 시도 수로 해석하지 않는다.
- 특정 WindowServer 오류는V1 81건/V2 69건. 필터 설명 머리글에도 문자열이 있으므로 단순 substring 개수82/70을 오류 건수로 오인하지 않았다. 앱/이벤트ID가 없는 오류여서 시간대 대조이며 인과1:1 확정은 아니다.

## Apple 공식 문서·SDK 확인

현재 macOS27.2 beta4 릴리스 노트 및27 릴리스 노트에서 performDrag 폐기/창 이동 API 통일 공지나 이번 증상의 명시적 수정/알려진 문제를 찾지 못했다.27의 텍스트 선택 제스처/SwiftUI Slider 배경 드래그 수정 등 다른 항목은 창 이동 API 폐기 근거가 아니다.

performDrag(with:) 문서는 원래 mouseDown 이벤트로 앱/뷰가 WindowServer에 이동을 넘기는 API로 여전히 안내하며 폐기 표기가 없다. 로컬27.2 SDK NSWindow.h661행도 API_AVAILABLE(macos10.11)이며 deprecated가 아니다. 미래 Apple 의도나 근본 원인이 공개됐다고 결론 내리지 않는다.

공식 문서는 Markdown 원문을 내려받아 전체를 확인했다. 출처:

## 판단

제품의 클릭 판정 문제만으로 설명되지 않는 앱 시작 드래그 경로의 실패가 독립도구에서 재현됐다. 문서상 기대 동작과 달라 결함으로 보는 것이 타당하지만 OS 회귀/세션 상태/공통 입력 환경 중 어느 원인인지는 안정OS/새세션 대조나 Apple 원인 확인이 없어 미확정이다. 공식 API 폐기나 의도적 통일로 해석할 근거는 없다.

단순 대기보다 공개 기본 배경 이동 경로로 기존 배경 드래그 구현을 전환하는 시험을 권한다. 비활성 패널 G에서도 이미 실제 이동이 확인됐으므로 근거 있는 후보이며 Apple 수정 일정은 확인되지 않는다. 단, isMovableByWindowBackground=true만 켜면 제품 전체가 동작한다고 보장할 수 없다. SwiftUI/네이티브 hit-test와 제외 영역을 맞추고 타일 클릭·우클릭·휠/스크롤바·Option 유지 상태를 보존해야 한다. 타일까지 이동 영역을 넓히는 기능은 별도 선택으로 유지한다. 제품 적용 성공은 아직 검증하지 않았다.
