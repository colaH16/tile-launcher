# R234 · 대상 앱 재실행 후 설정 타일 유지

2026-10-16. 개발1.9.4(44), 배포 시험본test.1은1.9.4(43), 정식 최신/설치는1.9.3(42)다. 이번 변경은 아직 새 배포를 하지 않았다.

## 확정한 동작

사용자는 이미지 캐시가 아니라 ‘Messages를 재실행해도 앱 설정 타일을 찾았던 결과 유지’를 선택했다. 한 번 찾은 앱은 앱 ID별 지원 여부만 메모리에 기억하며 Tile Launcher 종료 시 초기화한다. 대상 앱이 종료·새 PID로 재실행돼도 hasSettings는 즉시 true이고 refresh는 메뉴를 다시 읽지 않는다.

앱 종료 시 프로세스별 조회 기록은 정리한다. 미발견 앱의 실패 횟수·5회 실패 후 중단 상태는 대상 앱 재실행 시 초기화한다. 기존 전환당1회·처음 포함총5회·개별AX300ms/전체2초는 유지한다.3회 변경과 같은 전환 내 자동 재시도는 하지 않았다.

| 상태 | 대상 앱 종료 시 | Tile Launcher 종료 시 |
|---|---|---|
| 설정을 한 번 찾았다는 기록 | 유지 | 초기화 |
| 미발견 실패 횟수·중단 상태 | 초기화 | 초기화 |
| 창 목록·AX 관찰 참조·조회 예약 | 실행 앱 목록 변경에 따라 제거/취소 | 종료 |
| 메뉴 관찰의 열린 메뉴·Help 결과 등 임시 상태 | 관찰 대상 변경 시 해제 | 종료 |
| 앱/메뉴 이미지 메모리 캐시 | 종료만으로 지우지 않음; 기존 용량/메모리 회수 정책 유지 | 메모리 해제 |
| 저장 메뉴·핀·사용 횟수·리소스 카탈로그 | 유지 | 디스크 저장값 유지 |

## 실행 경로·제한

성공 집합에는 앱 ID만 저장한다. 이전 프로세스의 AX 메뉴 요소나 클릭 대상을 보관하지 않는다. 앱 설정 실행은 기존 prepare/현재 메뉴 재탐색/AXPress 경로를 그대로 사용한다. 표시 옵션과 접근성 권한의 UI 조건도 그대로다. 취소나 빈 현재 앱 상태로 성공 기록을 지우지 않는다.

지원 메뉴가 같은 런처 실행 중 실제로 없어져도 성공 기록은 유지하므로 타일은 남을 수 있다. 이 경우 실행 전 재탐색에서 실패를 안내하며 이전 요소를 누르지 않는다. 런처를 다시 실행하면 지원 여부를 새로 확인한다.

이 수정은 **한 번이라도 찾은 앱**의 재실행 처리다. 한 번도 찾지 못한 앱의 최초 누락을 해결했다고 주장하지 않는다. 집 Mac 기존 로그만으로 최초 조회 미호출/정상 미발견/AX 오류·시간 초과/취소/표시 지연을 구분할 수 없다는 진단 결과를 유지한다. 그 원인을 확인하려면 별도 내부 진단 로그가 필요하다. 이번에 진단 로그는 추가하지 않았다.

## 검증

- Release 빌드와 XCTest215개/Python23개 통과.
- 전체 비표시 네이티브 검사 exit0. 성공 캐시의 같은 PID 새 시작·새 PID·종료·취소 후 유지와 재조회/변경 콜백 없음, PID를 공유하는 다른 앱 ID에 기록이 새지 않음, 런처 새 인스턴스에서 성공 기록 초기화를 확인했다.
- 미발견5회 중단과 추가 횟수 갱신 없음, 미발견 프로세스의 재실행 초기화,3번째 활성화에서 발견, 늦게 온 취소 결과 무효화도 유지했다.
- 아이콘 사전 읽기·전체 배경 드래그·연속 종료와 기존 설정·레이아웃 검사를 함께 통과했다. 기존 macOS27.2 beta NSTableView 비표시 reentrant 경고3건은 남는다.
- 로그: /tmp/tile-r234-build-final.log, /tmp/tile-r234-tests.log, /tmp/tile-r234-native.log. 사용자 전경 앱/설치/공개 자산은 변경하지 않았다.
