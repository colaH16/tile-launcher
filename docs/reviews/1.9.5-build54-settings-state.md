# 앱 설정 오류·미발견 구분 시험 · 1.9.5(54)

R257 사용자가 공증 없이 표시 상태 정정본을 먼저 써보고, 문제가 남을 때 진단 로그를 추가하자고 요청했다. 임시 로그를 추가하거나 실제 Messages를 조작하지 않았다.

## 수정

- 실패 횟수와 정상 미발견 여부를 별도로 보존한다. AX 오류·마감·불완전 조회는 비활성 유지, 정상 미발견은 숨김, 성공은 활성이다.
- 세 경로 중 오류가 남으면 다른 경로의 nil 결과만으로 전체 미발견으로 처리하지 않는다(기존 race 동작 유지).
- 메뉴바 미획득/메뉴 구조 미준비/후보 모호함/후보 비활성·실행 불가를 정상적인 후보 없음과 구별한다.
- 기존 최초 포함 총5회 상한·간격·성공 캐시는 유지한다. 상한 후 미확인이면 비활성 ‘확인 실패’로 표시해 계속 조회 중으로 오인하지 않게 한다.

## 검증과 전달

- XCTest215개와 Python23개 통과. 마지막 소스의 Debug 빌드 후 비표시 네이티브 회귀 검사 통과.
- 활성 앱/실행 사전 탐색 양쪽에서 AX 오류→정상 미발견→불완전 조회→성공 시 비활성→숨김→비활성→활성 전환을 가상 결과로 검사했다.
- 혼합 오류/미발견 race, 5회 오류 후 비활성/조회 중단, 종료 시 상태 폐기와 기존 경로/캐시/취소 검사를 통과했다.
