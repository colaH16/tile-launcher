# 메뉴 역할·제한 구조 진단 dev81 (R374, 2026-11-06)

사용자가 R373 분석 뒤 “진단 dev 진행해”라고 지시했다. 이번 범위는 진단 구현·교차 검토·검증·Developer ID 서명/공증·Homebrew `tile-launcher@dev` 게시다. 공증과 dev 게시를 완료했다. 정식 채널은 2.1.10(77)을 유지하며 Numbers 수집은 다음 실기로 진단한다.

## 목적과 범위

dev80의 Numbers Help 검색 클릭은 행 보관과 release 확정에 성공했으나, 500번째 메뉴 요소의 역할 읽기/분류에서 62ms 만에 실패했다. API 오류·잘못된 반환 타입·미지원 역할 중 실제 분기는 미확정이다. 이번 시험본은 그 분기와 필요한 경우 실패 요소 아래 구조를 확인하기 위한 진단이며 Numbers 해결 완료본이 아니다.

- A: 기존 역할 조회의 실패 사유·오류 번호·SDK 역할 범주를 기록한다. 원래 조회 결과와 수집 판정은 유지한다.
- B: 진단 빌드에서 `--menu-capture-log --menu-capture-structure`를 함께 지정했을 때만, 알려진 미지원 SDK 역할 첫 실패 뒤 실행당 한 번 제한 구조 조회를 허용한다.
- B 범위는 실패 요소 아래 역할·자식 관계다. 이미 읽은 참조로 증명할 수 있는 부모/형제 맥락만 사용하며 AXParent·새 루트·앱 전체/창·제목·값·액션 조회를 추가하지 않는다.
- 최대 64노드/깊이4/자식100, AX 메시지 제한 25ms, 최대1초와 원 요청의 남은 마감 중 짧은 것, 호출 전후 취소 검사. 메시지 제한은 엄밀한 벽시계 지연 보장이 아니다.
- 원래 캡처는 incomplete로 고정하고 진단 결과로 저장을 재개하지 않는다. 미조회·잘림·오류는 “없음”과 구분한다.
- 진단을 켜지 않은 실행에는 B의 추가 조회가 없다. 로그는 로컬 10분/1MiB/200건 한도를 유지하며 자동 전송하지 않는다.

## 분담과 검토

실제 기존 Claude 세션이 생산 코드, Codex 서브 에이전트가 실제 helper에 공급자를 주입하는 검증·독립 정책 리뷰·배포 준비를 맡는다. 루트 Codex는 통합 검토·격리 검증·서명/공증·게시·기록을 맡는다. 같은 파일의 동시 수정을 피한다.

## 동결 코드와 로컬 검증

- 생산 변경: `MenuHelpRoleDiagnostics.swift`의 실제 역할 분류/읽기, 일반화한 읽은 경로 추적, 제한 구조 탐색, 실제 children 읽기 helper, 실행당 latch/봉인 시점 epoch. resolver/monitor/logger는 진단 플래그 안에서만 연결했다.
- 독립 리뷰에서 하위 구조 우선순위, 알 수 없는 역할 확장 금지, 메뉴 항목 이외의 unsupported 자식은 미확인 처리, 실시간 로그 만료/포화 확인, 설정 변경과 진단 시작의 경쟁 조건을 보완했다.
- 봉인 때 epoch를 저장하고 시작 전후 및 호출 사이에 비교한다. 대상/설정/stop/suppression은 큐로 보내기 전에도 진단 epoch를 취소한다. 정상 캡처 policy와 OFF 분기는 유지한다.
- Swift ON346 / OFF338, 실제 role/children/path/gate/ledger의 주입 native 검사, logger의 만료·record/byte/pending 한도·개인정보·직렬화 검사, 기존 Option 검사, Python30이 통과했다.
- 일반 Release OFF 빌드가 성공했고 새 helper/roleFailure 및 두 실행 옵션 문자열이 바이너리에서 제거됨을 확인했다.
- 231개 검증 입력의 SHA256을 고정 사본과 원본에서 대조했다. 최초 Python 검사에서 검증용 사본에 CHANGELOG를 빠뜨린 에이전트 준비 오류가 1건 있었으며 해당 입력을 복사·지문 추가한 뒤 영향받은 Python 검사만 다시 실행해 통과했다. 최초 오류 로그를 보존했고 제품 소스를 바꾸거나 통과 검사를 반복하지 않았다.
- Codex 독립 리뷰의 최종 차단 이견은 없다. 실제 Claude의 마지막 읽기 전용 교차 검토도 실제 helper/검증기를 대조했고 차단 결함 없음·dev81 진행 동의를 확인했다.

아래 실제 배포 검증까지 통과했다. Numbers의 역할 원인은 이번 빌드의 새 실기 로그로 확인해야 한다.
