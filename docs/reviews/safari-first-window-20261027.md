# Safari 계열 첫 창 전환 · 2.1.7(68) 검증

## 사용자 재현 조건

Safari와 Safari Technology Preview를 완전히 종료한 뒤 실행하고, Option을 유지한 채 최근 창을 처음 선택하면 전환이 실패한다. 선택 직후 Option을 놓으면 전환되고, 창을 한 번 활성화한 다음에는 Option을 유지해도 정상이다. 다른 앱은 첫 선택부터 정상이라고 보고했다.

## 실제 관찰

읽기 전용 도구는 창 제목·내용·이미지를 수집하지 않고, 실행 상태·Option 상태·AX 반환 코드·창 ID·화면 표시 여부만 기록했다.

사용자 직접 재현의 STP PID 75492 표본 106개는 모두 `isFinishedLaunching=true`, `AXWindows=success(0)`였다. 실패 구간에는 AX 창 목록이 비어 있었다. 선택 직후 Option을 놓은 표본은 관찰 시작 후 50.940초, WindowServer 창 11420이 화면에 나타난 표본은 51.230초, 같은 ID의 AX 창을 얻은 표본은 51.523초였다. 이전에도 Option 해제 표본이 있었으므로, Option 해제 자체만으로 항상 전환된다는 뜻은 아니다.

따라서 이번 실패를 실행 완료 신호 누락이나 AX 오류로 설명할 수 없다. 제어 가능한 AX 창이 처음 노출되는 전환이 핵심이다. 다만 macOS/Safari 내부의 전환 보류 이유까지 확정한 것은 아니다.

## 제외한 후보

독립 도구에서 Option을 유지한 채 앱 열기를 한 번 요청했다. 122.528초 요청, 122.543초 같은 PID의 성공 콜백 뒤에도 AX 창은 비어 있었다. 두 번째 선택 무렵인 138.160초에 화면 표시, 138.449초에 AX 창 11628이 나타났다. 따라서 앱 열기 요청만으로 즉시 복구됐다고 해석하지 않았고 이 코드는 제품 후보에서 제거했다. 독립 도구와 실제 사용자 클릭의 활성화 문맥이 같다고도 가정하지 않는다.

## 68 후보의 변경

AX 창이 없는 첫 전환에서만 런처 활성화를 요청하고 최대 0.2초 동안 메인 런루프에서 확인한다. 이후 공개 `yieldActivation(to:)`와 `activate(from:options:)`로 대상 앱에 활성 상태를 넘기고, 원래 선택한 창 ID를 기존 상한 안에서 다시 조회한다. 대상이 종료되거나 다음 선택으로 취소되면 후속 동작을 중단한다. 창을 제어할 수 있는 기존 경로는 그대로다.

Option 키 합성·해제, 패널 닫기·자동 고정, 앱 재실행, Space 직접 쓰기를 추가하지 않는다. 실행 완료 판정 정책도 변경하지 않는다. 다른 창이나 다른 Space를 성공으로 간주하지 않는 기존 포커스 확인을 유지한다.
