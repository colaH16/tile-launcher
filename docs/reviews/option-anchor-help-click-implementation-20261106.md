# R361 · Option 최초 좌표 구현과 Help 클릭 누락 진단

2026-11-06, Asia/Seoul. 사용자가 코드 구현을 시작하고 실제 Claude와 Codex 서브에이전트가 코딩하며 루트 Codex가 선택 이유·예상 원인/해결방안을 설명하도록 지시했다. 이번 단계는 소스 구현·로컬 검증이다. 버전/서명·설치·dev/정식 공개는 별도 다음 단계다.

## 구현을 나눈 이유

Claude의 기존 Opus5.5 세션이 HoldMonitor의 최초 좌표와 main의 준비/표시/복원fallback 전달 및 native회귀 검사를 작성했다. 콜백을 직접 쓰는 PreviewFixtures 두 곳도 시그니처에 맞췄다. Codex 서브에이전트는 메뉴 진단 logger/행 판별·경로해결·입력 확정의 사유 기록과 전용 빌드 옵션/검사를 작성한다. 다른 Codex 서브에이전트는 독립 리뷰/검증계획을 맡는다. 루트는 설명·통합 검토와 격리 실행 검증을 맡고 제품 코딩을 대신했다고 주장하지 않는다.

## Option에 선택한 방식

원래는 Option을누른A와실제표시하는B사이에0.25초가있고,준비창을재사용하거나다시생성할때각각현재mouseLocation을읽었다. 그래서사용자가미리왼쪽위로움직이면창도B를기준으로다시놓여추가이동이필요했다.

유효한첫arm에서AppKit좌표를동기1회샘플하고지역상수로저장한다. 준비·표시·빠른재열기복원이안되는새생성까지같은인자로전달한다. optional공유변수보다취소/stop/재누름간좌표가섞일위험이적고,prepare가main.async로넘겨지기전에저장하므로이미움직인값을나중에처음읽지않는다.

실제하드웨어이벤트시각과같음을보장하는방법은아니며Option감지시점위치다. 기존빠른재열기저장프레임복원,수동호출현재커서,내용최신화/최종크기/화면안전경계는보존한다. 정상화면/음수원점/세로화면과실제원격입력의실기결과는합성검사와구별한다.

## Help 클릭의 예상 원인과 원인별 수정 선택

사용자가 확인한 사실은 **Numbers 일반 메뉴 클릭과 Help 검색 Enter는 수집되지만, Help 결과 마우스 클릭은 수집되지 않는다**는 것이다. 1.9.2에서 iTerm의 같은 범주를 고쳤던 행 지원은 현재도 존재한다. 전체 자동수집이 꺼진 것으로 단정하지 않고 검색 결과 클릭에만 더 필요한 단계를 구분한다.

| 예상 실패 단계 | 클릭과 Enter가 다를 수 있는 이유 | 확인 후 선택할 최소 수정 |
|---|---|---|
| 검색 결과 행 판별 | 일반 메뉴는 실행 가능한AXMenuItem이고 검색 결과는 표/행/셀이다. 기존 Help소속·단일문구 등 조건이 Numbers 실제 구조를 거절할 수 있다 | 관측된 정확한 구조를 fixture로 재현하고 필요한 어댑터만 보완. 일반 표나 본문까지 허용하지 않음 |
| 결과와 실제 메뉴 연결 | 클릭한 결과 문구를 실행 가능한 유일 메뉴 경로에 연결하려고 전체 catalog를 읽는다. 0.35초/800노드·깊이12/자식100 제한이나 조회실패면 연결 불가다. 실패를빈목록으로캐시하는제약도있다. Enter가 실제원래메뉴선택을얻은경우에는이단계를우회한다 | 실패와정상빈목록구분,완전성과유일성을유지한조회비용감소검토. 제한재시도도실익을확인한경우만. 부분목록이나제목만으로추측연결하지않음 |
| 마우스 해제/닫힘·입력 큐 지연 | release시점에행이사라지거나후보/좌표연결이안맞으면거절한다. 기존down후보fallback은이미있다. AX처리가직렬로밀려1초유효기간을넘을수도있다 | 어느이벤트/세션에서끊겼는지확인하고취소·세대·중복검사를유지한채그경합만수정 |

위 항목들은 코드에서 가능한 실패 경로이며 Numbers의 확인된 원인이 아니다. 수집 판단을 바로 완화하면 동명 PDF 메뉴나 literal/breadcrumb충돌을 잘못 연결할 수 있다. Claude가 제안한 selected leaf 우회도 그 반례를 대조해 철회했다. 그래서 이번 메뉴코드는 새 추측 해결책 대신 기존 입력/조회결과로 최초 실패 단계를 남기는 opt-in진단을 구현한다. 원인별 제품수정은 실제 진단 증거 이후다.

## 진단의 범위

기본Release는진단컴파일플래그를끄고,전용옵션으로컴파일한코드도명시실행인자가있을때만로그파일을만든다. 고유임시파일0600,최대10분/1MiB/관련기록200건과pending상한,비동기writer를쓴다. enum/불리언/개수/상대시간만기록하고검색어·메뉴제목/행문구·문서/창내용·AX원시값·원시좌표·키문자열은API에넘기지않는다. 로그때문에새AX읽기나상시polling을추가하지않으며완전히무비용이라고주장하지않는다. 파일한도/큐포화시누락이가능하므로마지막레코드를실제입력완료로추정하지않는다.

## 남은 범위와 현재 대기 상태

- Option은코드/합성AppKit어댑터·현재화면배치를검증했다. 실제사용자의Option감지·마우스이동/원격입력·다중모니터·화면분리실기는아직이다.
- Numbers는진단코드완료이며실제누락guard는미확정이다. 실제메뉴클릭/Help클릭/HelpEnter진단후원인별최소수정을고른다. 합성검사로Numbersclick→save성공을주장하지않는다.
- 로그는상한·backlog포화로일부기록이없을수있고,강제종료/크래시의전달은보장하지않는다. shortcut reader 내부의세부AX실패는추가probe하지않아총catalog시간/예산결과로만관측한다. flagON의원래deadline경계에로그시간영향이있을수있다.
- 로그인자는MenuUsageMonitor생성때한번읽으므로실기때는기존앱정상종료후새프로세스를해당인자로시작해야한다. 기존실행중인앱에open --args만전달하면활성화되지않을수있다. 이번단계에서생산앱종료/시작이나설정을조작하지않았다.
- 버전/빌드설정은2.1.10(77)그대로이며새DeveloperID서명/공증·앱설치·@dev/정식게시는미실행이다. 현재Claude/서브에이전트의코딩·검증은완료했고**사용자의다음단계인시험앱준비지시를기다리는상태**다. 다음행동은“시험앱만들어줘”라고진행지시하는것이다.
