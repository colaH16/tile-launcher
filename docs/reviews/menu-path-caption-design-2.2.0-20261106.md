# 메뉴 경로 UI·2.2.0 노트 설계 (R380–R382, 2026-11-06)

R380–R382 설계/노트 초안 완료(2026-11-06): ChatGPT Browser→New tab 인식 성공을 사용자 보고로 기록했고, 다음 공개는v2.2.0 하나에2.1.11 버그 수정 두 항목과2.2.0 메뉴 경로 기능을 별도 구역으로 포함하기로 했다. 실제 Claude/Codex의 UI 추천은 현재 icon/resource/shortcut 타일에 작은 부모 경로 위·기존 이름 아래(초기75%)이며, 위/아래/현재 배치와 글씨 비율을 비교하는 대화용 시안을 제공한다. 현재 사용자 디자인 의견/다음 구현 지시 대기다. 아직 Views 등 앱 코드·버전·빌드·설치·공개는 변경하지 않았고 활성 배포는2.1.11(82)이다. 다른 앱/메뉴 수집 시험 목표도 유지한다. 상세: docs/reviews/menu-path-caption-design-2.2.0-20261106.md.

## 현재 동작과 요청

MenuCommand.title은 path.last이고 Views.menuTile은 text glyph에만 부모 경로를 표시한다. icon/resource/shortcut에는 leaf 제목만 표시한다. 이름 중복 여부를 검사해 경로를 숨기는 로직은 없다. 전체 경로는 이미 tooltip에 있고 저장된 path만으로 표시할 수 있어 추가 AX 조회가 필요 없다.

사용자는 처음 이름 아래 경로·글씨50%를 제안했고, 뒤이어 작은 경로 위/큰 이름 아래를 함께 고민하자고 했다. 아직 배치·비율을 최종 승인한 것은 아니다. ChatGPT Browser→New tab 추가 성공은 사용자 보고와 첨부 화면으로 기록하며 모든 앱 성공으로 확대하지 않는다.

## 공동 추천과 비교

- 현재 일반 타일에서 이름의 크기/아래 기준선을 유지하고 위에 부모 경로 한 줄을 더한다. 기존12에 경로9(75%)를 초기 비교값으로 제안한다. 아이콘/단축키/리소스 타일이 우선 대상이다.
- text glyph는 이미 큰 이름과 경로가 하나씩 있어 중복 제목을 추가하지 않는 최소안을 권한다. 현재selected recentGraySquare는smallfalse이고 smalltrue는 recentPastel 비교 경로에만 있으므로 지금 작은 타일의 별도 사용자 결정을 요구하지 않는다.
- 부모 경로는 저장된 path.dropLast() 그대로 사용하고 없으면 생략한다. 앱 이름이나 별칭을 경로로 추측하지 않고 identity/실행 경로/수집 데이터를 바꾸지 않는다.
- 중복일 때만 보이면 프로필/최근 목록에 따라 문맥이 사라지므로, 부모가 있으면 표시하는 안을 권한다. 메뉴 이름을 부모 경로에 반복하지 않는다.
- 긴 경로는 가운데 생략으로 Browser 같은 루트와 가까운 부모를 최대한 남기고, 전체 경로는 tooltip으로 확인한다. 실제 잘림은 픽셀 폭에 따라 양 끝도 일부 생략될 수 있다.
- Option 코너 때문에 pin/사용 횟수가 아래쪽에 오는 경우 footer 오른쪽 여백을 확보하고 glyph 아래 여백은 실제 두 줄 높이에 맞춰야 한다. 타일 크기·패킹·클릭/드래그 동작 변경은 현재 제안에 없다.

실제 Claude는 처음 앞쪽 생략과 작은 타일 선택을 제안했으나, 사용자 목표 Browser 문맥 및 현재selected 스타일의 실제 호출을 대조한 뒤 가운데 생략/현재 일반 타일 우선 범위에 동의했다. 최종 차단 이견은 없다. 절반 글씨는12→6/8→4 논리 크기가 되므로 일률 적용을 권하지 않았으며,75%는 Apple의 규정이 아니라 기존u9/u12를 활용한 에이전트의 비교 시작값이다. [Apple 접근성 지침](https://developer.apple.com/design/human-interface-guidelines/accessibility)의 작은 글씨 가독성도 참고한다.

대화용 비교는 경로 위/경로 아래/현재 이름만의3개 안이며 글씨50–80%, 작은 크기, 긴 경로 예시를 조작할 수 있다. 표시 예시는 사용자 저장 메뉴를 읽어 만든 실제 화면이 아니다. HTML/동작 스크립트의 초기 렌더·비율·크기·긴 경로 조작 검사를 Node runtime으로 통과했으나 native 앱 픽셀/실제 SwiftUI 배치를 검증한 것은 아니다.

## 릴리스 노트 계획

별도v2.1.11 GitHub 릴리스/태그는 만들지 않고 다음v2.2.0 하나를 공개한다. 노트 제목2.2.0/범위v2.1.10→v2.2.0 안에 ###2.1.11의 두 버그 수정(Option 최초 커서 위치, 도움말 검색 마우스 누락)과 ###2.2.0의 경로 표시 기능을 나눈다. release/drafts/2.2.0에 기존 양식의 초안을 작성했다. 구현/검증 뒤 활성 설정을2.2.0으로 올릴 때 초안을 실제 결과로 다듬어 적용한다. 현재 config/notes/notes-range는82그대로 유지한다.

## 현재 단계

시안과 노트 초안 검토 완료·사용자 의견 대기다. 앱 코딩/새 빌드·공증·게시를 진행 중인 상태가 아니며 실제 Claude/서브에이전트가 백그라운드에서 구현 중이지 않다. 코드 구현은 다음 사용자 지시를 받아 진행한다. R379의 다른 앱 수집 실기 목표는 취소하지 않았다.
