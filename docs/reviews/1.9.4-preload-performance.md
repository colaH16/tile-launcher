# 사전 로드 후보 성능 측정

2026-10-16, R228. 추가 캐시 구현 여부를 판단하기 위한 계측이며 기존 앱의 동작·설치·릴리스를 바꾸지 않았다.

## 방법

- Apple M2 Pro, 논리CPU10개, macOS27.2 beta. 현재 수정 중인 소스1.9.4의 실제 AppIconCache, SavedMenuImages, MenuCommand.ordered/frequentIDs, MenuCommand.glyph를 Release 최적화 앱에서 호출했다.
- 저장 설정 plist를 읽기만 했다. 저장 메뉴15개/8개 앱, 가장 많은 앱5개 메뉴, 등록36개다. 등록 경로와 현재 실행 중 일반 앱 경로를 합쳐 중복을 제거한45개 아이콘을 사용했다. 앱뿐 아니라 등록 폴더·휴지통 경로도 포함한 묶음이다. 앱 이름·메뉴 이름·경로·본문은 결과 파일에 기록하지 않았다.
- 임시 앱의 진입점에서 NSApplication activationPolicy를 prohibited로 두고 계측 후 종료했다. 사용자 앱 실행/활성화/메뉴 AX 조회/키보드 조작/설정 저장은 없다. 프로덕션 인스턴스 잠금·모니터·메뉴바 아이콘 초기화 전에 분기한다.
- 새 프로세스10회. 아이콘 첫 읽기는 매번 한 번, 캐시 조회는300회, 이미지 그리기는128×128 RGBA 메모리 비트맵으로 첫 한 번/반복30회 측정했다. 앱 아이콘 객체를 미리 읽은 것만으로 최초 이미지 그리기 비용까지 없어지는지 구분했다.
- 메뉴 정렬+최근/자주 분류는 가장 큰 실제 앱10000회, 전체8개 앱 묶음2000회 반복 평균을 구한 뒤10개 프로세스의 중앙값/범위를 기록했다. 앱20개×100개 메뉴=총2000개 중 한 앱100개를 처리하는 합성 데이터도3000회씩 검사했다. 설정 저장·AX 실행 시간은 정렬에 포함하지 않는다.
- 시간은 DispatchTime 기반 경과 시간과 getrusage의 해당 프로세스 user+system CPU다. 다른 프로세스의 IconServices CPU나 GPU/기기 전체 전력은 포함하지 않는다. 아래 표는10회 중앙값이며 단위ms다.

실제 한 앱5개 메뉴의 반복 평균 경과 시간은 프로세스별0.00883–0.00983ms였다. 첫 계산은 전체8개 앱 합계0.105ms 중앙값으로, 이 작은 데이터에서도 첫 사용 비용과 반복 비용은 구분된다. 5개 메뉴 계산을10000번 반복한 해당 CPU 합계는 약0.094초다. 사용자가 몇 번 호출마다 메뉴를 누르는지와 관계없이 현 자료에서는 정렬 캐시 절감량이 작다.

첫 시험 프로세스에서는 앱 아이콘45개 읽기109.787ms/첫 그리기481.851ms가 관찰됐다. 이후9개 프로세스의 읽기는15.270–18.110ms, 첫 그리기는30.329–31.590ms 수준이었다. 첫 그리기481.851ms 동안 계측 프로세스 CPU는40.316ms였다. 지연을 확인했으나 다른 프로세스/스케줄링을 추적하지 않아 원인을 IconServices나 디스크로 확정하지 않는다. 이 값을 실제 오버레이가482ms 지연된 증거로 해석하지 않는다.

## 판단과 한계

1. **메뉴 정렬 캐시는 보류 권고**: 실제 대상은약0.01ms여서 갱신 규칙·기간 만료·편집본 관리 복잡도를 늘릴 근거가 부족하다. 훨씬 많은 메뉴를 쓰는 집 Mac에서도 데이터가 달라지면 다시 측정할 수 있다.
2. **앱 아이콘은 첫 로딩을 앞당길 여지는 있다**: 이 Mac의45개 묶음 읽기 비용은 보통약16ms지만 이후 조회는이미약0.02ms다. 최초1회와 새 아이콘의 지연만 줄이는 후보이며 매 호출 개선으로 제시하지 않는다. 실제 그리기 비용과 첫 시험의 큰 대기까지 단순NSImage 사전 읽기로 해결된다고 보장하지 않는다.
3. **메뉴 이미지 파일은 실제 사례 부족**: 이 Mac의 저장 메뉴에는resourceIcon이0개다. PNG/PDF 수치는 작은 합성 파일2개여서 사용자의 실제 메뉴 이미지에 일반화하지 않는다. 실제 메뉴의Symbol/단축키/텍스트 glyph 처리15개 묶음은 첫약4ms, 반복약0.19ms였다.
4. 프로세스 메모리 캐시만 비운 상태다. macOS 디스크·이미지 서비스 캐시는 강제로 비우지 않았다.10회 최초 로딩을 재부팅 직후 완전한 cold start로 표현하지 않는다. 서브ms 연산은 타이머 오버헤드를 포함한 반복 평균이다.
5. 전체 실제 화면의 Option 입력→첫 표시 지연, 이미 실행 중인 프로덕션 앱의CPU 사용률, 집 Mac의 화면 해상도/실제 메뉴 개수는 이번 측정 범위가 아니다. 해당 체감 문제를 확인하려면 집 Mac에서 별도 계측해야 한다. 현재 판단에는 여기서 얻은 부품별 비용만 사용한다.

계측 코드는 제품Sources에 추가하지 않았다. 재현 시 저장소를별도 임시 디렉터리에 복사하고 위 파일을복사본Sources/TileLauncher/PreloadBenchmark.swift에 넣는다. 복사본main.swift에서 기존`--render-previews` 분기 직전에 아래 분기를 추가한 뒤`DEVELOPER_DIR`을 해당 Mac의 전체Xcode로 지정해`TILE_LAUNCHER_OUTPUT_DIR=/tmp/tile-preload-bench-products bash scripts/build.sh`로 빌드한다. 동일 바이너리를새 프로세스로10회 실행하며 출력JSON 경로를다르게 한다. 계측대상프로필이없는Mac에서는실제데이터측정으로사용하지않는다.

```swift
if let index = CommandLine.arguments.firstIndex(of: "--benchmark-preload"),
   CommandLine.arguments.indices.contains(index + 1) {
    application.setActivationPolicy(.prohibited)
    do {
        try MainActor.assumeIsolated {
            try PreloadBenchmark.run(to: URL(fileURLWithPath: CommandLine.arguments[index + 1]))
        }
        exit(0)
    } catch { fputs("Benchmark failed: \(error)\n", stderr); exit(1) }
}
```

'/tmp/tile-preload-bench-products/Tile Launcher.app/Contents/MacOS/TileLauncher' \

JSON에는집계와시간만기록한다. 앱을설치/교체/전경활성화하지않는다. 이번실측원본과계측코드는위링크에보존했다.
