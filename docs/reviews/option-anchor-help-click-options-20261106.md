# R359 · Option 최초 위치와 Help 결과 클릭 누락의 대안 검토

2026-11-06, Asia/Seoul. 실제 기존 Claude 세션과 독립 대안/반례를 3차에 걸쳐 대조해 아래 최종 설계에 합의했다. 이번 단계는 해결 방향 선택이며 제품 구현·진단 실기·검증·새 배포는 아직 수행하지 않았다.

### 최신 사용자 확인

Numbers의 **일반 메뉴 직접 클릭과 Help 검색 Enter는 모두 최근 메뉴에 추가된다**고 사용자가 확인했다. 기존 Help 결과 마우스 클릭 실패와 함께 세 경로의 비교 근거가 확보됐다. 이는 사용자 실기 보고이며 이쪽에서 원본 AX/이벤트를 관측했다는 뜻은 아니다. 따라서 Help 결과 클릭의 행 판별·메뉴 연결·release/큐 지연을 우선 확인하되 특정 원인으로 단정하지 않는다. R357 좌표 전달과 R358 진단 우선 합의는 유지한다. 아래 초기 기록의 Enter 미확인은 이번 답변으로 해소됐다.

기존 Claude Opus5.5 세션24d0061b에서 인증 복구 후 1차 독립안, 2차 반례 대조, 3차 운영 조건 정정을 실제로 받았다. 각 응답은 성공했고 permission_denials가 없었다. 이번 단계의 남은 기술적 차단 이견은 없다고 양측이 확인했다. 이는 **구현 방향/진단 순서에 대한 합의**이며 Numbers 원인이 규명되거나 제품 구현/회귀/실기까지 끝났다는 뜻이 아니다.

### 다음 구현 단계의 구체 범위

1. Option 좌표 콜백과 함수 인자를 연결한다. 유효 arm의 canTriggerHold 확인 직후, quick reopen나 앱 갱신보다 먼저 캡처한다. 감지 시점 좌표이며 하드웨어 이벤트 타임스탬프와 완전히 같은 위치라고 보장하지 않는다. locationInWindow는 사용하지 않는다. 늦은 work의 실제 취소 동작을 검사하고 onPrepare/onShow의 서로 다른 guard를 동일하다고 설명하지 않는다.
2. Numbers는 명시 실행 인자·전용 컴파일 플래그를 켠 시험 구성에만 단계 진단을 넣는 안으로 선택한다. 기본 off·설정 영구 저장 없음, 기존 데이터/판단을 이용해 enum/불리언/개수/상대시간만 남긴다. 기본 진단을 위해 새 selectedHit/AX 조회를 추가하지 않는다. 로그에도 비용이 있으므로 무영향이라고 주장하지 않는다.
3. 로그는 실행별 고유한 안전한 임시 파일을0600으로 만들고 기존 파일을 덮어쓰지 않는다. 최대10분/1MiB/관련진단기록200건으로 제한하고 bounded비동기쓰기와세션/generation을사용한다. 제목·행라벨·검색어·문서/창내용·AX원시값·원시좌표·키문자열·토큰은기록하지않고자동전송하지않는다. 같은bundleID/DeveloperID는권한재요청을줄이는선택이지무조건재요청없음보장이아니다.
4. Numbers에서 직접 메뉴 클릭/Help 클릭/Help Enter를 한 번에 비교한다. 필요하면iTerm동일입력을기준비교한다. 이벤트큐대기·1초초과폐기, 행형태/Help소속, catalog완료여부와실패이유·노드수/시간/후보수, down/up행내포함, suppression/gate/기록결과만본다. 추가출처probe는필요할때별도라고명시한다.
5. 확인된 실패가 구조면 그 구조만fixture/parser에 반영한다. catalog면 성공한빈목록과실패를구분하고완전성/유일성을보존한비용절감을먼저대조한다. 고정노드/깊이/자식한도실패에재시도가도움된다고추정하지않고제한재시도도관측/측정후필요한경우만고른다. 입력경합이면generation/취소검증을유지하며그경로만고친다. 부분catalog의유일성추정·무조건제목매칭은채택하지않는다.

## 작업 범위와 현재 근거

- R357: 유효한 Option 첫 누름부터 약0.25초 표시 대기 중 움직인 커서가 창의 기준점을 바꾸지 않게 한다. HoldMonitor의 arm은 동기지만 onPrepare는 main.async이고, buildOverlay/takePreparedOverlay는 각각 최신 NSEvent.mouseLocation을 읽는다. 원인은 정적 코드에서 확인됐다.
- R358: Numbers Help 검색의 Menu Items 결과 클릭이 최근 메뉴에 추가되지 않는다는 사용자 보고다. 현재 Numbers의 Enter 성공은 미확인이다. R209/1.9.2에서 iTerm 동일 범주의 클릭 누락을 수정·정식 배포했고 현재 행 parser/유일 메뉴 연결/물리 선택 gate가 남아 있다. Numbers의 실제 AX 구조나 이벤트에서 어느 guard가 실패하는지는 미관측이다.
- R357/R358은 병행 범위이며 한 요청이 다른 요청을 취소하지 않는다. 단순 모델 동의가 실행 검증이나 실제 Numbers 수집 성공을 대신하지 않는다.

좌표 공급은 기존 AppKit 화면 좌표계와 일치해야 한다. arm의 동기 콜백에서 NSEvent.mouseLocation을 한 번 읽는 안은 표시 시점 조회를 제거하지만 물리 하드웨어 이벤트 시각과 완전히 같은 샘플이라고 보장하지 않는다. event.cgEvent 위치를 쓰는 대안은 원점/축·다중 모니터 변환을 추가 검증해야 하므로 Claude와 비교할 미결 세부사항이다. 비동기 onPrepare에서 첫 캡처를 해서는 안 된다.

현재 down 후보 fallback은 이미 존재한다. 따라서 행 소멸 가설만으로 새 캐시를 덧붙이지 않는다. Help catalog 실패를 []로 저장하는 코드는 성공한 빈 목록과 실패를 구분하지 않고 해당 세션에서 재시도하지 않는 제약이 있으나, 이것이 Numbers 원인이라는 실기 근거는 없다. Enter는 원래 메뉴의 focused/selected 항목을 얻으면 Help 문자열→전체 목록 연결을 우회할 수 있고, 클릭은 행 bounds의 release 좌표 일치를 추가 요구한다.

### 최소 진단 설계 제안

항상 켜진 폴링/전체 앱 읽기 대신 명시 진단 모드나 별도 도구를 검토한다. 실행 시간·파일 크기/권한을 제한하고 활성 앱/세션 generation 및 물리 선택에 연결한다. 검색어·문서 내용·텍스트필드 값·모든 메뉴 제목 목록을 로그로 저장하지 않는다. 읽는 범위는 기존 메뉴/Help 결과와 판별에 필요한 메타데이터로 제한한다.

기록 후보는 앱/런처 버전·선택 방식, 이벤트→큐 처리 지연, role 계층과 Help 소속 여부, cell/static-label 개수, catalog 완전성/실패 이유·시간/노드 수·매칭 후보 수, down/up 행 bounds 일치 여부, gate 거절 단계다. 실패 이유·시간 등을 얻기 위해 코드를 추가한다면 opt-in이며 정식 제품에 영구 진단을 섞는지 별도로 명확히 한다. 현 이미지로 해당 결과를 수집한 것으로 주장하지 않는다.

원인별 최소 대응: 관측된 구조만 fixture/parser에 추가; catalog 실패는 성공 빈 결과와 구분하고 유효한 물리 확정에 묶인 제한 재조회 가능성 검토; down/up/닫힘 경합은 기존 후보의 세션·세대/취소 검증을 보존하며 해당 경로만 보완; 중복 후보는 추측 기록하지 않는다.

검증은 Numbers에서 얻은 형태를 재현한 샘플, 기존 iTerm·일반 메뉴/Enter, 취소·행 밖 release·Help Topics·일반 표·Apple 메뉴 제외·중복/동명·오래된 세션/프로세스·catalog 실패/회복을 포함한다. 합성 검사는 실제 click→save를 대체하지 않으며 회사 Mac 기능 확인은 별도다.

## Claude 연결 상태와 다음 합의 절차

기존 세션24d0061b-0998-45a6-89f5-c68c4655a01c의 대화 기록을 확인했다. 예전 실행 프로세스는 끝났지만 같은 세션으로 재개를 시도했다. 실제 Claude CLI는 OAuth 만료·갱신 실패를 반환했고 modelUsage가 비어 있어 이번 검토 답변은 생성되지 않았다. 제한 밖 공식 auth status도 loggedIn=false/authMethod=none이다. CLI의 Read/Glob/Grep만 허용했으며 Bash/쓰기/MCP는 제외했다. 데스크톱 앱 로그인 여부를 CLI 로그인으로 추정하지 않았다.

기존 구독의 공식 CLI 로그인 흐름을 열었으나 Mac은 잠겨 있고 로컬 브라우저 제어도 비활성화돼 자동 진행을 마치지 못했다. 인증 정보·토큰·코드·인증 URL은 이 문서에 저장하지 않는다. 사용자에게 CLI 인증 완료 또는 검토안 우선 정리를 요청했으며 재인증 답변 전 Claude 합의를 주장하지 않는다.

인증 복구 후 동일 세션에 현재 코드/대안과 반례를 전달해 Claude 독립안과 Codex안을 비교한다. 단순 동의 대신 오탐·부하·좌표 수명/화면변경·실기 증거의 반론을 주고받고, 미관측 원인/해결책을 구분한 합의안을 기록한다. 사용자 단계별 진행 지시에 따라 그 다음 구현 단계 설명은 다음 작업 지시 때 이어간다. 새 설치·공증·정식/dev 배포는 이번 분석 단계의 완료로 추정하지 않는다.


## 인증 복구와 실제 공동 검토 재개

사용자가 CLI 로그인 완료를 알렸고 공식 auth status에서 loggedIn=true/claude.ai를 확인했다. 기존 동일 세션24d0061b를 Read/Glob/Grep만 허용해 재개했다. 실제 transcript의 모델claude-opus-5-5가 HoldMonitor/main 및 Help 수집 경로를 읽기 시작했음을 확인했다. 앞선 인증 대기는 해제됐으며 현재는 첫 독립안 답변/상호 반론 대조 진행 중이다. 최종 합의 완료 기록은 실제 응답을 받은 뒤 추가한다. 인증 정보는 저장하지 않는다.

추가 독립 점검: SDK NSEvent.h는 locationInWindow를 mouse-related 이벤트에 유효하다고 하므로 flagsChanged 좌표 공급으로 채택하지 않는다. CGEventGetUnflippedLocation은 main display lower-left 좌표이고 cgEvent는 nullable이다. 직접 현재 화면 높이로 y를 뒤집는 방식은 피한다. AppKit 호환 좌표인 CG 이벤트 좌표를 쓸지 arm에서 mouseLocation을 동기 샘플할지는 실기 보장 범위/복잡성을 포함해 Claude와 대조할 항목이다. 공식 문서: https://developer.apple.com/documentation/appkit/nsevent/locationinwindow 및 https://developer.apple.com/documentation/coregraphics/cgevent/unflippedlocation. 현재 이벤트 좌표의 로컬/원격 flagsChanged 실기를 검증했다고 주장하지 않는다.


## Claude 1차 독립 검토와 Codex 반론

실제 기존 Opus5.5 세션의 성공 응답을 받았고 permission_denials는 없었다. 읽기 도구만 사용했다. R357의 arm 지역 상수/콜백 인자 전달에는 동의했다. R358에는 Help 행 검증 후 시스템의 selected leaf와 라벨을 대조해 전체 catalog를 생략하는 fast path와 opt-in 로그를 같은 dev 빌드에 넣는 안을 1순위로 제안했다. Numbers에서 그 selected leaf가 실제 클릭 행의 실행 대상인지는 미관측임을 Claude도 명시했다.

Codex는 다음 반례를 보내 재검토를 요청했고 독립 서브에이전트도 코드로 대조했다.

- `selectedHit`는 `self.hit`를 호출하므로 Help 분기에서 다시 selectedHit를 부르면 Help형 메뉴 항목으로 재진입할 수 있다. 별도 primitive와 Help/Apple 제외 없이 단순 추가하면 안 된다.
- label/suffix 일치는 오래된 동명 leaf를 배제하지 못한다. `File/Export To/PDF…`와 `Other/Export To/PDF…`가 함께 있으면 기존 catalog의 유일성 검사는 거절하지만 선택된 한 leaf만 비교하는 안은 잘못 채택할 여지가 있다.
- 단일 literal 제목 `Export To > PDF…`와 계층형 `Export To/PDF…`의 충돌도 기존 resolveHelp는 함께 거절한다. 선택 leaf 하나만으로는 이 충돌을 알 수 없다.
- 행 frame과 release 게이트는 그 행을 눌렀다는 근거이지 다른 AX leaf가 그 행과 같은 명령이라는 입증은 아니다. 따라서 로그를 함께 넣는다고 그 명령을 먼저 기록하는 위험이 없어지지 않는다.
- Enter의 catalog 우회는 실제 원래 메뉴의 선택 항목을 얻은 경우에만 성립한다. Numbers 메뉴 크기/시스템 공통 구조를 근거로 원인 우선순위를 확정하지 않는다. 진단과 검증에 필요한 실제 사용자 참여 횟수도 지금 확정할 수 없다.

좌표 API에는 CGEventGetUnflippedLocation이 존재해 직접y변환이필수라는1차설명을정정요청했다. 동기mouseLocation의감지시점선택에는동의하지만측정하지않은수ms/하드웨어시각정확성은보장하지않는다. 또한현재onPrepare의timeridentity확인과onShow의guard가서로같지않으므로늦은작업이전부같은검사로막힌다고일반화하지않도록요청했다.

2차 응답에서 위 안전성/사실 반론을 대조한 뒤 최종 합의 여부를 기록한다. 제품 수정이나 회귀 실행은 아직 없다.
