# 2.1.9(75) 메뉴 막대 좌·우클릭 분리

2026-10-28, Asia/Seoul. R343 인계와 R344 사용자 재확인에 따른 로컬 시험 후보다. 최신 정식은 2.1.8(74), 현재 집 Mac 설치는 미공증 Developer ID 시험본 2.1.9(75)이며, 새 공증/소스 푸시/릴리스/cask 갱신/iCloud ZIP 전달은 하지 않았다.

## 동작과 구현

- 좌클릭: 기존 실제 오버레이를 `show(held:false)`로 연 뒤 기존 `pinOverlay()`를 적용한다. `present`의 reset이 끝난 다음 고정하므로 닫기 버튼을 표시한다. 이미 보이는 패널은 같은 창을 재사용해 고정·앞으로 가져온다. 두 번째 클릭으로 닫는 토글은 추가하지 않는다.
- 우클릭과 Control-클릭: 기존 열기/설정/접근성 권한 요청/종료 메뉴를 보존한다. 메뉴를 `NSStatusItem.menu`에 붙이지 않고 별도로 보관한 뒤 `NSMenu.popUp`으로 표시해 다음 좌클릭도 액션으로 전달된다. 버튼 강조는 defer로 해제하고 flipped 좌표계에서도 버튼 아래쪽에 메뉴를 붙인다.
- 기존 Option 길게 누르기, 메뉴의 열기, 최근 창/Space 전환, Esc/명시적 닫기, 설정·동기화·드래그 정책은 보존한다. 오버레이의 원래 앱 문맥은 런처 활성화 전에 만든다. 새 UI/전역 마우스 모니터/폴링/합성 키는 없다.

집 Developer ID 인증서는 유효하며 기본 Keychain은 잠금 해제 상태다. 기존 설치본의 회사 프로비저닝 프로파일에는 집 인증서가 포함되지 않아 검증기가 서명을 거부했다. 사용자는 기존 App ID·iCloud 컨테이너 범위의 프로파일 갱신을 명시 승인했다. Xcode CLI는 No Accounts 오류가 계속돼 Xcode 앱을 확인했으며, 앱의 계정 연결은 정상이나 이 인증서에 맞는 eligible profile이 없다. 사용자 재로그인/화면 잠금 해제와 웹 로그인 후 기존 App ID에 집 인증서를 선택한 전용 Developer ID 프로파일을 생성·다운로드해 해결했다. 인증서는 공개 파일 지문으로 정확히 대조했고 기존 회사 인증서·프로파일·컨테이너/schema는 변경하지 않았다. 개인 키 서명도 성공했다. 기존 앱과 설정 파일을 iCloud 밖 로컬 Library에 보존한 뒤 설치했다.
