# R242 · Messages 설정 탐지 경로 비교

2026-10-17. 개발 1.9.4(49). 사용자가 재시도 외 탐지 방법도 가능한 범위에서 조회하도록 요청했다. 준비 중이던48은 전달하지 않았으며49는 별도 진단 모드를 포함한다. 제품 AX 오류 재시도 소스는 R241대로 보존하지만 **이번 비교 모드는 제품을 실행하지 않는다.** 새 영구 캐시/추정 타일/자동 설정 실행은 추가하지 않는다.

## 독립 실험

`--app-settings-compare`는 일반 AppDelegate/인스턴스 교체/메뉴 자동 수집/오버레이/전역 입력 감시를 만들기 전 독립 분기로 진입한다. Messages가 활성화되면 시작하고 현재 활성 앱이 Messages이면 즉시 시작한다. 다른 앱으로 전환, 대상 종료/PID 변경, 접근성 권한 취소,60초 관찰 상한에 중단한다. Messages를 기다리는 시간을 포함해 전체90초 상한이다. 현재 설치 앱과 Messages를 먼저 종료한 뒤 사용자가 Messages를 직접 실행한다. 이 Mac에서는 재현을 위한 앱 조작을 하지 않는다.

하나의 worker 큐에서 경로별로 순차 실행하며 각 경로는 개별 AX 요청 최대300ms/전체2초 예산이다. 다음 순회는 이전 순회 완료 후0.2초다. 경로별 연속3회 전체 설정 탐지 성공이면 안정으로 간주하고 모든 선택 경로가 안정되면 종료한다. 실패하는 경로가 있으면60초까지 관찰한다. 순회마다 시작 경로를 바꾸지만, 같은 시작 조건 비교에는 `--app-settings-route`로 경로 하나만 선택해 Messages를 새로 실행해야 한다. 한 세션의 선후만으로 어떤 API가 준비를 유발했다거나 OS 내부 준비 시점을 확정하지 않는다.

| route | 경로 | 제한 |
|---|---|---|
| direct | AXMenuBar 단일 속성 | 기준 경로 |
| multiple | AXMenuBar/AXRole 일괄 속성 | 외부 성공과 개별 속성 오류를 별도로 해석 |
| children | 앱 AXChildren에서 AXMenuBar 역할 탐색 | 최대32개/역할만 조회, 창 내용 미탐색 |
| pagedChildren | 하위 개수→부분 목록 API→역할 탐색 | 최대32개, 잘린 목록은 로그 표시 |
| hitTest | 주 화면 메뉴바 예상 위치의 앱 한정 hit-test→부모 | 최대6단계/동일 PID 확인, 자동 숨김·다른 화면·가려짐 영향 |
| roleFirst | 앱 AXRole 조회 뒤 AXMenuBar | 선행 일반 조회의 영향 비교 |
| namesFirst | 지원 속성 이름 목록 뒤 AXMenuBar | AXMenuBar 포함 여부만 기록, 다른 속성 이름/값은 기록하지 않음 |

읽은 bar를 실제 제품 finder에 전달해 같은 앱 메뉴/단축키·설정 이름/유일 후보/활성/AXPress 지원 조건을 검사한다. finder가 AXMenuBar를 다시 직접 읽어 대체 경로를 무효화하지 않게 한다. AXPress는 실행하지 않는다. 프로세스가 다른 bar는 거부한다. AX 후보/창/대화 원문은 로그에 기록하지 않는다.

`--app-settings-observer-first`는 **별도 실행에서만** AXObserver 생성→앱 요소에 메뉴 열림/닫힘·포커스 창 변경 알림 등록→run loop 연결을 먼저 시도한다. 메뉴바를 선행 조회하지 않으며 등록 API의 성공/실패와 알림 상수만 기록한다. 이 옵션 없는 비교에서는 관찰자를 만들지 않는다. 기존47 자동 수집 관찰자와 섞지 않는다. 등록은 AX 응답/시간에 영향을 줄 수 있으므로 실험을 구분한다. 종료 시 run loop에서 source를 제거한다.

첫 순회 후 본체 Resources만 최대1초/12000개 엔트리/200개 아카이브/파일8MiB·합계32MiB로 조사한다. 기존 value-only MenuNibResources를 사용하며 NSNib/NSKeyedUnarchiver/외부 코드 로딩은 하지 않는다. main nib/storyboard 선언·아카이브 수·설정 이름 후보 수·잘림 여부만 남긴다. 메뉴 이름 문자열/경로는 기록하지 않는다. 후보 수는 정적 단서일 뿐 실행 중 메뉴 존재나 단축키의 증명이 아니다. 이 Mac Messages26.0 본체 Resources에는 해당 아카이브가0개였지만 사용자 Mac은 별도로 기록한다.

## 로그와 판독

- `session_start.fields.comparisonEnabled=true`인49 로그인지 확인한다. 일반 제품 `settings` 조회가 없어야 한다.
- `comparison/route_start`와 `route_end`를 requestID로 연결한다. route·round·order는 고정된 식별자와 순번이다.
- `barResolved=true`는 bar 획득·소유 PID 확인 완료, `reason=found`는 전체 설정 후보 확인 완료다. 둘은 다른 결과다.
- 일괄 API의 `axCode=0`이어도 AXValue 안의 속성 오류가 있으면 추가 ax_read와 실패 route_end가 남는다.
- `apiStartedMS/apiEndedMS`는 단조 시각, timestampMS는 벽시계다. 이벤트 sequence만으로 서로 다른 큐의 API 호출 순서를 추정하지 않는다.
- `resource_audit`는 hints이고 제품 지원 캐시로 게시하지 않는다. 비교 결과도 타일 표시/설정/사용 기록을 바꾸지 않는다.
- 기존0600/O_EXCL/O_NOFOLLOW 로그·32MiB 제한을 사용한다. 기본 실행에서는 비교/로그가 꺼진다.

## 공식 문서 및 제외한 방법

- [AX 단일 속성](https://developer.apple.com/documentation/applicationservices/1462085-axuielementcopyattributevalue): CannotComplete는 messaging 실패이며 값 없음과 구별한다.
- [앱 한정 위치 조회](https://developer.apple.com/documentation/applicationservices/1462077-axuielementcopyelementatposition): top-left 화면 좌표, system-wide 객체 없이 앱에 한정한다.
- [메뉴 표시 전 변경](https://developer.apple.com/documentation/appkit/nsmenudelegate/menuneedsupdate(_:)): 정적 리소스만으로 모든 런타임 메뉴를 확정할 수 없다.
- SDK AXUIElement.h의 batch 속성별 AXValue 오류/메시징 timeout을 확인했다. 전역 system-wide timeout은 변경하지 않는다.
- System Events AppleScript는 추가 자동화 권한/동일 AX 의존성이 있어 이번 읽기 비교에서 제외한다. 비공개 접근성 플래그 변경, 메뉴 강제 열기, 키 입력·클릭, 앱 활성화, 실행 파일 selector 문자열만으로 설정 지원 추정은 하지 않는다.
