# 1.9.5 공동 코드 리뷰

2026-10-18. 대상 제품 소스는 v1.9.5, `fcd64b0915fad555b7efdfdf401441a7a542b555`다. Claude Code가 읽기 전용으로 변경분과 호출부를 검토했고, Codex가 실제 소스와 대조한 뒤 과장되거나 기존 의도와 다른 해석을 전달해 재검토했다. 이 문서는 두 차례 응답을 종합한 기록이며 Claude 원문 보고서가 아니다.

이번 작업에서는 제품 수정, 앱 실행, 성능 측정, 빌드, 설치, 배포를 하지 않았다. 아래의 소스 경로 확인과 물리 입력 재현은 구별한다. 심각한 회귀나 측정으로 입증된 성능 저하는 발견하지 못했다. 결함이 없다는 보증은 아니다.

## 코드로 확인한 경미한 UI 문제

`Sources/TileLauncher/OverlayDragHandle.swift:108`의 begin은 action이 nil인 비활성 타일에도 pressed=true를 설정한다. 따라서 확인 중인 앱 설정 타일이나 실행 중복을 막은 앱 타일도 눌림 강조를 그리는 경로가 있다. release는 nil action을 실행하지 않으므로 잘못된 앱 실행 문제는 아니다. 실제 화면에서의 강조 정도는 이번에 측정하지 않았다.

권고: 향후 수정에서 눌림 강조만 action 유무에 따라 제한한다. 비활성 타일에서 시작하는 창 드래그는 유지한다. 확인 항목은 비활성 설정 타일의 클릭 시 강조 없음·실행 없음, 7픽셀 이후 창 이동, 활성 타일의 클릭·드래그 구분이다. 위험도는 낮다.

## 취소 범위의 방어적 개선 후보

`ApplicationSettingsMenu.swift:322`, `:324`, `:325`의 재시도 방어 조건은 전체 cancel을 호출한다. 이 함수는 `:233`에서 전경 요청 외에 launchedQueue와 launchedReader도 정리한다. 해당 조건에 도달하면 관계없는 다른 앱의 사전 탐색도 취소할 수 있는 호출 관계는 확인했다.

다만 정상적인 앱 종료 알림은 먼저 invalidate→cancelActive로 해당 요청을 중단한다. 따라서 일상 경로에서 실제로 다른 앱 탐색이 누락됐다는 근거는 없다. 낮은 우선순위의 방어적 개선 후보이며, 재현된 회귀로 분류하지 않는다. 권한 취소·전체 표시 끄기는 전체 취소가 맞으므로 호출을 일괄 변경하면 안 된다.

권고: 대상 프로세스만 무효화된 경우에 한해 cancelActive를 사용하도록 검토하고, 서로 다른 두 앱의 탐색이 겹치는 격리 검사로 확인한다. 위험도는 낮음~중간이다.

## 성능 가설 — 측정 전 제품 변경 보류

### 스크롤과 타일 눌림 표시

`Views.swift:220`의 anchor 해석과 `OverlayDragHandle.swift:55`의 대상 뷰 갱신은 스크롤 중 움직인 영역을 반영한다. frame은 값이 달라질 때만 설정한다. 모든 타일을 무조건 매번 다시 그린다는 초기 설명은 정정했다. 스크롤하지 않는 다른 섹션의 frame까지 매 프레임 바뀐다고 단정하지 않는다.

각 TileView의 draw 구현이 실제 계층에서 별도 이미지 메모리나 합성 비용을 얼마나 만드는지는 미측정이다. draw 존재만으로 큰 비용이나 프레임 저하를 확정할 수 없다. updateLayer 기반 단색 강조는 비교 후보지만 개선 효과는 측정 후 판단한다. SwiftUI 전체 렌더링·메모리·물리 스크롤 프레임 시간을 함께 비교해야 한다. 위험도는 중간이며 현재 잘 되는 입력을 보존해야 한다.

### 빠른 드래그 좌표

`OverlayDragHandle.swift:118`은 이벤트의 창 좌표를 현재 창 기준 화면 좌표로 변환한다. Claude는 대기 중인 이벤트와 이동한 창의 좌표 기준이 달라 떨림을 만들 가능성을 제안했다. 그러나 AppKit의 해당 이벤트 좌표 시점이나 실제 떨림을 이번에 입증하지 않았다. 전역 마우스 좌표 또는 CGEvent 좌표로 바꾸는 것도 검증된 해결책이 아니다.

권고: 실제 고속 드래그에서 문제가 보고될 때 좌표와 이벤트 시점을 비교한다. 현재 사용자가 만족한 드래그를 가설만으로 바꾸지 않는다.

## 기존 의도이며 이번 결함에서 제외한 항목

- 읽기 오류·구조 불완전·후보 모호성을 정상적인 설정 없음과 구별하고, 누적 5회 뒤 미확인 타일을 비활성으로 유지하는 정책.
- 하나의 경로가 불완전할 때 다른 경로의 미발견만으로 설정 없음을 확정하지 않는 보수적 판정.
- 배경은 문턱 없이 직접 창 이동, 타일과 설정·핀은 7물리픽셀 이후 원래 누른 지점을 보존하며 이동하는 동작.
- 드래그 후 클릭 취소, 마우스 입력 중 내용 갱신 지연, 우클릭·휠·스크롤바의 원래 경로 유지.

설정 메뉴 자체가 일시적으로 disabled인 경우에도 탐지 완료로 저장하지 않는 조건(`ApplicationSettingsMenu.swift:438`)은 기존 동작이다. 지원 여부와 현재 실행 가능 여부를 분리할지는 별도 설계 후보이며 이번에 변경하지 않았다.

## 다음 작업 권고

가장 작은 확정 문제인 비활성 타일 눌림 강조부터 처리할 수 있다. 취소 범위는 격리 재현을 먼저 하고, 렌더링·드래그 좌표 변경은 성능 또는 물리 입력 증거가 생긴 뒤 판단한다. 변경한 경우 시험 빌드를 iCloud에 전달하고 사용자가 영향받는 UI를 최종 확인한 뒤 공증·정식 배포한다.

## R287 후속 반영 — 1.9.6(57) 시험 후보

사용자 승인으로 취소 범위 보완만 반영했다. 세 요청별 방어 조건은 cancelActive 뒤 onChange를 호출하며 권한 취소는 전체 cancel을 유지한다. 부모가 자식 작업의 중단을 통지받아 다음 대기 앱을 시작하는 경로도 포함한다. 드래그·렌더링 가설과 비활성 타일 강조는 변경하지 않았다.

첫 회귀 검사는 기존 코드에서 다른 앱 작업 취소 오류로 실패했다. 수정 후 전경 요청 격리·중단된 자식 작업 뒤 대기열 진행·권한 상실 전체 취소 검사를 통과했다. Claude 재검토에서 제안한 테스트 준비 상태와 타이머의 경합, 실패 시 콜백 순환 참조를 보완했고, 최종 재독에서 차단 이슈가 없다는 답변을 받았다. 독립적인 코드 대조와 자동 검사 결과이며 실제 사용자 확인은 남아 있다.
