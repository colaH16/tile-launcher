# 메뉴 그룹/정렬 시안 · R215

사용자 요청은 고정 메뉴에만 순서 버튼을 표시하고 자동 수집의 자주/최근 메뉴는 사용 횟수순으로 정렬하는 것이다. 고정/자동 수집 사이 구분선을 넣되 고정이 없는 경우도 비교한 뒤 실제로 적용한다. 다음 구현은 사용자 지정 패치1.9.3(42)로 예약하며 현재 제품·공개·설치는1.9.2(41)다.

## 시안

1. 고정이 있으면 ‘고정 N개’ 제목 아래 수동 순서 메뉴를 배치한다. 위/아래는 실제 이동할 상대가 있을 때만 켜고, 자동 수집과의 사이에 얇은 Divider와 세로16pt 간격을 둔다.
2. 고정이 없으면 빈 고정 영역과 구분선 없이 ‘자동 수집 N개’부터 시작한다. 불필요한 빈 영역을 줄이는 추천안이다.
3. 고정이 없어도 ‘고정 0개’와 핀 안내, 구분선을 남긴다. 고정 기능을 더 잘 알릴 수 있지만 메뉴가 적을 때도 공간을 쓴다.

자동 수집 행에는 핀/삭제만 있고 위/아래 버튼이나 빈 버튼 자리는 없다. ‘자주 사용/최근 사용’ 표시와 기존 누적·메뉴 막대·Tile Launcher 사용 횟수를 함께 보여준다. 자주/최근 사이에는 추가 구분선을 넣지 않는다.

정렬 해석은 자동 수집 전체를 관찰+런처의 누적 사용 횟수 내림차순으로 정렬하고 동률은 최근 사용 시각순으로 정하는 것이다. 가상 예시4회·3회·1회를 사용하며 실제 사용자의 목록을 읽거나 바꾸지 않는다. 고정 순서는 수동이다.

## 구현 범위

MenuOrderProposal.swift는 비표시 시안 전용 SwiftUI 뷰다. TILE_PREVIEW_MENU_ORDER_PROPOSAL=1과 --render-previews를 함께 지정할 때만 이 세 이미지를 출력하고 종료한다. 일반 실행은 기존 설정/정렬/앱 인스턴스를 유지한다. 메뉴 원본 모델·실제 설정 UI·저장/병합 코드는 공개1.9.2와 같다.

R214에서 먼저 준비한 기존 규칙 유지 수정은 요청이 바뀌어 적용하지 않고 /tmp/tile-r214-superseded-prototype에 보존했다. 제품 버전과 릴리스 노트도1.9.2로 유지한다. 시안의 확인 전 공증·소스 푸시·새 GitHub 릴리스·설치를 하지 않는다.

## 검증

실제 AppKit/SwiftUI 비표시 렌더로 세 상태를 생성해 확인한다. 개발 출력은 /tmp/tile-r215-products이며 설치된 앱이 아니다. 빌드 로그는 /tmp/tile-r215-build.log, 시안 로그는 /tmp/tile-r215-previews.log다. 이미지의 제목/행/선/버튼 겹침과 자동 수집의 화살표 부재를 확인한 후 결과를 추가한다.

- 검증 완료: 시안 개발 빌드와 세 네이티브 렌더 모두 성공했다. 고정2개/자동3개, 고정0개/구분선 없음, 고정0개/빈 영역 유지 상태에서 제목·행·선·버튼이 겹치지 않고 자동 수집에 화살표가 없는 것을 실제 PNG로 확인했다. 네이티브 빌드의 아이콘 fallback도 그대로 표시한다.
- 원본 모델·실제 설정 UI·설정 store·제품 버전/노트가 HEAD의1.9.2와 바이트 단위로 동일함을 확인했다. 실행 owner도1.9.2다.
- 전달 이미지: 시각화 폴더의 tile-launcher-menu-order-with-pins.png, tile-launcher-menu-order-no-pins-clean.png, tile-launcher-menu-order-no-pins-placeholder.png.
