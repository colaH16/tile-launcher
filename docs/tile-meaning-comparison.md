# 최근 창의 크기·색 의미 비교

2026-10-14 · R159–R160 · 사용자 선택 전 제안

## 요청과 공통 전제

사용자는 같은 앱의 모든 창이 함께 앞으로 이동하는 방식이 혼란을 줄 수 있다고 보고, 개별 창의 최근 활성화 순서로 돌아가면서 첫 등장/반복을 크기 또는 색으로 구분하는 대안을 요청했다. 이어 크기는 데스크탑 위치, 색은 앱의 첫 등장 여부를 나타내는 반대 매핑도 포함하라고 요청했다. 이 문서는 비교 단계이며 실제 구현 변경 승인이 아니다.

- 순서는 모든 앱을 가로지르는 개별 창의 최근 활성화 순서다. 하나를 선택하면 그 창 하나만 맨 앞으로 옮긴다.
- 첫 등장은 현재 정렬된 목록을 앞에서부터 읽을 때 해당 앱의 첫 실제 창이다. 앱을 처음 설치/실행했는지 또는 과거 이력에 한 번이라도 있었는지를 뜻하지 않는다. 같은 앱이 떨어져 등장해도 이후 창은 반복이다.
- 실제 적용 시 앱의 안정적인 ID로 판정하고, 서로 다른 앱의 같은 표시 이름을 합치지 않는다.
- 현재 위치는 활성 앱이 있는 모니터의 보이는 데스크탑, 다른 모니터 위치는 다른 모니터에서 현재 보이는 데스크탑, 숨김 위치는 현재 보이지 않는 데스크탑이다. 창 최소화/앱 숨김/위치 미확인은 실제 수집 의미에 맞춰 별도 검토한다. 정보가 없다는 이유만으로 창 없는 앱으로 분류하지 않는다.
- 창 없는 앱은 모든 안에서 회색 1×1이다. 실제 창을 추적하는 타일 기준이며 브라우저 탭 수집을 새로 구현하는 제안이 아니다.
- 앱별 묶음은 만들지 않는다. 기존 작은 타일 세로 쌍과 큰 줄의 왼쪽→오른쪽 흐름을 유지하고, 나중 항목으로 이전 줄의 빈칸을 메우지 않는다.
- 채택 후 실제 앱에서는 표시 중 번호/선택 대상/배치를 고정하는 기존 입력 정책을 보존해야 한다. 아래의 즉시 재정렬은 비교용 실험이다.

## 네 가지 대안

| 이름 | 실제 창 크기 | 실제 창 색 | 위치 구분 보완 | 주된 장점과 비용 |
|---|---|---|---|---|
| 위치 크기 · 등장 색 | 현재 4×2 / 다른 모니터 보임 2×2 / 안 보임 1×1 | 앱 첫 등장 진한색 / 반복 파스텔 | 크기로 세 위치 구분 | 사용자가 제안한 반대 매핑. 위치가 직접 드러나지만 현재 위치의 반복 창도 4×2여서 큰 타일이 많아질 수 있다. |
| 등장 크기 · 위치 색 | 앱 첫 등장 2×2 / 반복 1×1 | 모든 모니터에서 보이는 창 진한색 / 안 보이는 창 파스텔 | 현/외 보조 표시로 현재와 다른 모니터 구분 | 서로 다른 앱을 더 많이 보여준다. 같은 앱의 다른 창 제목을 읽기 어렵다는 비용이 있다. 최근 영역에 4×2를 반드시 사용할 필요는 없다. |
| 최근 하나만 크게 | 가장 최근 실제 창 하나 4×2 / 다른 실제 창 2×2 | 보임 진한색 / 안 보임 파스텔 | 현/외 보조 표시 | 크기와 최근 순서의 강조가 일치한다. 앱 반복 여부는 아이콘으로만 읽으며 작은 창 타일이 없어 표시 밀도가 낮다. |
| 같은 크기 · 등장 색 | 모든 실제 창 2×2 | 앱 첫 등장 진한색 / 반복 파스텔 | 현/외/숨 보조 표시 필요 | 창 제목과 선택 영역이 일정하다. 창 사이의 크기 변화가 사라져 사용자가 원하는 혼합 타일 느낌은 약해진다. |

추천은 사용성 실험 결과가 아니라 에이전트의 디자인 판단이다. 서로 다른 최근 앱을 빨리 찾는 목적에는 ‘등장 크기 · 위치 색’을 먼저 시험한다. 데스크탑 위치 구분이 더 중요하면 ‘위치 크기 · 등장 색’이 더 직접적이다. 같은 앱의 여러 창을 자주 비교한다면 작은 반복 창을 없앤 두 안도 함께 평가한다. 파스텔에 ‘반복’과 ‘안 보임’을 동시에 부여하는 혼합 규칙은 제안하지 않는다.

세 크기를 모두 쓰는 것 자체는 목표가 아니다. 2×2와 1×1의 조합만으로도 크기가 섞이며, 기존 메뉴의 고정 4×2는 별도로 유지할 수 있다. 메뉴/등록 항목의 색 의미를 이번 요청으로 변경하지 않는다.

## 비교 화면과 한계

- 동일한 가상 목록: 터미널 3창, Safari 2창, Finder 2창, 메모 1창, 미리보기 1창, 창 없는 계산기 1개. 실제 사용자 실행 목록이나 현재 데스크탑 분포를 읽은 것이 아니다.
- 각 안은 같은 순서를 공유한다. 타일을 누르면 해당 항목만 앞으로 옮겨 첫 등장/반복을 다시 계산한다. 색/크기의 영향을 비교하기 위해 데스크탑 분류는 고정한다. 실제 앱 활성화·Space 이동을 수행하지 않는다.
- 번호는 비교용 전체 순번이며 실제 제품의 숫자 단축키 할당 변경을 뜻하지 않는다.
- 위치 보조 표시를 켜고 끌 수 있다. 같은 크기 안은 위치를 다른 채널로 표현하지 않으므로 항상 유지한다.
- HTML 비교 화면은 새 규칙을 설명하는 모형이다. 네이티브 빌드 렌더나 R158 글자 번짐 해결 근거가 아니다. 실제 반영 시 전체 scaleEffect 대신 실제 폰트·아이콘·레이아웃 치수로 그리는 후속 수정이 필요하다.
