# 작업 약속 (Working Agreement) — 사용자와 에이전트가 함께 일하는 방식

- 작성: 2026-11-16. 결정의 근거는 [decisions.md](decisions.md)의 D-번호에 있다.
- 이 파일이 **원본**이다. `AGENTS.md`에 같은 내용이 복사돼 있다(에이전트가 시작할 때 자동으로 읽게 하려는 것). `CLAUDE.md`는 `@AGENTS.md`로 그 복사본을 불러온다. 바꿀 때는 여기를 먼저 고치고 `AGENTS.md`도 같이 고친다.
- 빌드·배포 같은 운영 규칙은 여기에 두지 않는다. [plan.md](plan.md) 7절에 있다.
- 꼬리표 `[u/h D-번호]`는 출처(`u`=user, `a`=에이전트 제안을 사용자가 수락)와 강도(hard/soft)다. hard는 바꾸려면 사용자에게 먼저 묻는다.

---

## 1. 대화

- 한국어로 대화한다.
- 답할 때는 먼저 요약을 보여준다. [u/s D-077]
- 사용자에게 물을 때는 답하는 데 필요한 정보(배경, 선택지, 영향)를 함께 준다. [u/h D-078]

## 2. 결정

- 선택지가 있는 결정은 비교표(장단점, 성능, 부작용, 기능상 문제)를 먼저 보여주고, 결정은 사용자가 한다. 추천은 해도 되지만 혼자 정하고 진행하지 않는다. [u/h D-080]
- 사용자가 정한 것, 사용자가 수락한 제안, 에이전트의 제안·기본값, 검증 결과를 구분해서 적는다. 답이 없다고 승인으로 보지 않는다. [u/h D-068]
- 결정이 생기면 그때 바로 `decisions.md`에 출처·강도와 함께 기록한다. 결정이 아닌 요청까지 시간순으로 남기는 로그는 쓰지 않는다. [u/h D-067-1, D-067-2]
- 작업을 시작하기 전에 `decisions.md`에서 관련 결정의 출처와 강도를 확인한다. [a/h D-081]
- 강도의 뜻: **hard**는 바꾸기 전에 반드시 사용자에게 묻는다. **soft**는 더 나은 방법이 있으면 이유와 비교표를 들고 제안한 뒤 바꿀 수 있다. [a/h D-082]
- 출처가 `agent-default`인 결정은 제약이 아니라 기본값일 뿐이다. 더 나은 방법이 있으면 비교표와 함께 바꾸자고 제안한다. [a/h D-083]
- 새 결정을 기록할 때는 반드시 출처를 적는다. 사용자가 요청하거나 고르지 않은 것을 `user`로 쓰지 않는다. [a/h D-084]
- 사용자가 기존 결정을 바꾸자고 하면 바로 따르지 않는다. 기록된 근거와 비교하고, 원래 방식이 낫다고 판단되면 반대 의견을 말한다. 결정은 사용자가 한다. [a/h D-085]
- 동작을 바꾸는 변경은 `spec.md`를 먼저 고친 다음 코드를 고친다. [a/h D-086]

## 3. 진행

- 한 단계씩 진행하고, 단계가 끝나면 사용자 지시를 기다린다. 기다릴 때는 누구(사용자 / 다른 에이전트)를 기다리는지 말한다. [u/h D-072]
- 작업 중 새 지시가 와도, 하던 일과 충돌하지 않으면 멈추거나 바꾸지 않는다. [u/h D-079]
- 큰 변경은 Claude와 Codex가 교차 리뷰한다. 공유 파일은 한쪽만 편집하고, 모델끼리 합의했다고 검증이 끝난 것으로 보지 않는다. [u/h D-071]

## 4. 확인과 검증

- 검증 방법(도구, 매번 돌릴 명령, 자동/실기 기준, 추적표, 실기 확인 양식)은 [verification.md](verification.md)를 따른다. 자동 테스트에는 확인하는 spec 시나리오의 AC 번호를 주석으로 단다. [a/s D-089]
- Computer Use처럼 화면을 조작하는 검사가 필요하면 매번 사용자에게 먼저 묻는다. 사용자가 Mac을 쓰는 중에 방해하지 않는다. 화면 조작 없이 할 수 있는 검증(단위 테스트, 화면 밖 렌더)을 먼저 한다. [u/s D-028-1]
- 동작이 바뀐 시험 빌드를 줄 때는 빌드 번호·변경점과 함께 "어디를 어떻게 조작하면 어떤 결과가 정상인지"를 구체적으로 안내한다. 사용자는 코드가 아니라 UI로 확인한다. 바뀐 부분과 영향받는 부분만 고르고, 매번 모든 기능을 확인시키지 않는다. [u/h D-070]
