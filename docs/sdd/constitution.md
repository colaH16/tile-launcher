# Tile Launcher 프로젝트 원칙 (Constitution)

- 작성: 2026-11-16 (Phase 3). 기준 결정 기록: [decisions.md](decisions.md)
- **이 문서에는 출처가 `user`이고 강도가 `hard`인 결정만 들어간다.** 각 줄 끝의 D-번호가 근거다.
- 이 원칙을 바꾸려면 반드시 사용자에게 먼저 묻는다. 에이전트는 이유와 비교표(장단점, 성능, 부작용, 기능상 문제)를 들고 제안만 할 수 있다.
- 기능 단위의 user/hard 결정(예: 최근 메뉴 30일 규칙)은 [spec.md](spec.md)에 hard로 표시해 둔다. 여기에는 여러 기능에 걸치는 원칙만 모았다.

---

## 1. 이 앱이 무엇인가

1. **macOS 전용 네이티브 앱**이다. (D-001)
2. **목표는 Dock을 없애고 이 앱으로 대체하는 것**이다. 터치바·Stream Deck처럼 손 가까운 곳에서, 커서를 화면 끝까지 옮기지 않고 실행한다. (D-004-1)
3. **Option을 누르고 있으면 오버레이가 뜬다.** 이것이 기본 진입 방식이다. (D-032-1)
4. **등록 앱은 위치가 고정되고 숫자 키로 실행하는, 손이 외우는 경로다. 최근 창은 순서가 바뀌어도 되는 마우스용 목록이다.** 최근 창 순서를 고정하자는 제안은 하지 않는다. (D-041-1)

## 2. 생김새

1. **타일은 큰 클릭 영역을 위한 UX일 뿐이다. 모양·조작·단축키·창 버튼 위치는 macOS 관례를 따른다.** Windows식 UI를 만들지 않는다. (D-040-1, D-040-2)
2. **Liquid Glass는 배경과 버튼에만 쓰고, 타일은 불투명하게 둔다.** (D-061-1)
3. **창 썸네일을 쓰지 않고 창 이름으로 구분한다.** (D-022-1)
4. **크기를 키울 때는 타일만 키우고, 헤더·버튼·여백은 Apple 기본 UI 크기를 유지한다.** (D-045-2)

## 3. 조작

1. **오버레이는 Option을 누른 순간의 커서 위치를 중심으로 열고, 화면 밖으로 나가지 않는다.** (D-033-1, D-033-2)
2. **실행은 즉시 한다.** 클릭이든 ⌥+숫자든 누르는 순간 실행한다. (D-036-2)
3. **닫히는 규칙은 두 가지 상태로 나뉜다.** 내용은 두 상태 모두 실시간으로 갱신한다. (D-034-1, D-034-3, D-062)

   | | Option 유지 | 고정 (핀·⌥X·메뉴 막대 좌클릭) |
   |---|---|---|
   | Option을 떼면 | 닫힘 | 유지 |
   | 항목을 실행하면 | 유지 | 닫힘 (창 없는 앱 종료만 예외) |
   | ×·Esc·⌘W | 닫힘 | 닫힘 |

4. **Option이 아닌 방법으로 연 오버레이는 고정 상태로 연다.** (D-035-1, D-035-2)
5. **Option 대기 중 오버레이를 미리 만드는 동작은 지우지 않는다.** (D-063)

## 4. 메뉴

1. **단축키 없이 메뉴로 실행한 명령을 모든 앱에서 자동으로 모은다.** 앱별로 고르게 하지 않는다. (D-047-1)
2. **복사·붙여넣기도 메뉴에서 골랐다면 모은다.** 이름이나 단축키로 미리 거르지 않는다. (D-048-1)

## 5. 플랫폼·배포

1. **App Sandbox를 쓰지 않고 App Store에 올리지 않는다.** 기능을 우선한다. (D-005)
2. **GitHub Releases와 개인 Homebrew tap으로 배포한다.** 정식은 Developer ID 서명과 Apple 공증을 거친다. 시험판은 `tile-launcher@dev` cask로 내고, 회사 Mac은 @dev를 쓴다. (D-017-1, D-017-2, D-017-3, D-021)
3. **버전: 버그·UI 수정은 patch, 기능 추가·변경은 minor.** 사용자가 직접 정한 버전이 있으면 그것을 따른다. (D-018-1)
4. **릴리스 노트는 직전 공개 이후 모든 버전을 누적한다.** (D-019-1)

## 6. 데이터와 동기화

1. **여러 Mac 사이에서 설정을 동기화한다.** 범위는 메뉴와 일부 설정이고, 등록 앱·프로필·사용 기록은 각 Mac에 둔다. (D-010-1, D-011)
2. **동기화 충돌은 실제 편집 시각이 늦은 쪽이 이긴다.** (D-012-1)

## 7. 작업 방식 (에이전트에게)

1. **사용자 요청과 결정을 파일로 남겨, 다음 세션의 에이전트가 이어받게 한다.** (D-067-1)
2. **사용자가 정한 것, 사용자가 수락한 제안, 에이전트의 제안·기본값, 검증 결과를 구분해서 적는다. 답이 없다고 승인으로 보지 않는다.** (D-068)
3. **동작을 바꾸면 사용자가 직접 확인하기 전에는 공증·GitHub 정식·정식 cask를 갱신하지 않는다.** `@dev`는 확인 전에 갱신해도 된다. (D-070)
4. **진단·시험 전용 코드는 정식 배포본에 넣지 않는다.** (D-029-1)
5. **iCloud 동기화 폴더 안에서 빌드하지 않는다.** (D-020-1)
6. **새 macOS가 나오면 Apple 지침을 다시 확인한다.** 과거 수치를 영구 규칙으로 쓰지 않는다. (D-069)
7. **큰 변경은 Claude와 Codex가 교차 리뷰한다.** 공유 파일은 한쪽만 편집한다. (D-071)
8. **한 단계씩 진행하고, 단계가 끝나면 사용자 지시를 기다린다. 기다릴 때는 누구를(사용자/다른 에이전트) 기다리는지 말한다.** (D-072)
