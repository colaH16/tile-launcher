R148 비교 시안: 각 열 작은 타일 가로6칸, 최신 앱부터 위→아래로 앱 그룹을 쌓는다. 왼쪽은 보이는 모든 데스크탑의 창이며 앱 대표가 활성 모니터면4×2/다른 보이는 모니터면2×2, 후속은1×1로 전부 진한색이다. 오른쪽은 보이지 않는 창의 앱별 대표2×2/후속1×1 파스텔, 그 아래 창 없는 앱1×1 회색이다. 최신 순서 방향은 사용자가 확정했고 다른 모니터 대표 크기·회색 영역 위치는 시안 해석이다. 앱 적용 승인은 아직 없으며 설치본에는 포함하지 않는다.

R145 비교 중: 사용자 안은 보이는 창 2×2/보이지 않는 창 1×1이며 활성 모니터의 묶음 첫 창만 4×2다. 에이전트 추천 대안은 활성 앱 대표 창 하나만 4×2, 나머지 보이는 창 2×2/보이지 않는 창 1×1이다. 색은 R144대로 크기와 독립적이고 창 없는 앱은 회색 1×1이다. 두 안 모두 합성 비교 시안이며 사용자 선택 전 실제 앱/버전은 1.1.5로 유지한다.

R144 최종 시안 기준은 크기와 색을 독립적으로 정한다. 묶음 첫 창이 활성 모니터의 보이는 데스크탑이면 4×2, 그 외 첫 창은 2×2, 후속 창은 1×1이다. 모든 실제 창의 색은 현재 보이는 모든 모니터의 데스크탑 기준이며 크기/묶음 내 위치와 무관하게 보이면 진한색·안 보이면 파스텔이다. 창 없는 앱은 1×1 회색이다. R143의 후속 창 모두 파스텔 조건은 철회됐다. 아직 시안이며 설치/공개 앱 1.1.5는 유지한다.

R143 시안 확정 규칙: 첫 창은 활성 모니터 4×2 진한색, 다른 모니터의 보이는 데스크탑 2×2 진한색, 보이지 않는 데스크탑 2×2 파스텔이다. 후속 창은 모두 1×1 파스텔, 창 없는 앱은 1×1 회색이다. R142의 활성 모니터만 강조하던 시안 가정을 대체한다. 아직 실제 앱 적용 전이며 설치/공개 1.1.5를 유지한다.

R142 비교 단계: 활성 모니터의 앱 묶음 첫 창 4×2/다른 보이는 모니터의 첫 창 2×2/묶음의 후속 창 1×1을 현재 캡처로 시각화한다. 실제 모니터 분류·앱별 목록 묶기는 아직 채택 전이며 설치·공개 1.1.5의 전역 MRU·2×2/연속 1×1은 유지한다. 모니터 B 분포는 가정이며 23개 합성 창·앱을 사용한다. 채택 후 구현은 기능 변경 minor 1.2.0이다.

## 제품과 플랫폼 경험

- Option으로 큰 오버레이를 불러 앱·창·메뉴를 빠르게 선택한다. 터치바와 Stream Deck의 접근성을 키보드 가까이 가져오는 것이 목적이다.
- 타일은 공간 배치와 넓은 클릭 영역을 위한 UX다. R65에서 실제 적용을 승인해 유리 배경 위에 더 불투명한 색 레이어와 밝은 타일을 사용한다. R70부터 유리·파스텔(기본)과 클래식·직각 테마를 설정에서 선택·저장한다. 유리는 고정 메뉴 노랑/현재 데스크탑 창 파랑, 클래식은 초록/파랑과 완전 불투명 타일이다.
- 닫기/핀과 뒤로 가기는 왼쪽, 앱 이름·창 설명은 중앙, 원형 유리 설정 버튼은 오른쪽이다. R66에 따라 프로필 선택은 등록 항목 제목 옆으로 옮겨 중복 없이 제공한다.
- macOS 기본 메뉴·⌘W 닫기·⌘, 설정·⌘H 가리기·⌘Q 종료와 포커스·접근성 관례를 유지한다. 다른 앱의 단축키를 전역에서 소비하지 않는다.
- Apple 지침과 재질은 OS 업그레이드 때 [업그레이드 절차](macos-upgrade-guide.md)로 재확인한다. 시안 CSS나 임의 곡률을 Apple의 고정 규격으로 취급하지 않는다.
- 기능을 우선한다. 향후 Homebrew Cask를 고려하며 App Store는 필요한 기능을 유지할 수 있을 때만 검토한다.

## R52 확정 레이아웃

- 첫 비교안 채택: **위 왼쪽 메뉴 / 위 오른쪽 최근 창 / 아래 전체 폭 등록 항목**. 메뉴와 최근 창의 시작·끝 높이와 타일 모듈을 맞춘다.
- R131: 최근 창은 전역 최근 순서다. **첫 창 또는 바로 앞 창과 앱이 다르면 2×2, 같으면 창 이름이 있는 1×1**. 창 없는 앱은 회색 1×1에 앱 이름을 표시한다. 작은 두 개는 같은 열의 위·아래에 놓고 큰 타일 높이의 줄을 왼쪽에서 오른쪽으로 채운 뒤 다음 줄로 이동한다. 홀수 작은 타일 아래/이전 줄 빈칸을 후속 줄 타일로 채우지 않는다.
- `Terminal cc2 → Terminal se3 → Safari → Terminal local`은 2×2·1×1·2×2·2×2다. 앱마다 창이 하나라면 모두 2×2다. 떨어져 있는 같은 앱의 창을 모으거나 중복 제거하지 않는다.
- 큰 타일도 그 개별 창을 전환한다. 별도 최근 앱 영역은 표시하지 않는다. **R52는 초기 앱/창 분리 요구 및 R47–R51의 미정 상태를 대체한다.**
- 행 우선으로 순서대로 배치하고 빈칸에 뒤 항목을 끌어올리지 않는다. R62부터 최대 3.3줄을 보여주어 다음 줄 일부가 보이며 초과분은 세로 스크롤한다.
- 일반 Option 호출에서는 타일 크기/최근 순서를 고정하고 재호출 때 갱신한다. R67에 따라 고정 오버레이는 활성 앱/창 변경을 따라 갱신하되 Option 유지·선택 대기·마우스 누름/드래그 중에는 대상을 고정한다.
- R135: 메뉴는 고정·빈도·최근을 한 섹션에서 크기와 배경/핀으로 구분한다. 고정 메뉴는 강조색 가로형 4×2로 맨 앞, 자주 사용은 파스텔 2×2, 최근 사용은 회색 2×2다. 큰 메뉴 둘을 한 행에 나란히 놓는다. 메뉴 색 선택은 고정·자주 사용에 적용하고 최근 회색은 유지한다.
- 등록 앱·폴더만 작게 표시한다. R60에서 아이콘 32pt를 유지하며 최소 60pt 정사각 타일과 8pt 간격으로 보완했다. 배경/테두리·마우스 반응·우상단 숫자를 사용하며 메뉴/최근 창 크기는 유지한다. R70부터 모서리는 선택한 테마에 따른다.

- R65: 배경색 레이어 0.72, 유리 테마의 타일 배경색 레이어 0.96, 클래식의 타일 레이어 1.0이 초기 구현값이다. 실제 유리 합성 전체의 alpha와 구별한다. 글자/아이콘은 불투명하게 유지하고 밝은 강조 타일은 짙은 글자를 사용한다. 투명도 줄이기와 대비 증가에 대응한다.

- R73 확정 아이콘은 파란 계단형 바탕에서 초록 타일이 오른쪽 위로 빠져나오는 두 요소의 컬러 ICNS다. 메뉴 막대는 동일 형태의 18pt 단색 NSImage template다. 세 칸 격자 및 Option 형태 후보를 대체하며 테마와 관계없이 같은 앱 정체성을 유지한다.
- 별도 Square 비교 앱은 R71 요청으로 휴지통에 옮기고 소스도 단일 앱으로 정리했다. 두 테마는 앱을 나누지 않고 설정에서 전환한다.

## R76 · 모양 설정과 섹션 색상

- 설정 탭 순서는 **일반 / 모양 / 메뉴 / 등록 항목·프로필**이다. 테마는 일반에서 모양 탭으로 옮긴다.
- 메뉴·최근 창·등록 항목별 기준 색을 선택·저장한다. R135에서 메뉴 기준 색은 고정·자주 사용에 적용하고 최근 메뉴는 회색으로 구분한다. 최근 창/등록의 기본색·현재 데스크탑 강조 및 기존 데이터/순서는 보존한다.
- 기본 메뉴는 클래식 초록/유리 노랑, 최근 창은 파랑, 등록 항목은 보라 계열이다. 등록의 보라색 및 색으로부터 기본/강조 명도를 만드는 방식은 에이전트의 초기 구현 선택이다.
- 사용자가 고른 섹션 색은 두 테마에서 같은 기준 색으로 유지한다. 유리는 강조를 파스텔로, 클래식은 불투명한 원색으로 표시하며 기본 타일은 라이트/다크에 맞게 배합한다. 텍스트와 보조 텍스트의 대비를 자동으로 조정한다.
- 섹션별 기본색/전체 기본색 복원을 제공한다. 기본값 복원은 색만 바꾸며 기존 프로필·등록 항목·메뉴·테마는 보존한다. 사용자 투명도 선택은 추가하지 않는다.
- R75의 수동 등록 기록만 사용하는 범위는 R80–R82의 메뉴 자동 수집 구현으로 확장한다.
- R77: 사용 중인 화면을 방해하지 않는 컴파일·테스트·샘플 렌더링을 우선한다. Xcode Canvas용 Preview와 별도 PNG 출력은 실제 권한·WindowServer 합성·전역 입력을 검사한 것으로 설명하지 않는다.
- R78: 기본 타일은 어두운 회색 혼합 대신 흰색을 섞어 부드러운 파스텔로 표시한다. 현재 다크 기본색의 흰색 혼합은 클래식 0.50/유리 0.76이다. 클래식 강조는 기준 색 그대로, 유리 강조는 다크 0.56/라이트 0.72로 조정한다. 저장된 사용자 색이나 모서리·불투명도·정렬 의미는 변경하지 않는다.
- R79의 설계 제안은 R80–R82에서 구현을 승인했다. [메뉴 관찰 동작과 제한](menu-observation-design.md) 및 실제 검증 범위는 validation.md를 함께 확인한다.

## 호출·고정·숫자 단축키

- R104–R108: 선택 없이 Option 해제로 닫힌 오버레이는 기본 0.6초 이내 Option 단독 재입력 시 직전 위치·크기로 즉시 다시 연다. 평상시의 250ms 대기를 적용하지 않는다. 일반 설정에서 켜기/끄기와 0.1–2.0초를 0.1초 단위로 조절·저장한다. 기존 설정에 값이 없으면 켜짐/0.6초로 시작한다. 창 위치만 복원하며 메뉴·창 목록·프로필은 재호출 시점의 정상 갱신 정책을 따른다. 닫기는 지연하지 않는다.
- 입력 이벤트의 단조 timestamp를 기준으로 재입력 간격을 측정한다. 닫을 때의 설정 시간을 기억하며 한 번의 닫힘을 한 번만 복원한다. 설정 시간 초과·비활성화·역전/비정상 시각은 일반 호출로 돌아간다. 항목 실행 대기가 있거나 Option 호출이 아닌 창, Esc/닫기/설정, 중간 키/보조키/클릭, 화면/Space 변경에는 복원을 취소한다. 복원 프레임을 담는 화면이 없어졌으면 현재 화면의 정상 배치를 사용한다. 고정된 창은 기존처럼 Option 해제만으로 닫히지 않는다.

- 설정에서 Option 호출을 켜고 끌 수 있다(기본 켜기). 초기 호출값: 좌/우 Option 단독 250ms. 표시 전 타이핑·다른 보조키 조합은 호출을 취소한다. 표시 이후 Command 추가만으로 닫지 않는다.
- R109: 클릭은 Option 유지 여부와 상관없이 즉시 실행한다. 숫자키로 명시적으로 선택한 항목은 Option을 놓으면 실행한다. 클릭은 이전 숫자 선택 대기를 취소하며 해제 때 중복 실행하지 않는다. 포인터를 올리는 것만으로 실행하지 않는다. 고정하지 않은 패널에서 선택 없이 놓으면 닫는다.
- R110: 설정 아이콘/설정 단축키는 일반 탭, 메뉴 +와 빈 메뉴 타일은 클릭 시점 앱의 메뉴 추가 시트, 등록 +와 빈 등록 안내는 등록 항목·프로필 탭을 즉시 연다. 기존 설정 창에서도 탭/추가 대상 앱을 갱신한다. 메뉴 추가 시트는 자동 메뉴 읽기·검색·수동 경로 입력·추가를 제공하고 기존 메뉴 탭의 ‘메뉴 추가…’에서도 열린다.
- R116–R117이 R114의 별도 권한 탭을 대체한다. 권한은 일반 하단에 통합하며 R118에 따라 기본 폭은 580pt이며, 실제 GeneralSettingsContent의 높이를 측정해 바깥 여백 16pt씩을 더한다. 일반 내부에는 바닥 여백을 중복으로 두지 않아 버전 아래에 바깥 16pt 여백만 남긴다. 1000pt 고정 높이는 사용하지 않는다. 처음 생성/닫았다 다시 열 때 기본 크기를 적용하고, 이미 열린 창에서 탭을 바꿀 때는 사용자가 조절한 크기를 유지한다. 리사이즈는 계속 허용한다. 화면 작업 영역의 네 변에 24pt 여백을 두고 초기 창 프레임을 제한한다. 기존 최소 창 프레임 540×660pt도 작은 화면의 상한 안으로 줄인다. 일반은 작은 창·긴 로그인 오류 안내에서 스크롤로 하단에 접근한다. 메뉴 추가 버튼은 하단에 고정하고 메뉴 목록의 180pt 고정을 없애 남는 높이를 사용한다. 자세한 설명은 펼침 안내로 정리하고 상단 설정이 넘치면 목록과 별도로 스크롤한다. 기간·수집 중단·목록 비우기·핀/순서/횟수 기능과 저장 데이터는 유지한다.
- R112: 수동 메뉴 추가 후보에서도 Apple 시스템 메뉴와 Recent Items 등 하위 전체를 제외한다. 기존 명시적 등록/고정과 앱 자체 동명 메뉴는 유지한다. 추가 시트는 부모 콘텐츠 높이에서 64pt를 뺀 크기로 넓게 표시하고 목록이 남는 공간 전체를 사용한다. 0.17.3 기본은 540×696pt였고 R114의 640×820pt 부모에서는 540×756pt였다. R116 당시 580×1000pt 부모에서는 540×936pt였다. R118부터 부모 높이는 일반 내용에 맞춰 측정한 값이며 시트도 해당 부모 높이-64pt를 따른다. 540×660pt 부모 콘텐츠에서는 500×596pt이며 부모 리사이즈를 따라간다. 직접 입력을 펼쳐도 목록/컨트롤이 영역 안에서 조절된다.
- R111·R116: 일반 → 권한에서 접근성·앱 관리 확인 화면을 각각 제공한다. 접근성은 창/메뉴 조작용, 앱 관리는 다른 앱 업데이트/삭제용이라고 설명한다. 앱 관리 자동 승인·필수 권한 판정·전체 디스크 접근 요청은 하지 않는다. Safari 웹 앱의 앱 관리 알림 보완을 위해 아이콘 리소스를 직접 읽고 앱 실행/문서 열기 API를 구별한다. 실기 알림 해소 여부는 validation.md와 구별한다.
- R53 **사용자가 확정한 기본값은 ⌥1–9/0 등록 항목, ⌥⌘1–9/0 최근 창**. 설정의 라디오 선택으로 두 대상을 서로 바꾼다. 0은 10번째이며 첫 10개에 숫자 배지를 표시한다. 각 제목 줄에 현재 조합을 안내한다.
- 숫자는 오버레이가 키 입력을 받을 때만 로컬 처리한다. 열기 전 조합이나 다른 앱에 포커스가 있을 때는 가로채지 않는다. 한국어/영어 입력과 무관한 물리 숫자열 및 숫자 키패드를 지원하며 Shift/Control을 추가한 조합은 숫자 선택으로 해석하지 않는다.
- 숫자를 고른 뒤 다른 숫자로 대상을 바꿀 수 있고 반복 키는 재실행하지 않는다. 취소·설정·핀 조작은 이전 실행 대기를 취소한다. 없는 번호는 실행하지 않는다.
- 폴더의 ‘오버레이 탐색’은 기존 클릭과 같이 바로 진입한다. 안에서는 숨겨진 등록/최근 창 번호를 실행하지 않는다. 파일·앱/Finder 열기는 클릭하면 즉시 실행하고 숫자 선택이면 Option 해제까지 기다린다.
- 왼쪽 위 핀 또는 ⌥X로 현재 패널을 고정하고 같은 자리는 닫기 ×로 바뀐다. 고정 상태는 Option 해제·바깥 클릭에 유지되며 Esc/⌘W/×로 닫는다. 재호출 시 고정은 초기화한다.
- R59: 핀 버튼/⌥X는 같은 처리기로 앱 활성화와 패널의 키보드 포커스를 요청한다. Command 조합은 패널의 key-equivalent 경로와 로컬 키 이벤트를 공통 처리한다. 다른 앱을 명시적으로 선택한 후에는 그 앱의 단축키를 가로채지 않는다.
- 고정 중 항목 실행은 패널을 유지하되 설정/권한 화면 이동·디스플레이 구성 변경은 닫는다. Option을 유지한 ⌘,로도 고정 없이 설정을 연다.
- 고정 상태에서 상단의 버튼을 제외한 제목·설명·전체 여백을 AppKit 기본 드래그로 이동한다. 컨트롤의 실제 bounds를 제외한다. 위치는 현재 표시 동안만 유지하며 재호출 때 커서 기준으로 돌아간다. 폴더 뒤로 버튼도 원형 Liquid Glass다.

- R63: ⌥W 닫기, ⌥, 설정을 추가하고 ⌘W/⌘,·Esc는 유지한다. 오버레이의 로컬 입력에만 적용한다.
- R61: ⌥A/S 이전, ⌥D/F 다음 프로필. 가로 쓸기 왼쪽은 다음/오른쪽은 이전이며 한 제스처 한 단계만 순환한다. 세로 스크롤·관성·취소와 구분한다.

## 최근 창·크기·배치

- 모든 앱의 열린 OS 창을 대상으로 하며 현재 창도 포함한다. iTerm 탭/분할을 별도 창으로 만들지 않는다. 닫힌 창·종료 앱은 정리하고 관찰하지 않은 과거 순위를 만들어내지 않는다.
- 최소 6개 용량. 일반 화면은 최대 3.3줄, 작은 화면은 등록 한 줄도 함께 보이도록 축소한다. 자동은 전체 창을 유지하고 영역 밖 항목은 세로 스크롤한다. 수동은 6 이상의 최대 개수, 제품 고정 상한 없이 실제 창 수까지만 표시한다.
- R57: 다른 데스크탑의 열린 창도 포함하며 **현재 데스크탑의 모든 창**을 파란 배경으로 표시한다(R65/R70). 여러 화면이면 각 화면의 현재 데스크탑을 포함한다. 전역 최근 순서를 유지하며 데스크탑별로 재정렬하지 않는다.
- AX 목록 누락/시간 초과를 닫힘으로 간주하지 않는다. WindowServer 창 ID/PID와 AX 객체/닫힘 알림으로 유지·삭제를 판단한다. 처음 관찰한 다른 데스크탑 창의 제목이 없으면 대체 제목을 쓰고 선택 시 AX를 다시 조회한다.
- R124–R125: 정상 최대 폭 1120pt/높이 840pt, 작은 타일을 읽기 위한 정상 배치 기준 폭 840pt/높이 620pt, 작은 최소 패널 512×420pt와 화면 24pt 여백을 유지한다. 정상 타일은 4/2/1 반단위 모듈로 배치하며 작은 화면에서는 메뉴를 접고 창 뷰포트를 줄인다. 초기 폭은 화면별 상한을 적용하고 높이는 현재 프로필의 등록 행과 최근 3.3줄을 합산한다. 프로필 변경은 드래그한 x/윗변을 유지하고 화면 한계 안에서 줄이거나 늘린다. 이전 1.45 목표/비율 전용 빈 공간을 대체하며 초광폭 화면에서 계속 늘리지 않는다.
- 메뉴 4개 정사각 단위, 최근 창 최소 6개 단위의 공통 모듈과 간격 8pt를 사용한다. R131의 2×2/1×1은 같은 반단위 모듈이며 큰 타일 높이의 줄로 묶는다. 실제 제목·작은 타일 가독성은 네이티브 검증 대상이다.
- 가용 영역이 작으면 메뉴를 생략하고 최근 창/등록 항목을 우선하는 작은 화면 배치를 사용한다. 512×420pt 패널도 들어가지 않으면 안내하고 메뉴 막대 설정을 제공한다. 전체 폰트를 통째로 축소하지 않는다.
- 호출 순간 커서 모니터의 visibleFrame을 기준으로 중심을 잡고 가장자리에서 위치만 보정한다. 열린 뒤 커서를 따라가지 않는다. 앱 문맥은 커서 아래 앱이 아닌 호출 직전 활성 앱이다.
- R62가 R56의 30% 여백 규칙을 대체한다. 상단 빈 여백 없이 메뉴·최근 창의 공통 높이를 최대 3.3줄로 늘린다. 등록 선반은 남는 공간에서 완전한 행 단위로 일반 최대 3줄/작은 배치 최대 2줄을 표시하고 자체 스크롤한다. 패널 높이는 콘텐츠와 기존 크기·비율 범위 안에서 줄인다.
- 일반 호출의 목록·숫자는 표시 동안 고정한다. 고정 오버레이는 유휴 상태에서 활성 앱/창·제목·메뉴·최근 순서를 갱신한다. 등록 프로필의 임시 선택과 실제 창 위치는 유지한다.
- 고정 패널의 데스크탑 이동 시 현재 데스크탑 색은 즉시 갱신하고, 최근 순서/크기/번호는 입력 중인 경우를 제외하고 활성 창에 맞춰 갱신한다.

## 앱별 메뉴

- R80–R82: 앱별 사전 선택 없이 모든 일반 앱의 **macOS 메뉴 막대(파일/편집/이동/도움말 등)**를 수집 대상으로 한다. R87에서 사용자가 전경 앱 한 개를 관찰하고 앱 전환 때 바꾸는 설계를 확정했다. 이 방식 자체를 기능 제약이나 미결정 사항으로 취급하지 않는다. 상태 막대 전용 앱/리본/우클릭 메뉴는 포함하지 않는다.
- 기본은 전체 수집 켜기이며 설정 → 메뉴에서 전체 끄기·앱별 중단을 제공한다. 메뉴 삭제는 재수집 제외 목록에도 넣고 숨긴 메뉴 다시 수집으로 복원한다. 직접 수동 추가하면 그 메뉴의 제외를 해제한다.
- 메뉴 항목 위의 마우스 release 또는 열린 메뉴/Help에서 Return·키패드 Enter 확정과 접근성 항목을 연결한다. Command/Control/Option 조합·Esc·키 반복·hover만 있는 경우는 기록하지 않는다. **복사·붙여넣기도 메뉴에서 선택했다면 수집하며, 기본 편집 명령 필터는 없다.**
- Help 검색 결과는 동일 앱의 실제 메뉴 경로가 하나로 확인될 때만 변환한다. 검색어/입력 문자를 읽어 저장하지 않으며, 이름이 중복되거나 조회가 불완전하면 추측하지 않고 건너뛴다.
- 자동 메뉴는 고정 해제 상태로 시작하고 관찰 횟수/시각을 갱신한다. 기존 경로의 수동 메뉴와 중복 생성하지 않으며 ID·핀·순서를 보존한다. 같은 입력의 중복 알림은 한 번만 기록한다.
- R83: 최근 메뉴는 앱별 최근 30일 이내 **또는** 고정하지 않은 사용 메뉴 중 최근 5개면 유지한다. 30일이 지나고 최근 5개 밖인 항목만 최근 목록에서 숨긴다. 고정 메뉴·기간 안의 자주 사용 메뉴·미사용 수동 등록은 유지한다. 설정에는 숨겨진 기록도 남겨 재고정/기간 확대가 가능하다. 초기 100개/500개 자동 삭제 제한은 제거한다. 대표적인 최근 문서/폴더·단축키 없는 최상위 Window 목록은 보수적으로 제외한다.
- R84: 시작 시 전경 앱, 실행/활성/종료/깨우기에서 관찰 연결을 확인한다. PID+프로세스 시작 시각을 구별하며 초기 읽기 실패는 0.25/0.75/2/5/15초 간격으로 제한 재시도한다. 앱 전환/중단/권한 상실은 예약 작업을 취소한다. 모든 앱에 메뉴 옵저버를 상시 붙이지 않는다.
- 앱별 접근성 알림·메뉴 구조·지연에 따라 누락될 수 있는 실험 기능이다. UI에는 조회 불가/클릭 확인 사용/관찰 대기/수집 결과를 구분한다. 앱이 제공하지 않는 정보나 최종 명령 성공은 추정하지 않는다.

- 설정에서 실행 중 앱의 메뉴를 요청해 읽고 선택 등록하거나, 정확한 계층 경로를 직접 등록한다. 전체 앱 메뉴를 주기적으로 스캔하지 않는다. 새 등록 메뉴는 고정 상태를 기본값으로 한다.
- 런처의 AXPress 요청 성공 횟수와 외부 메뉴 선택 관찰 횟수를 별도로 로컬 저장한다. 두 경로 모두 최근 시각과 기간 내 빈도에 반영한다. 외부 선택을 최종 작업 성공으로 설명하지 않는다.
- R89: 설정 → 메뉴의 모든 항목(고정·미고정·0회 포함)에 누적 합계/메뉴 막대/Tile Launcher 횟수를 표시한다. 오버레이 툴팁과 접근성 설명에도 제공한다. R90: 오버레이 메뉴 타일에는 오른쪽 위 핀 아래에 누적 합계만 `5회` 형식으로 항상 표시한다. 미고정/0회도 같은 위치에 표시하며 큰 숫자는 축약하고 정확한 횟수는 툴팁/설정에서 확인한다. 기존 카운터는 보존하고 누적 합계와 기간별 빈도를 구분한다. 자동 수집을 꺼도 런처 사용은 기록하며 실패/취소는 제외한다.
- R83: 자주 사용은 최근 90일 안의 런처 실행+관찰 선택 3회 이상이다. 설정 → 메뉴에서 최근/자주 사용 기간을 일 단위로 수정한다(기본 30/90일, 입력 1–36,500일). 고정·자주 사용 그룹은 수동 순서, 나머지는 최근 순서다. 메뉴별 최근 시각 3개만 저장하고 누적 횟수와 구별한다. 이전 기록은 실제로 아는 마지막 1회만 날짜 통계로 이전한다. 표시 대상/가로형 여부는 오버레이 스냅샷에 묶어 선택 도중 시간 경과로 재배치하지 않는다.
- 메뉴 실행은 선택 당시 표시된 앱/창 문맥으로 돌아가 정확한 현재 경로/활성/AXPress를 확인한다. 고정 중 문맥이 바뀌어도 캡처한 다른 앱으로 잘못 실행하지 않도록 앱 ID를 대조한다. 실패 안내·자동 재실행 없음, 실패는 빈도에 넣지 않는다.
- 백그라운드 직렬 큐와 AX 메시지 시간 제한·조회 깊이/노드 수/시간 제한을 둔다. 초기 조회는 최대 1,800노드/깊이 12/약 3초 경계에서 중단한다. AX 단일 응답 지연까지 포함한 엄밀한 3초 전체 보장은 아니다.
- 동적 메뉴·서드파티 앱의 AX 노출·언어/문서 상태에 따른 차이가 있으므로 실제 Excel 이미지 용량 줄이기 명령을 별도 검증한다. 일부 메뉴는 원래 앱에서 한 번 연 뒤 불러오기가 필요할 수 있다.

## 등록 항목·프로필·폴더

- R103 현재 제한: 배포한 ad-hoc 0.16.3에서 Team ID 조회 실패 및 실제 Focus 필터 연결 시간 초과를 확인했다(macOS 27.2 beta). 아래 기능은 구현 목표/코드 경로이며 해당 배포본의 실제 연동 성공을 뜻하지 않는다. 유효한 Apple 서명 후 재검증하며 그동안 수동 프로필 전환을 사용한다. 아이콘 파일/일반 AppKit 아이콘 로딩은 정상이다. 상세 근거는 focus-diagnostics.md에 있다.

- 앱·일반 폴더·다운로드·통합 휴지통을 수동 등록하고 순서를 바꾼다. 기존 목록/ID/이름/순서/폴더 방식은 ‘기본’ 프로필로 보존한다.
- 프로필별 등록 목록을 저장한다. **빈 프로필 추가**와 **현재 구성 복제**를 별도로 제공한다. 생성 즉시 새 프로필을 선택하며 공백 이름은 막는다. 선택·삭제를 제공하며 기본/마지막 프로필은 삭제하지 않는다. 수동 선택하면 자동 추종을 끈다.
- 집중 모드는 공개 SetFocusFilterIntent로 연결한다. 사용자가 macOS 집중 모드의 앱 필터에서 프로필을 지정하고 자동 추종을 켠 경우에만 따른다. 임의 집중 모드 이름 조회나 비공개 설정 읽기는 사용하지 않는다.
- 필터 없음/해제/삭제된 프로필 ID는 마지막 수동 구성으로 복귀하며, 그 구성도 없으면 첫 구성을 사용한다(R91). 앱 시작·깨우기와 명시적 자동 선택 때 현재 필터를 확인한다. 사용자 선택 시에만 표시 중 프로필을 바꾸고 자동 변경은 다음 호출에 반영한다.
- 일반 폴더는 항목별 ‘오버레이 탐색’/‘Finder 열기’. 탐색 시 하위 폴더·뒤로·새로고침·추가 날짜순/이름순·기본 연결 앱 실행. 추가 날짜가 없으면 생성일을 사용하며 재귀 색인·상시 폴더 감시는 하지 않는다.
- **휴지통은 Finder에서만 열기 가능**. 이유를 표시하며 다른 방식을 선택할 수 없다. Dock과 동일한 Finder 통합 trash 객체를 열고 로컬 ~/.Trash나 볼륨별 폴더로 대체하지 않는다. 외장 볼륨·되돌려 놓기·비우기는 Finder에 맡긴다. 전체 디스크 권한을 추가 요구하지 않는다.
- Dock에서 가져오기: Finder → 고정 앱 → 폴더 → 통합 휴지통 순서. 기존 중복 항목의 이름/방식 유지, Dock 밖 등록은 뒤에 보존. 비고정/최근 앱·최소화 창·웹 링크·개별 문서는 제외하고 건너뛴 수를 안내한다. Dock을 수정/재시작하지 않는다. 가져오기 시작 당시 프로필에 결과를 저장한다.

- 프로필 순서는 설정에서 변경·저장하며 헤더 목록과 순환이 같은 배열을 따른다. 키/휠 순환은 이번 표시만의 임시 선택으로 자동 추종이나 저장된 선택을 변경하지 않는다. 다음 호출은 기존 집중 모드/수동 설정으로 복귀한다. 위치·고정·앱 문맥·최근 창 순서를 유지하고 이전 실행 대기는 취소한다.

## 앱 수명·저장·기술 범위

- 로그인 자동 실행은 SMAppService.mainApp으로 사용자가 선택한다. 실제 상태·승인 대기·오류를 표시하고 사용자의 해제를 시작 시 임의로 되돌리지 않는다.
- 동일 사용자 한 인스턴스. 같은 버전/빌드는 기존 앱 유지, 다르면 정상 종료 후 가장 최근 실행 앱으로 전환하며 숫자의 대소는 따지지 않는다. 15초 시간 초과/종료 거부는 오류이며 강제 종료하지 않는다.
- 표시 버전·빌드·컴파일 결과 SHA-256을 시작 시 기록한다. 같은 경로 덮어쓰기/Finder 재열기/동시 실행/PID 재사용을 구별하며 잠금 파일을 지우지 않는다.
- Swift Package, AppKit NSPanel/NSGlassEffectView, SwiftUI, macOS 26 이상. 로컬 현재 아키텍처/ad-hoc 서명 개발 빌드이며 정식 OS·Intel·공증 배포 검증과 구별한다.
- 앱 출력은 동기화 폴더 밖 ~/Library/Developer/TileLauncher/build. 현재 Xcode beta를 프로젝트별 DEVELOPER_DIR로 지정하며 전역 개발 도구 설정은 바꾸지 않는다.
- 앱·창 관찰과 아이콘 캐시를 재사용한다. 썸네일·입력 문자/Help 검색어 저장·메뉴 전체 주기 조회는 없다. 메뉴 자동 수집은 현재 앱의 입력/접근성 이벤트 중심이며, 창 이력은 세션 메모리, 설정·프로필·등록 메뉴/횟수는 로컬 UserDefaults다.
- 모든 사용자 요청을 Markdown에 기록한다. 테스트/컴파일/패키징 성공을 실제 창 전환·Focus 연동·Liquid Glass·성능 검증과 혼동하지 않는다.
- Space 소속/선택 이동과 AX 창 ID 연결은 DesktopWindows.swift의 선택적 macOS 내부 함수로 보완한다. 공개 API 계약이 아니므로 App Store 지원을 전제하지 않으며 OS 업그레이드마다 확인한다. 함수/정보가 없으면 현재 여부를 추측하지 않고 공개 정보로 축소한다. 화면 녹화 권한은 추가 요구하지 않는다.

## R93–R95 · 배포 준비

- 실행 중인 개발 앱을 덮어쓰지 않고 깨끗한 Git 커밋의 소스를 독립 디렉터리에서 빌드한다. 로컬 수정으로 만든 리허설은 local_only로 기록하고 업로드하지 않는다.
- ZIP을 다시 풀어 코드 서명, 파일/실행 권한, 아이콘, Focus 메타데이터, 번들 ID/버전/빌드/소스 커밋을 검사한다. ZIP·공개 메타데이터에 SHA-256 체크섬을 제공한다.
- 현재 ad-hoc 결과는 미공증으로 명시한다. GitHub 초안/게시 단계는 이 상태를 명시적으로 선택한 --allow-unnotarized를 요구한다. 상태 안내는 자동 생성하며 서명되지 않은 파일을 공증 완료라고 설명하지 않는다.
- 나중의 Developer ID 서명은 강화된 런타임·타임스탬프·필요한 Apple Events 권한을 사용한다. 개인 키/암호를 저장소에 넣지 않고 공증 인증은 Keychain profile, GitHub 인증은 gh의 로그인을 사용한다.
- 공증은 제출 ID를 기록해 조회/재개하고 결과가 불명확하면 중복 제출하지 않는다. Accepted 후 티켓 첨부·Gatekeeper·최종 ZIP을 확인한다.
- GitHub는 지정 저장소/소스 커밋/태그/파일 해시/릴리스 설명이 일치하는 초안만 게시한다. 기존 릴리스 덮어쓰기나 저장소 공개 범위 자동 변경은 하지 않는다. 사용자가 선택한 정식 릴리스 상태를 유지한다.

## R96–R98 · 모서리·패치 버전

- 외곽의 유리 효과/배경/콘텐츠를 같은 연속 곡선 마스크로 잘라 모서리 바깥에 선이나 사각 배경이 남지 않게 한다. 기존 테마·타일 곡률·불투명도·배치·드래그 영역은 유지한다.
- 당시 R98의 실제 전달본은 0.2.1(5)이다. 이후 규칙은 R99–R100이 대체한다. 과거 실제 번호는 고치지 않는다.
- release/config.json만 버전의 원본으로 사용하고 개발/배포 빌드가 이를 번들에 넣는다. 설정에는 실행 중인 프로세스의 번들 버전·빌드를 표시한다.
- GitHub 바이너리 태그/업로드/게시는 보류한다. 이전 0.2.0 ZIP에 이번 패치가 들어 있다고 설명하거나 게시하지 않는다.

## R99–R101 · 버전 정책·UI 보완·시스템 메뉴 제외

- CHANGELOG.md의 소급 분류 및 R104–R108 기능 추가·기본값 보정 후 현재 공개본은 Developer ID 서명·공증 완료 1.1.5(20), 로컬 설치본은 색상 예시 정렬 1.1.5(20) 서명·공증 완료다. 1.1.5 이후 다음 UI/버그 수정은 1.1.6, 기능 추가/변경은 1.2.0으로 분류한다. 색·아이콘·간격·배치·hover는 UI 수정이며 새 설정·단축키·자동 동작·통계는 기능 추가다.
- Developer ID Application 서명 완료를 검증한 첫 빌드는 1.0.0이다. 가입/인증서 생성/ad-hoc 서명은 해당하지 않고 공증은 별도로 기록한다. 내부 후보·권한·시안/문서/도구만의 변경은 앱 단계에서 제외하며 과거 실제 버전·해시·Git 이력은 보존한다.
- 메뉴/최근 창은 hover 채움+2pt 테두리로 강조한다. 글자 위에 색을 덮지 않고 등록 타일은 유지한다.
- Apple 메뉴 전체와 하위 항목은 클릭·키보드·Help 경로에서 자동 수집하지 않는다. 이름이 같은 앱 고유 명령과 메뉴에서 선택한 복사/붙여넣기는 수집한다. 기존 자동 항목은 최근·자주에서 숨기고 최근 5개에도 포함하지 않는다. 데이터·직접 고정·수동 등록은 보존한다.
- 사용자 피드백은 모서리 선의 완전 해소가 아니라 좌우 잔존이다. 유리 효과를 1pt 바깥으로 확장해 선을 마스크 밖으로 보낸다. 콘텐츠 크기·타일 불투명도는 유지하고 배경 색 레이어는 0.72→0.28, 투명도 줄이기는 1을 유지한다. 실제 Glass 굴절·WindowServer 그림자는 별도 확인한다.

## R102 · GitHub 정식 릴리스 게시 재개

- 사용자가 현재 앱을 그대로 GitHub에 릴리스하라고 요청했다. R96의 보류를 해제하고 0.16.3(6)을 개발용 ad-hoc 서명·미공증 상태로 정식(prerelease=false) 게시한다.
- 깨끗한 현재 커밋에서 ZIP·공개 메타데이터·SHA256SUMS를 새로 만들고 초안 업로드 파일을 다시 내려받아 해시를 확인한 뒤 공개한다. 이전 0.2.0 ZIP은 사용하지 않는다.
- 기능 변경은 없으므로 앱 버전·빌드는 유지한다. Developer ID 서명/공증이나 별도 배포 채널을 완료/승인한 것으로 확대하지 않는다.

- R102 완료: https://github.com/colaH16/tile-launcher/releases/tag/v0.16.3 에 정식/최신 릴리스 공개. 업로드 3개 파일의 재다운로드 해시 일치와 draft=false/prerelease=false를 확인했다. 이후 업데이트는 새 버전으로 준비하며 공개 자산을 덮어쓰지 않는다.
