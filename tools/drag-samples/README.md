# A/B 드래그 샘플

Tile Launcher와 독립된 AppKit 샘플 앱입니다. 제품 설정/캐시/앱 실행은 건드리지 않으며 제품의 SwiftUI 타일을 그대로 이식한 것은 아닙니다. 같은 단순 레이아웃에서 기본 배경 이동과 입력 기능의 공존을 비교합니다.

- A: 타일·설정·핀·빈 여백을 포함한 샘플 창 전체에서 기본 창 이동 허용.
- B: 메뉴·세션·등록 앱의 세 직사각형 전체에서 이동 금지. 직사각형 안 타일 사이 여백도 금지. 위/아래/좌/우/두 상단 섹션 사이/등록 앱과의 사이에서는 이동 허용. 설정/핀은 세 직사각형 밖에 있어 A처럼 클릭과 이동을 함께 시험합니다.

두 모드 모두 클릭은 누르고 놓을 때, 길게 누르기는 약0.55초 유지했을 때 표시됩니다. 우클릭은 샘플 메뉴를 엽니다. 핀 클릭은 샘플의 ON/OFF 표시만 바꿉니다. 실제 앱을 실행하거나 Tile Launcher 설정을 바꾸지 않습니다. 바탕 클릭도 결과를 표시합니다.

시작점에서6pt 이상 커서가 이동했거나 실제 창 이동 알림이 오면 클릭/아직 발생하지 않은 길게 누르기를 취소합니다. 이6pt는 앱 입력 분류용이며 macOS 기본 창 이동의 자체 문턱값을 바꾸는 설정은 아닙니다. 길게 누르기 뒤 놓아도 클릭은 중복 실행하지 않습니다. 길게 누른 뒤 계속 끄는 경우까지 어떤 UX를 쓸지는 제품 적용 때 별도 결정할 수 있습니다.

기본 배경 API와 mouseDownCanMoveWindow를 사용합니다. performDrag/WindowDragGesture/수동 setFrame 드래그/전역 이벤트 감시/AX/사설 API를 사용하지 않습니다. 생성 시 초기 배치 외에는 창 좌표를 앱이 갱신하지 않습니다. 단색 타일/배경이며 블러·유리 효과·이동 중 반복 UI 갱신은 없습니다. 로그용 실제 이동 알림은 최대10Hz로 샘플링하며 파일 쓰기는 백그라운드 큐에서 합니다. 입력이 없을 때 폴링하지 않고 길게 누르기는 누르는 동안 단발 타이머 하나로 처리합니다.

## 실행

1. ZIP 압축을 풀고 `Tile Launcher Drag Samples.app`을 실행합니다. 터미널 명령/플래그는 필요 없습니다.
2. 작은 선택 창의 A/B 버튼으로 모드를 바꿉니다. 큰 샘플 창에서 타일/설정/핀/빈 여백을 시험합니다.
3. 클릭, 짧은 손떨림 뒤 클릭, 길게 유지, 우클릭, 드래그를 비교합니다. 큰 창 아래에 인식 결과와 카운터가 표시됩니다.
4. B에서는 주황 테두리 세 영역 안/밖과 각 섹션 사이를 구분해 시험합니다.
5. 끝나면 작은 창의 ‘종료 · 로그 저장’ 또는 ⌘Q를 누릅니다. 작은 창을 닫아도 종료합니다. 자동 종료는 없습니다.

앱 메뉴의 ‘로그 폴더 열기’(⌘L)로 JSONL 위치를 열 수 있습니다. 기본 경로는 `~/Library/Logs/TileLauncherDragSamples/`이며 실행마다 고유 파일 하나, 최대5MiB입니다. 다른 앱 입력/제목/대화/화면은 수집하지 않습니다. 클릭 수와 실제 창 이동 알림을 구분하며 생성 시 위치 변경을 드래그 성공으로 보지 마세요.

샘플 앱 ID는 dev.cola16.TileLauncher.DragSamples로 제품과 다릅니다. 기존 Tile Launcher를 덮어쓰지 않으며 별도 실행입니다. 공증·정식 릴리스·로그인 등록·설치 변경을 하지 않습니다.

## 개발과 검증

Xcode 도구를 선택한 환경에서:

```sh
bash tools/drag-samples/build.sh /tmp/tile-drag-samples-local
'/tmp/tile-drag-samples-local/Tile Launcher Drag Samples.app/Contents/MacOS/DragSamples' --self-test
'/tmp/tile-drag-samples-local/Tile Launcher Drag Samples.app/Contents/MacOS/DragSamples' --self-test-native
```

첫 검사는 세 크기의 영역 정책/클릭·이동 분류를 검사합니다. 두 번째는 창을 표시하지 않고 AppKit 뷰/클릭 중복 취소/실제 단발 타이머/종료 시 입력 해제/우클릭 동작/핀 토글을 가상 이벤트로 검사합니다. 물리 마우스의 기본 창 이동 성공이나 WindowServer 동작을 검증하지 않습니다.

`--render OUTPUT_DIRECTORY`는 A/B 레이아웃 PNG만 만듭니다. 그리기 검증이며 물리 입력 시험이 아닙니다. 기본 빌드는 ad-hoc 서명이고 전달본의 Developer ID 서명 여부는 동봉 build.json을 확인하세요.
