# v4.1 · 타일 드래그 거리 조절

이전 샘플을 종료하고 **Tile Launcher Drag Threshold.app**을 실행하세요. **F 모드**로 시작하며 기본값은 **9px**입니다. 작은 선택 창의 숫자를 바꾸고 **적용**하거나 Enter를 누르면 다음 누르기부터 적용됩니다. 0~200px, 소수 입력도 가능합니다. 앱을 다시 실행하면 9px로 돌아갑니다.

- **타일·설정·핀에서 누르기:** 누른 지점에서 직선 거리로 지정한 픽셀만큼 움직이기 전에는 창이 움직이지 않습니다. 처음 누른 타일 안에서 놓으면 클릭입니다.
- **지정 거리 도달:** 클릭/아직 실행되지 않은 길게 누르기를 취소하고 창 이동 모드로 들어갑니다. 처음 누른 지점부터의 이동량 전체를 즉시 반영해, 타일에서 처음 잡은 지점이 커서 아래에 유지됩니다. 문턱까지의 거리를 빼지 않습니다. 따라서 문턱을 넘는 순간 그때까지의 거리만큼 창이 따라잡습니다. 되돌아와도 클릭으로 바뀌지 않습니다.
- **타일 밖에서 누르기:** 섹션 내부 빈자리·타일 사이·바깥 배경은 별도 문턱을 추가하지 않고 macOS 기본 배경 이동을 사용합니다. macOS 자체의 입력 인식까지 0픽셀로 강제하는 것은 아닙니다.
- **D/E/A:** 이전 방식과 비교하는 대조 모드입니다. 숫자 변경은 F에만 적용됩니다. F는 설정/핀에도 같은 문턱을 적용합니다.

단위는 물리 화면 픽셀입니다. 시작 화면의 backingScaleFactor를 누를 때 고정해 환산합니다. 2배율 Retina의9px는4.5pt입니다. 거리 역시 누를 때 고정하므로 이미 누른 상태에서 설정을 바꿔도 현재 입력에는 영향을 주지 않습니다.

## 확인 순서

1. F에서9px로 타일 클릭/약한 손떨림/드래그를 비교합니다.
2. 8,12,16px 등으로 바꾸고 적용해 편한 값을 찾습니다.
3. 타일을 끈 뒤 배경에서도 계속 이동하는지 확인합니다.
4. 길게 누르기/우클릭과 설정/핀을 확인합니다. 길게 누르기는0.55초이며, 기존6pt 이동 취소와 F 문턱 도달 취소가 적용됩니다. 실제 앱 실행/제품 설정 변경은 없습니다.

**종료 · 로그 저장** 또는 선택 창 닫기로 종료합니다. 앱 메뉴의 **로그 폴더 열기(⌘L)**로 로그를 찾습니다. 경로는 `~/Library/Logs/TileLauncherDragThresholdSamples/drag-threshold-UUID.jsonl`입니다. 최대5MiB이며 threshold.changed/threshold.crossed, 픽셀 거리와 배율, 클릭/이동 결과를 기록합니다. 다른 앱 입력을 수집하지 않습니다.

## 구현과 한계

창의 이동 가능 플래그를 입력 중 껐다 켜지 않습니다. F의 타일은 자식 뷰로 기본 창 이동을 차단하고, 문턱 이후 앱 로컬 마우스 이동 이벤트마다 setFrameOrigin으로 창 좌표를 갱신합니다. 배경은 기존 macOS 기본 이동입니다. 타일 이동은 WindowServer가 직접 시작하는 드래그가 아니므로 화면 가장자리/Spaces/시스템 창 배치 동작이 다를 수 있습니다. 실제 체감과 물리 입력은 사용자 시험 대상입니다.

문턱 전/정확히 도달/되돌아오기/손 놓기와1·2배율 계산, 화면 밖 AppKit의 문턱 전 클릭 유지/문턱 후 창 좌표 변화/원래 잡은 지점과 커서의 일치/클릭 취소를 검사했습니다. 가상 검사가 실제 마우스 성공이나 성능/FPS를 입증하지는 않습니다. 기존 시험본과 제품은 보존했습니다. Developer ID 서명·미공증 독립 시험본입니다.
