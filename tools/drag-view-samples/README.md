# v3.1 · 타일과 배경 뷰 분리·클릭 유지 시험

기존 A/B/C 샘플을 종료한 뒤 **Tile Launcher Drag Views.app**을 실행하세요. 터미널 명령은 필요 없습니다. 처음에는 **D**로 시작합니다. 기존 제품 앱과 이전 샘플은 교체하지 않습니다.

- **D**: 타일·설정·핀을 각각 이동 금지 자식 뷰로 분리합니다. 섹션 내부 빈자리와 타일 사이를 포함한 배경은 이동을 허용합니다.
- **A**: 자식 뷰 없이 전체 이동을 허용하는 대조 모드입니다. 6pt는 클릭 취소 기준이며 창 이동 시작 문턱이 아닙니다.
- **E**: 이전 B와 같은 세 섹션 전체를 자식 뷰로 막습니다. 섹션 내부 빈자리도 금지입니다. 설정/핀은 섹션 밖이므로 이동 허용입니다.

창의 `isMovable`과 `isMovableByWindowBackground`는 생성 때만 true로 설정하고, 입력·모드 전환 중에는 변경하지 않습니다. 배경 뷰의 `mouseDownCanMoveWindow`는 항상 true, 자식 뷰는 항상 false입니다. 자식 뷰는 왼쪽 누르기/끌기 이벤트를 상위로 전달하지 않습니다. 클릭·길게 누르기·우클릭은 기존 앱 로컬 입력 처리로 유지합니다. performDrag, WindowDragGesture, 수동 창 좌표 드래그, 접근성/전역 입력 감시는 없습니다.

v3.1에서는 **이동 금지 타일/버튼은 6pt 이상 움직여도 처음 누른 타일/버튼 안에서 놓으면 클릭**합니다. 밖에서 놓으면 취소합니다. 실제 창이 움직였거나 길게 누르기가 이미 실행됐다면 클릭을 중복 실행하지 않습니다. 6pt 이상 움직이면 길게 누르기는 취소되며, 손을 놓을 때의 클릭과는 구별합니다. A와 이동 허용 배경의 드래그 정책은 그대로입니다.

## 시험 순서

1. **D**에서 배경을 3번 끌어 창이 움직이는지 확인합니다.
2. 타일을 3번 끕니다. 창이 움직이지 않아야 합니다.
3. 다시 배경·섹션 내부 빈자리·타일 사이를 끕니다. 계속 움직여야 합니다.
4. 타일 클릭, 길게 누르기(0.55초), 우클릭과 설정/핀을 확인합니다. 더미 동작 결과만 표시하며 실제 앱을 실행하지 않습니다.
5. D에서 배경이 막히면 **A로 바꾼 뒤 실제로 배경을 끌어** 회복 여부를 확인합니다. 필요하면 앱을 완전히 종료하고 D부터 다시 시험합니다.
6. E에서도 ‘바깥 배경 이동 → 섹션 안 끌기 → 바깥 배경 이동’을 비교할 수 있습니다.

끝나면 작은 선택 창의 **종료 · 로그 저장**을 누르세요. 작은 창을 닫거나 앱이 활성 상태일 때 ⌘Q로도 종료됩니다. 자동 종료는 없습니다.

로그는 앱 메뉴의 **로그 폴더 열기(⌘L)**로 찾습니다. 경로는 `~/Library/Logs/TileLauncherDragViewSamples/drag-views-UUID.jsonl`이며 실행마다 파일 하나, 최대5MiB입니다. 이전 샘플의 로그 폴더와 다릅니다. 실제 입력 대상 뷰, 이동 허용 판정, 창 이동 속성·좌표와 동작 결과를 기록합니다. 다른 앱의 화면/입력은 수집하지 않습니다.

## 검증 범위

영역 계산, 화면 밖 AppKit hitTest, 반복 타일 입력 뒤 창 속성/배경 hitTest 유지, 클릭·길게 누르기·우클릭 처리, 서명을 검사했습니다. 이 검사는 실제 WindowServer의 물리 마우스 이동 검증을 대신하지 않습니다. 이전의 ‘금지 영역에서 한 번 움직인 뒤 배경도 막힘’이 해결됐는지는 사용자 시험으로 확인해야 합니다.
