# Tile Launcher

A native macOS tile launcher with Liquid Glass. Hold Option to switch windows, launch apps, and browse folders.

Option을 누르면 커서 근처에 열리는 macOS 네이티브 런처. 최근 앱과 개별 창을 따로 보여주며, 앱·폴더를 직접 등록합니다. SwiftUI와 AppKit의 Liquid Glass를 사용합니다.

개인용 **0.1 개발 버전**입니다. 실제 외관과 입력 동작을 검증하는 첫 빌드이며, App Store·Homebrew 배포와 Sites 게시를 진행한 상태가 아닙니다.

## 빌드와 실행

- macOS 26 이상. 현재 검증 대상은 Apple Silicon / macOS 27.2 베타입니다.
- Swift 6 이상과 해당 macOS SDK. 단위 테스트는 XCTest가 포함된 전체 Xcode를 사용합니다.
- 외부 패키지 의존성 없음. 로컬 빌드는 ad-hoc 서명하며 공증된 배포 앱이 아닙니다.

```sh
./scripts/build.sh
open "$HOME/Library/Developer/TileLauncher/build/Tile Launcher.app"
./scripts/test.sh
```

Xcode가 별도 위치에 있으면 `DEVELOPER_DIR`를 해당 Xcode의 `Contents/Developer`로 지정합니다. 전역 `xcode-select`를 변경할 필요는 없습니다.

```sh
DEVELOPER_DIR="/Applications/Develop/Xcode-beta.app/Contents/Developer" ./scripts/build.sh
DEVELOPER_DIR="/Applications/Develop/Xcode-beta.app/Contents/Developer" ./scripts/test.sh
```

기본 앱 출력 경로는 `~/Library/Developer/TileLauncher/build`입니다. Desktop/iCloud 등의 동기화 폴더가 `.app`에 메타데이터를 덧붙여 서명을 깨뜨리는 것을 피합니다. `TILE_LAUNCHER_OUTPUT_DIR` 환경 변수로 출력 위치를 바꿀 수 있습니다.

`Package.swift`를 Xcode에서 열어 소스를 편집할 수 있습니다. 권한 검증과 실제 사용에는 위 스크립트가 만든 같은 경로의 `.app`을 사용하세요. 개발용 서명/앱 경로가 바뀌면 macOS 접근성 권한 재등록이 필요할 수 있습니다.

## 사용

1. 실행하면 메뉴 막대에 격자 아이콘이 생깁니다. ‘설정’에서 앱·폴더·다운로드·휴지통을 등록합니다. 화살표 또는 목록 이동으로 순서를 바꿉니다.
2. ‘접근성 권한 요청’을 누르고 시스템 설정에서 Tile Launcher를 허용합니다. 시스템 입력 감지와 다른 앱의 창 조회/전환에 사용합니다. 앱이 권한을 자동으로 허용하지 않습니다.
3. 좌/우 Option만 0.25초 누르면 패널이 열립니다. 항목을 클릭하고 Option을 놓으면 실행합니다. 선택하지 않고 놓으면 닫힙니다. 메뉴 막대의 ‘열기’로는 키를 누르지 않고 사용할 수 있습니다.
4. 일반 폴더는 설정의 각 항목에서 ‘오버레이에서 탐색’ 또는 ‘Finder에서 열기’를 선택합니다. 오버레이에서는 하위 폴더·뒤로 가기·정렬·파일 실행을 제공합니다. **휴지통은 Finder에서 열기만 가능**하며 선택 메뉴 대신 이유를 표시합니다.
5. 최근 창은 행 우선·두 줄이며, 설정에서 자동 개수 또는 6 이상의 수동 개수를 선택합니다. 넘치는 항목은 최근 창 영역만 세로로 스크롤합니다.
6. 설정 → 시작 → ‘로그인 시 자동 실행’을 켜면 macOS 로그인 항목으로 등록합니다. 시스템 승인이 필요한 경우 안내 버튼으로 로그인 항목 설정을 엽니다. 끄면 등록을 해제합니다.
7. 오버레이 **왼쪽 위 핀** 또는 **`⌥X`**로 고정하면 같은 자리가 닫기 `×`로 바뀝니다. Option을 놓거나 다른 창을 클릭해도 유지되며 `×`·Esc·`⌘W`로 닫습니다. 닫은 후 다시 열면 고정은 해제되어 있습니다. 고정한 채 앱/파일을 선택해도 창은 유지하고, 설정을 열거나 디스플레이 구성이 바뀌면 닫습니다.
8. 설정 → 등록 앱·폴더 → **Dock에서 가져오기**로 고정된 앱·폴더를 순서대로 등록합니다. Finder는 맨 앞, 휴지통은 Dock 항목 맨 뒤에 포함합니다. 중복 항목은 기존 이름·여는 방식을 유지하며 Dock 순서로 앞에 놓고, 그 밖의 기존 항목은 뒤에 남깁니다. 새 폴더는 오버레이 방식입니다.

스크린샷은 고정 후 Option을 놓고 `⌘⇧5`를 눌러 찍습니다. [macOS 스크린샷 도구](https://support.apple.com/ko-kr/guide/mac-help/-mh26782/mac)를 사용하므로 Xcode가 필요하지 않습니다.

앱 창이 키 입력을 받는 동안에는 `⌘W`로 닫기, `⌘,`로 설정 열기, `⌘H`로 가리기, `⌘Q`로 종료할 수 있습니다. 다른 앱에 포커스가 있으면 그 앱의 단축키로 동작합니다.

Option으로 오버레이가 열린 뒤에는 Command를 추가로 눌러도 닫히지 않습니다. **Option을 계속 누른 채 `⌘,`**로 바로 설정을 열거나, **X**로 고정할 수 있습니다. 이 단축키는 오버레이가 키 입력을 받을 때만 처리합니다. 패널이 열리기 전의 Option 조합은 기존 앱에서 그대로 사용합니다.

동일 사용자에게서는 한 인스턴스만 실행합니다. **같은 버전·빌드면 기존 앱을 유지하고 새 프로세스가 종료**하며, **다르면 기존 앱이 정상 종료된 뒤 방금 실행한 앱으로 교체**합니다. 숫자가 낮은 버전을 나중에 실행해도 같은 규칙입니다. 표시 버전·빌드 번호·컴파일 결과 식별값을 비교하므로 버전 번호를 올리지 않은 로컬 재빌드도 구별합니다. 동일한 컴파일 결과를 다시 포장한 앱은 같은 빌드로 취급합니다.

실행 중인 앱의 버전은 시작할 때 기록하므로 같은 경로에 새 빌드를 덮어써도 비교가 유지됩니다. Finder가 기존 프로세스에 ‘다시 열기’만 전달하면 디스크의 새 빌드를 별도로 시작해 교체합니다. 종료가 거부되거나 15초 안에 완료되지 않으면 오류를 표시하고 중복 실행하지 않습니다. 버전 기록이 없는 이전 개발 빌드는 버전을 추정하지 않고 정상 종료 후 교체합니다.

입력 문자를 저장하지 않으며 창 이력은 실행 중 메모리에만 유지합니다. 앱 시작 전의 사용 순서를 복원하지 않습니다. 등록 항목과 표시 설정은 이 앱의 UserDefaults에 로컬 저장합니다.

## 첫 버전의 범위와 제한

- 최근 창은 접근성 API가 제공하는 **OS 창**입니다. 같은 앱의 여러 창은 분리하지만 iTerm의 탭·분할은 각각의 창으로 만들지 않습니다.
- 최근 앱은 실행 중인 앱을 중복 제거하여 최대 3개, 최근 창은 현재 창을 포함합니다. 패널을 연 동안 순서는 고정하고 재호출 시 갱신합니다.
- 접근성 정보를 제공하지 않는 앱, 다른 Space·전체 화면·최소화 창의 동작은 실제 앱별 검증이 필요합니다. 조회는 백그라운드에서 시간 제한을 두고 수행합니다.
- 일반 폴더의 오버레이 탐색 권한은 macOS 설정에 따릅니다. 휴지통 타일은 **Dock과 같은 Finder 통합 휴지통**을 엽니다. 개별 볼륨의 `~/.Trash` 경로를 열거나 내용을 직접 읽지 않습니다. 외장 저장소의 휴지통 관리와 ‘되돌려 놓기’도 Finder에서 이용합니다. Tile Launcher에는 휴지통 탐색·파일 열기·복원·비우기를 구현하지 않습니다.
- 기존 등록 목록과 순서는 유지합니다. 여는 방식이 저장되지 않은 일반 폴더는 오버레이를 유지하며, 기존 휴지통은 Finder 전용으로 전환합니다. 자동 실행 상태는 macOS에서 읽으며 앱 시작 시 임의로 켜지 않습니다.
- 추가 날짜 메타데이터가 없는 파일은 생성일을 사용합니다. 폴더는 열거나 새로고침할 때 조회하고 백그라운드 감시·재귀 색인은 하지 않습니다.
- Dock 가져오기는 버튼을 누를 때만 수행합니다. 실행 중인 비고정 앱·최근 앱·최소화 창·웹 링크·개별 문서는 제외합니다. 사용할 수 없거나 지원하지 않는 항목은 건너뛴 개수를 안내합니다. Dock의 저장 형식은 공개 API 계약이 아니므로 OS 업그레이드 때 재검증하며, Dock 설정을 변경하거나 Dock을 종료하지 않습니다.
- 앱별 고정 메뉴와 메뉴 순서 편집, 집중 모드 연동은 **다음 단계**입니다. 현재 메뉴 영역은 준비 상태로 표시합니다.
- 정상 패널 760–1,040 × 620–720pt, 목표 비율 5:4, 허용 1.2–1.5, 화면 여백 24pt. 작은 작업 영역은 간격·배치를 줄이며 512×420pt 패널을 담을 수 없는 화면은 지원 안내를 표시합니다.
- 전역 키 감지는 원래 앱의 입력을 차단하지 않습니다. 오버레이가 열리면 비활성화 패널이 키 입력을 받고 `⌥X`·`⌘,`·`⌘W`·Esc를 로컬에서 처리합니다. 다른 앱에 포커스를 옮긴 경우 단축키는 해당 앱에 전달되며, 전역에서 감지한 Escape는 고정 패널도 닫을 수 있습니다.
