# Tile Launcher

A native macOS tile launcher with Liquid Glass. Hold Option to switch windows, launch apps, and browse folders.

Option을 누르면 커서 근처에 열리는 macOS 네이티브 런처. 앱별 메뉴와 모든 앱의 최근 창을 나란히 보여주며, 아래에 앱·폴더를 작은 정사각 타일로 등록합니다. SwiftUI와 AppKit의 Liquid Glass를 사용합니다.

**[1.9.3 정식 릴리스](https://github.com/colaH16/tile-launcher/releases/tag/v1.9.3)**를 공개했습니다. Apple Silicon · macOS 26 이상이며 **Developer ID 서명·Apple 공증 완료**입니다. [ZIP 다운로드](https://github.com/colaH16/tile-launcher/releases/download/v1.9.3/Tile-Launcher-1.9.3-arm64.zip) · [설치 안내](docs/installation.md). 이전 0.x 릴리스는 개발용 ad-hoc 서명·미공증이며 기존 자산을 보존합니다.

GitHub 정식 릴리스 구분과 Apple 개발자 서명·공증 상태는 별개입니다. 버그·UI 수정은 패치, 기능 추가·변경은 마이너로 올립니다. Developer ID 서명 완료 첫 빌드는 **1.0.0**입니다. 설정 → 일반에서 실제 실행 버전을 확인할 수 있습니다. 개발용/배포용 버전은 `release/config.json`에서 함께 관리합니다.

시험용 **1.8.1(36)**까지 Developer ID 서명·미공증 ZIP을 전달했습니다. Handoff 타일과 색 설정, Option 유지/고정 모드의 공통 갱신 규칙이 포함됩니다. 정식 공개본과 개발 Mac 설치본은 **1.9.3(42)**입니다.

메뉴 추가 시 앱 리소스에서 아이콘을 저장하고, 지원되는 정적 메뉴에는 언어별 경로를 연결합니다. SF Symbol 코드·PDF 벡터를 보존하며 비트맵만 원래 해상도로 저장합니다. 앱 업데이트 때 아이콘을 자동 갱신하지 않고 **설정 → 메뉴 → 메뉴 아이콘 새로고침**으로 다시 가져옵니다. 모든 앱의 동적 메뉴/불확실한 연결까지 자동으로 처리하는 것은 아닙니다.

시험용 **1.5.0(28)**은 설정 → 메뉴에서 메뉴마다 오버레이 타일 아이콘을 SF Symbol로 지정합니다. 1.5.1(29)부터 New Tab·New Folder·New Window·Get Info 등 자주 쓰는 메뉴는 기본 아이콘을 씁니다. 아이콘이 없으면 단축키, 둘 다 없으면 메뉴 이름을 크게 보여줍니다. 응답하지 않는 앱 때문에 창 선택이 밀리던 경로를 줄이고, 창 목록 조회·메뉴 수집·스크롤·Option 호출을 가볍게 했습니다. Developer ID 서명·미공증 ZIP으로 전달합니다.

정식 **1.4.3(27)**은 타일과 내부 글자/아이콘만 최대 **1.4배**로 표시합니다. 확정한 바깥24pt·상단52pt·기본32pt 버튼과 제목, 타일 사이 간격은 함께 커지지 않습니다. 상단은 앱 아이콘·앱 이름 — 창 이름 한 줄이고 하단 안내 아래 여백은8pt입니다. 메뉴와 최근 창 중 더 긴 목록이1/2/3줄이면 그 높이,4줄 이상이면3.3줄로 맞추고 등록 목록과 작은 화면의 높이를 배분합니다. 타일 의미·색·개별 창 순서와 기존 실행 기능은 유지합니다. Developer ID 서명·Apple 공증을 완료한 ZIP을 GitHub Releases에서 받을 수 있습니다. 자세한 변경은 [CHANGELOG](CHANGELOG.md)에 있습니다.

현재 공개본은 **1.9.3(42)**입니다. 초기 설정 창의 폭은 580pt, 높이는 일반 탭의 실제 내용에 맞춰 정합니다. 메뉴 목록은 남은 공간을 모두 쓰며 ‘메뉴 추가…’는 하단에 고정합니다. 설정 아이콘·메뉴 +·등록 +는 각각 일반·현재 앱 메뉴 추가·등록 항목/프로필 화면을 엽니다. R123에서 네 탭의 공통 상단/일반 버전 간격과 오버레이 여백을 정리하고 Developer ID 서명·Apple 공증·티켓·Gatekeeper 및 업로드 후 재다운로드 검증을 거쳐 공개했습니다.

이전 서명·공증 완료 공개본 **1.1.5(20)**은 실제 창을 다른 앱 2×2/같은 앱 연속 1×1로 표시하고 작은 타일 두 개를 세로로 쌓습니다. 창 없는 앱은 회색/앱 이름, 작은 실제 창은 창 이름으로 구별합니다. 1.1.0에서 추가한 프로필별 높이·최근 창 바로 아래의 등록 영역·창 없는 앱의 우클릭 정상 종료도 포함합니다. UI 패치 1.1.2(17)에서 메뉴를 고정 강조 4×2/자주 파스텔 2×2/최근 회색 2×2로 정리합니다. 버그 패치 1.1.3(18)는 닫힌 보조 창의 중복 표시를 수정합니다. Developer의 닫힌 설정 표면을 제외하고 창 없는 앱을 회색 타일 하나로 표시하며, 실제 최소화·다른 데스크탑 창은 보존합니다. 1.0.0 이후 1.1.0–1.1.3의 변경은 1.1.3 노트에, 이후 1.1.4–1.1.5의 모든 변경은 최신 릴리스 노트에 담았습니다.

로컬 UI 패치 1.1.4(19)는 모양 설정의 최근 창 예시를 회색 1×1/연한색 2×2/진한색 2×2 순으로 맞추고 등록 앱은 진하게, 폴더는 파스텔로 구분합니다. 실제 오버레이 배치는 유지합니다.

로컬 UI 패치 1.1.5(20)는 작은 회색 예시의 자리 폭을 다른 행과 맞춰 세 섹션의 예시 시작선을 정렬합니다.

서명·공증 완료 로컬 설치본 **1.2.0(21)**은 앱별로 창을 묶고 활성 앱 그룹을 앞에 둡니다. 활성 앱의 보이는 대표 창 하나만 4×2, 나머지 보이는 창은 2×2, 다른 데스크탑 창은 1×1입니다. 모든 모니터의 보이는 데스크탑 기준 색과 숫자 단축키를 유지합니다. 기존 실행 인스턴스는 보존하며 다음 재열기에서 전환합니다. 아직 GitHub 바이너리는 공개하지 않았습니다. R148의 데스크탑별 두 열은 별도 비교 시안입니다.

**Focus:** 이전 ad-hoc 0.16.3의 Team ID 조회 실패는 [진단 기록](docs/focus-diagnostics.md)에 남겨 두었습니다. Developer ID 서명·공증 1.0.0 이후 사용자가 시스템 필터의 프로필 선택 화면이 정상 로딩된다고 확인했습니다. 캐시 아이콘과 모든 전환/해제 조합의 검증은 구별합니다.

- macOS 26 이상. 현재 검증 대상은 Apple Silicon / macOS 27.2 베타입니다.
- Swift 6 이상과 해당 macOS SDK. 단위 테스트는 XCTest가 포함된 전체 Xcode를 사용합니다.
- 외부 패키지 의존성 없음. 로컬 빌드는 ad-hoc 서명하며 공증된 배포 앱이 아닙니다.

```sh
./scripts/build.sh
open "$HOME/Library/Developer/TileLauncher/build/Tile Launcher.app"
./scripts/test.sh
```

Xcode가 별도 위치에 있으면 `DEVELOPER_DIR`를 해당 Xcode의 `Contents/Developer`로 지정합니다. 전역 `xcode-select`를 변경할 필요는 없습니다.

```sh
DEVELOPER_DIR="/Applications/Develop/Xcode-beta.app/Contents/Developer" ./scripts/build.sh
DEVELOPER_DIR="/Applications/Develop/Xcode-beta.app/Contents/Developer" ./scripts/test.sh
```

기본 앱 출력 경로는 `~/Library/Developer/TileLauncher/build`입니다. Desktop/iCloud 등의 동기화 폴더가 `.app`에 메타데이터를 덧붙여 서명을 깨뜨리는 것을 피합니다. `TILE_LAUNCHER_OUTPUT_DIR` 환경 변수로 출력 위치를 바꿀 수 있습니다.

`Package.swift`를 Xcode에서 열어 소스를 편집할 수 있습니다. 권한 검증과 실제 사용에는 위 스크립트가 만든 같은 경로의 `.app`을 사용하세요. 개발용 서명/앱 경로가 바뀌면 macOS 접근성 권한 재등록이 필요할 수 있습니다.

## 테마와 아이콘

설정은 **일반 / 모양 / 메뉴 / 등록 항목·프로필** 순서입니다. **모양**에서 유리·파스텔 또는 클래식·직각을 고르고, 메뉴·최근 창·등록 항목의 색을 각각 선택합니다. 같은 섹션의 작은/긴 타일은 같은 기본색이며 고정 메뉴·현재 데스크탑 창은 더 강하게 구분합니다. 색과 테마 선택은 저장됩니다.

기본색은 클래식의 메뉴 초록·최근 창 파랑·등록 항목 보라 계열이며, 유리 테마의 기본 메뉴는 노랑 계열입니다. 사용자 색은 두 테마에서 유지하고 명도·글자색은 자동으로 조정합니다. 섹션별 또는 전체 기본색 복원이 가능합니다. 배경과 상단 버튼은 공통 유리 재질입니다. 배경 색 레이어만 0.28로 낮추고 타일 불투명도는 유지합니다. 메뉴·최근 창에는 마우스 hover 채움과 2pt 테두리를 제공합니다.

기본 타일에는 선택한 색을 밝게 섞어 부드러운 파스텔 느낌을 주고, 클래식의 고정 메뉴·현재 데스크탑 강조에는 진한 기준 색을 유지합니다.

앱 아이콘은 파란 계단형 바탕에서 초록 타일이 오른쪽 위로 빠져나오는 모양입니다. 메뉴 막대에도 같은 형태의 단색 심벌을 사용합니다. 원본과 재생성 방법은 [아이콘 기록](Resources/Brand/README.md)에 있습니다. 설정 → 일반 → 시작에서 Option 호출을 끌 수도 있습니다.

## 사용

1. 실행하면 메뉴 막대에 타일 모양 아이콘이 생깁니다. ‘설정’에서 앱·폴더·다운로드·휴지통을 등록합니다. 화살표 또는 목록 이동으로 순서를 바꿉니다.
2. ‘접근성 권한 요청’을 누르고 시스템 설정에서 Tile Launcher를 허용합니다. 시스템 입력 감지와 다른 앱의 창 조회/전환에 사용합니다. 앱이 권한을 자동으로 허용하지 않습니다.
3. 좌/우 Option만 0.25초 누르면 패널이 열립니다. 항목을 클릭하면 바로 실행합니다. 숫자키로 고른 항목은 Option을 놓으면 실행합니다. 선택하지 않고 놓으면 닫힙니다. 메뉴 막대의 ‘열기’로는 키를 누르지 않고 사용할 수 있습니다.
4. 일반 폴더는 설정의 각 항목에서 ‘오버레이에서 탐색’ 또는 ‘Finder에서 열기’를 선택합니다. 오버레이에서는 하위 폴더·뒤로 가기·정렬·파일 실행을 제공합니다. **휴지통은 Finder에서 열기만 가능**하며 선택 메뉴 대신 이유를 표시합니다.
5. 시험용1.4.0의 최근 창은 개별 창 최근 사용 순서입니다. 크기는 위치(활성 모니터4×2·다른 모니터에서 보임2×2·안 보임1×1), 색은 각 앱의 가장 최근 창/나머지 창(진한색/파스텔)이며 창 없는 앱은 회색입니다. 작은 타일 둘은 세로로 쌓고 이전 줄의 빈칸을 메우지 않습니다. 자동 모드는 전체 목록을 유지하며 최대3.3줄 이후는 오버레이 안에서 스크롤합니다. 일반 설정에서 수동 최대 개수도 정할 수 있습니다. 개발 Mac 설치본1.2.0/공개1.1.5와 시험본의 규칙은 다릅니다.
6. 설정 → 시작 → ‘로그인 시 자동 실행’을 켜면 macOS 로그인 항목으로 등록합니다. 시스템 승인이 필요한 경우 안내 버튼으로 로그인 항목 설정을 엽니다. 끄면 등록을 해제합니다.
7. 오버레이 **왼쪽 위 핀** 또는 **`⌥X`**로 고정하면 같은 자리가 닫기 `×`로 바뀝니다. Option을 놓거나 다른 창을 클릭해도 유지되며 `×`·Esc·`⌘W`로 닫습니다. 닫은 후 다시 열면 고정은 해제되어 있습니다. 고정한 채 앱/파일을 선택해도 창은 유지하고, 설정을 열거나 디스플레이 구성이 바뀌면 닫습니다.
8. 설정 → 등록 앱·폴더 → **Dock에서 가져오기**로 고정된 앱·폴더를 순서대로 등록합니다. Finder는 맨 앞, 휴지통은 Dock 항목 맨 뒤에 포함합니다. 중복 항목은 기존 이름·여는 방식을 유지하며 Dock 순서로 앞에 놓고, 그 밖의 기존 항목은 뒤에 남깁니다. 새 폴더는 오버레이 방식입니다.

9. 설정 → 일반 → **숫자 단축키**에서 배치를 고릅니다. 기본은 `⌥1–9, 0` 등록 항목, `⌥⌘1–9, 0` 최근 창입니다. 반대로 바꿀 수도 있습니다. 0은 10번째이고 각 목록의 첫 10개에 숫자가 표시됩니다. 오버레이를 연 다음 숫자로 선택하고 Option을 놓으면 실행합니다. 다른 숫자로 선택을 바꾸거나 Esc로 취소할 수 있습니다. 오버레이 탐색 폴더는 숫자를 누르면 바로 안으로 들어가며 폴더 내부에서는 등록/최근 창 숫자키를 처리하지 않습니다.
10. 설정 → **메뉴**의 자동 수집은 기본 켜짐입니다. 모든 일반 앱의 macOS 메뉴 막대에서 클릭하거나 열린 메뉴·Help 검색에서 Enter로 고른 명령을 기록합니다. Apple 시스템 메뉴 전체·리본·우클릭·단축키 직접 실행은 제외하고, 복사·붙여넣기도 메뉴에서 골랐다면 포함합니다. 최근 메뉴는 회색 2×2이며 최근 90일 안의 런처 실행+관찰된 선택이 3회 이상이면 자주 사용 파스텔 2×2로 표시합니다. 고정 메뉴는 강조색 4×2입니다. 최근 메뉴는 **앱별 최근 30일 이내 또는 최근 5개**를 유지합니다. 두 기간은 설정 → 메뉴에서 바꿀 수 있습니다. 고정하면 맨 앞에 놓입니다. 오버레이 메뉴 타일은 핀 아래에 누적 합계만 표시합니다. 설정 목록에는 고정 메뉴도 누적 합계와 메뉴 막대/Tile Launcher 경로별 횟수를 표시하며, 타일에 마우스를 올려서도 확인할 수 있습니다. 자동 수집을 꺼도 Tile Launcher로 실행한 메뉴의 사용 횟수와 최근 시각은 기록합니다.
    전체 수집 끄기, 선택한 앱의 수집 중단, 자동 목록 비우기, 숨긴 메뉴 복원도 제공합니다. 메뉴 삭제는 해당 명령의 재수집도 막습니다. 수동 추가는 기존처럼 앱의 메뉴를 불러오거나 정확한 경로를 입력하며, 고정 메뉴로 추가합니다.
11. 설정 → **등록 항목·프로필**에서 이름을 입력하고 **빈 프로필 추가** 또는 **현재 구성을 복제**를 선택합니다. 빈 프로필은 등록 항목 없이 시작하고, 복제는 현재 등록 목록과 순서를 가져옵니다. 등록 항목 제목 옆에서 수동 선택하거나 macOS 집중 모드의 앱 필터에 프로필을 연결합니다. 자동 선택을 켜면 연결한 필터를 따르고, 없거나 해제되면 마지막 수동 구성으로 돌아갑니다. 기존 등록 항목은 ‘기본’ 프로필로 보존합니다.

오버레이는 **상단의 제목이나 빈 곳을 드래그**하여 옮깁니다(1.8.0부터 Option을 누르고 연 상태도 가능). 위쪽·양옆 여백과 버튼 사이의 빈 곳도 포함하며 핀/닫기·뒤로·프로필/설정 그룹과 본문 타일은 제외합니다. 일반 재호출은 커서 근처에서 화면 경계를 보정합니다. 폴더의 뒤로 가기는 핀/닫기와 같은 원형 Liquid Glass 버튼입니다.

**Option 재입력 보정:** 선택 없이 Option을 놓아 닫힌 뒤 기본 0.6초 안에 다시 누르면 커서가 이동했어도 직전 위치·크기로 바로 엽니다. 설정 → 일반 → Option 재입력 보정에서 켜기/끄기와 0.1–2.0초(0.1초 단위)를 조절합니다. 그보다 늦으면 기존처럼 0.25초 누른 후 커서 근처에 엽니다. 닫기는 즉시 처리합니다. Esc/닫기/설정·항목 실행·중간의 다른 키/보조키/클릭·화면/데스크탑 변경은 복원을 취소합니다. 정상 단축키와 고정 상태는 기존 동작을 유지합니다. 위치만 복원하므로 임시 프로필·폴더 탐색·선택은 일반 재호출과 같이 초기화됩니다.

**설정 이동:** 설정 아이콘/단축키는 일반, 메뉴 +는 현재 앱의 메뉴 추가 시트, 등록 +는 등록 항목·프로필을 바로 엽니다. **일반 → 권한**에서 접근성·앱 관리 설정을 각각 확인할 수 있습니다. 앱 관리는 다른 앱 업데이트/삭제용이며 런처에는 해당 기능이 없습니다. 일부 웹 앱에서 나온 차단 알림의 보완 경로는 넣었지만 실제 해소 여부는 별도 확인이 필요합니다.

설정 네 탭은 바깥/가로 16pt 기준을 공유하고 내부 상단 여백을 중복으로 두지 않습니다. 일반 권한→버전은 12pt, 버전 아래는 바깥 16pt입니다. 오버레이는 바깥 24pt·두 열 사이 24pt·제목→타일 12pt를 공유하며 최근 창 3.3줄과 등록 행 공간 계산도 같은 값을 씁니다. 설정 창의 기본 폭은 580pt이며 일반의 시작·재입력·숫자·최근 창·권한·버전 내용을 실제 SwiftUI 뷰로 측정해 높이를 맞춥니다. 마지막 버전 아래에는 설정의 기본 여백만 남깁니다. 작은 화면에서는 작업 영역 안으로 줄입니다. 처음 열거나 닫았다 다시 열면 이 기본 크기를 적용합니다. 창 크기는 계속 직접 조절할 수 있고, 이미 열린 창에서 탭만 바꿀 때는 조절한 크기를 유지합니다. 일반 탭은 작은 창에서 스크롤할 수 있고, 메뉴 탭은 추가 버튼을 하단에 유지한 채 자동 수집·고정 목록에 남는 높이를 배정합니다. 수집·표시의 자세한 설명은 ‘수집과 표시 안내’에서 펼쳐볼 수 있습니다.

오버레이에서 **왼쪽으로 쓸면 다음 프로필**, 오른쪽으로 쓸면 이전 프로필로 순환합니다. **⌥A/S는 이전, ⌥D/F는 다음**입니다. 이번 오버레이에서만 목록을 바꾸며 닫았다 열면 집중 모드/수동 설정에 따른 원래 구성으로 돌아갑니다. macOS 집중 모드 자체는 바꾸지 않습니다. 설정 → 등록 항목·프로필 → 프로필 순서에서 순서를 변경합니다.

오버레이에서는 **⌥W로 닫기, ⌥,로 설정**도 가능합니다. 기존 ⌘W/⌘,와 Esc는 그대로 사용할 수 있습니다.

스크린샷은 고정 후 Option을 놓고 `⌘⇧5`를 눌러 찍습니다. [macOS 스크린샷 도구](https://support.apple.com/ko-kr/guide/mac-help/-mh26782/mac)를 사용하므로 Xcode가 필요하지 않습니다.

핀 버튼이나 `⌥X`로 고정하면 Tile Launcher를 활성화하여 키 입력을 받습니다. 앱 창이 키 입력을 받는 동안에는 `⌘W`로 닫기, `⌘,`로 설정 열기, `⌘H`로 가리기, `⌘Q`로 종료할 수 있습니다. 다른 앱에 포커스가 있으면 그 앱의 단축키로 동작합니다.

Option으로 오버레이가 열린 뒤에는 Command를 추가로 눌러도 닫히지 않습니다. **Option을 계속 누른 채 `⌘,`**로 바로 설정을 열거나, **X**로 고정할 수 있습니다. 이 단축키는 오버레이가 키 입력을 받을 때만 처리합니다. 패널이 열리기 전의 Option 조합은 기존 앱에서 그대로 사용합니다.

동일 사용자에게서는 한 인스턴스만 실행합니다. **같은 버전·빌드면 기존 앱을 유지하고 새 프로세스가 종료**하며, **다르면 기존 앱이 정상 종료된 뒤 방금 실행한 앱으로 교체**합니다. 숫자가 낮은 버전을 나중에 실행해도 같은 규칙입니다. 표시 버전·빌드 번호·컴파일 결과 식별값을 비교하므로 버전 번호를 올리지 않은 로컬 재빌드도 구별합니다. 동일한 컴파일 결과를 다시 포장한 앱은 같은 빌드로 취급합니다.

실행 중인 앱의 버전은 시작할 때 기록하므로 같은 경로에 새 빌드를 덮어써도 비교가 유지됩니다. Finder가 기존 프로세스에 ‘다시 열기’만 전달하면 디스크의 새 빌드를 별도로 시작해 교체합니다. 종료가 거부되거나 15초 안에 완료되지 않으면 오류를 표시하고 중복 실행하지 않습니다. 버전 기록이 없는 이전 개발 빌드는 버전을 추정하지 않고 정상 종료 후 교체합니다.

오버레이는 Option을 누르고 열었든 고정했든 활성 앱과 창을 따라 상단 제목·등록 메뉴·최근 창 순서가 바뀝니다(1.8.0). 창 위치와 등록 프로필은 유지합니다. 숫자로 선택한 뒤 Option을 놓기 전, 마우스 버튼을 누르고 있는 동안에는 재배치를 미룹니다. 고정 메뉴는 유리 테마에서 노랑, 클래식에서 초록이며 현재 데스크탑 창은 파랑으로 구분합니다. 타일은 유리 배경보다 더 불투명하게 표시합니다.

입력 문자를 저장하지 않으며 창 이력은 실행 중 메모리에만 유지합니다. 앱 시작 전의 사용 순서를 복원하지 않습니다. 등록 항목과 표시 설정은 이 앱의 UserDefaults에 로컬 저장합니다.

## 첫 버전의 범위와 제한

- 등록 항목은 32pt 아이콘과 이름을 최소 60pt 정사각 타일에 담습니다. 은은한 배경/테두리와 마우스 올림·선택 표시를 사용하며, 하단 선반에 최대 3줄(작은 배치 2줄)로 표시하고 넘치면 스크롤합니다. 메뉴·최근 창은 같은 높이로 최대 3.3줄을 보여주며, 상단 여백을 없애고 패널 높이도 기존 크기·비율 범위 안에서 줄입니다.
- 데스크탑 구분/선택 이동은 선택적 macOS 내부 API로 보완합니다. OS 변경에 따라 제한될 수 있어 App Store 호환을 전제하지 않습니다. 아직 AX 제목을 제공하지 않은 창은 ‘다른 데스크탑의 창’으로 표시할 수 있으며 선택 시 제어 정보를 다시 조회합니다. 화면 녹화 권한이나 창 이미지는 사용하지 않습니다.

- 최근 창은 접근성 API가 제공하는 **OS 창**입니다. 같은 앱의 여러 창은 분리하지만 iTerm의 탭·분할은 각각의 창으로 만들지 않습니다.
- 최근 창은 현재 창을 포함하며 별도 최근 앱 목록은 표시하지 않습니다. 일반 Option 호출은 최근 순서·타일 크기·숫자를 고정하고 재호출 시 갱신합니다. 고정 모드는 선택 중일 때를 제외하고 활성 앱/창을 따라 갱신합니다. 직접 프로필을 선택하거나 메뉴 고정을 편집하면 그 변경은 즉시 반영합니다.
- 접근성 정보를 제공하지 않는 앱, 다른 Space·전체 화면·최소화 창의 동작은 실제 앱별 검증이 필요합니다. 조회는 백그라운드에서 시간 제한을 두고 수행합니다.
- 일반 폴더의 오버레이 탐색 권한은 macOS 설정에 따릅니다. 휴지통 타일은 **Dock과 같은 Finder 통합 휴지통**을 엽니다. 개별 볼륨의 `~/.Trash` 경로를 열거나 내용을 직접 읽지 않습니다. 외장 저장소의 휴지통 관리와 ‘되돌려 놓기’도 Finder에서 이용합니다. Tile Launcher에는 휴지통 탐색·파일 열기·복원·비우기를 구현하지 않습니다.
- 기존 등록 목록과 순서는 유지합니다. 여는 방식이 저장되지 않은 일반 폴더는 오버레이를 유지하며, 기존 휴지통은 Finder 전용으로 전환합니다. 자동 실행 상태는 macOS에서 읽으며 앱 시작 시 임의로 켜지 않습니다.
- 추가 날짜 메타데이터가 없는 파일은 생성일을 사용합니다. 폴더는 열거나 새로고침할 때 조회하고 백그라운드 감시·재귀 색인은 하지 않습니다.
- Dock 가져오기는 버튼을 누를 때만 수행합니다. 실행 중인 비고정 앱·최근 앱·최소화 창·웹 링크·개별 문서는 제외합니다. 사용할 수 없거나 지원하지 않는 항목은 건너뛴 개수를 안내합니다. Dock의 저장 형식은 공개 API 계약이 아니므로 OS 업그레이드 때 재검증하며, Dock 설정을 변경하거나 Dock을 종료하지 않습니다.
- 메뉴 자동 수집은 **실험 기능**입니다. 현재 앱의 접근성 메뉴 알림과 클릭 위치 확인을 조합하며 유휴 상태에서 전체 메뉴를 반복 조회하지 않습니다. 외부 선택 횟수는 명령의 최종 작업 성공을 보장하지 않습니다. 앱에 따라 알림/메뉴 구조가 없거나 응답이 늦으면 누락됩니다. 초기 연결 실패는 짧은 간격부터 제한 재시도하고, 앱 전환·종료·수집 중단 시 예약을 취소합니다.
- Help 검색 결과는 실제 메뉴 경로를 제한된 시간 안에 하나로 확인할 수 있을 때만 기록합니다. 검색어/입력 문자는 저장하지 않습니다. 대표적인 최근 문서/폴더와 동적 창 목록은 제외합니다. 기간과 최근 5개 조건에서 벗어나면 오버레이에서 숨기며 설정 목록에서는 재고정할 수 있습니다. 기간 확대 시 과거 항목을 다시 표시합니다. 빈도에는 메뉴별 최근 사용 시각 3개만 저장하며, 이전 버전의 날짜 없는 누적 횟수는 최근 사용으로 추정하지 않습니다. 실행할 때는 최신 메뉴 경로·활성 상태를 다시 확인합니다.
- 집중 모드는 사용자가 시스템 설정에서 연결한 앱 필터로 받습니다. 모든 집중 모드의 이름을 임의로 읽는 방식이 아닙니다. 실제 필터 전환/해제와 Excel 메뉴 실행 등 미검증 범위는 [검증 기록](docs/validation.md)에 남깁니다.
- 1.1.0 개발 구성은 정상 최대 1120×840pt, 작은 최소 512×420pt와 화면 여백 24pt를 사용합니다. 현재 프로필의 등록 행 수에 맞춰 높이를 조절하고 최근 창 아래 간격을 유지합니다. 작은 화면은 메뉴/뷰포트를 줄이며 패널을 담을 수 없는 화면은 지원 안내를 표시합니다.
- 전역 키 감지는 원래 앱의 입력을 차단하지 않습니다. 오버레이가 열리면 비활성화 패널이 키 입력을 받고 숫자 조합·`⌥X`·`⌘,`·`⌘W`·Esc를 로컬에서 처리합니다. 다른 앱에 포커스를 옮긴 경우 단축키는 해당 앱에 전달되며, 전역에서 감지한 Escape는 고정 패널도 닫을 수 있습니다.

## 개발 기록

### 작업 화면을 건드리지 않는 미리보기

`Sources/TileLauncher/PreviewFixtures.swift`에는 실제 앱·폴더·사용자 설정 대신 샘플 데이터를 쓰는 Xcode `#Preview`가 있습니다. `Package.swift`를 Xcode에서 열고 해당 파일의 Canvas를 사용합니다. 일반 앱의 키 감지·인스턴스 잠금·메뉴 막대를 미리보기에서 시작하지 않습니다.

```sh
DEVELOPER_DIR="/Applications/Develop/Xcode-beta.app/Contents/Developer" ./scripts/preview.sh /tmp/tile-launcher-previews
```

이 명령은 Xcode 도구로 컴파일하고 화면에 표시하지 않는 호스트에서 타일 이미지를 저장합니다. 실행 중인 Tile Launcher를 종료/재실행하지 않습니다. 라이트/다크 두 테마·사용자 색·작은 배치를 확인하며 격리된 SettingsStore의 색 저장·복원도 검사합니다. 앱 배경의 실제 Liquid Glass 합성·전역 키·드래그 성능 검증을 대신하지 않습니다. 네이티브 색 선택기/라디오 컨트롤은 이 PNG 방식으로 완전히 그려지지 않아 Xcode Canvas나 이후 실제 UI 확인이 필요합니다.

## 배포 파일 준비

`release/config.json`에 버전/빌드/지원 플랫폼을 두고 `scripts/release.py`로 독립 배포 ZIP을 만듭니다. 공개 1.0.0은 깨끗한 태그 소스의 Developer ID 서명·공증 앱이며, 로컬 build.sh의 ad-hoc 빌드와 구별합니다. 이전 공개 자산을 보존합니다. 첫 실행과 접근성 허용은 [설치 안내](docs/installation.md)를 확인하세요.

```sh
DEVELOPER_DIR=/Applications/Develop/Xcode-beta.app/Contents/Developer python3 scripts/release.py prepare
DEVELOPER_DIR=/Applications/Develop/Xcode-beta.app/Contents/Developer python3 scripts/release.py verify
```

깨끗한 Git 커밋에서 빌드하며 기존 실행 앱을 교체하지 않습니다. ZIP/체크섬/릴리스 메타데이터는 현재 구성 기준 `~/Library/Developer/TileLauncher/releases/v1.0.0`에 생성합니다. Desktop/문서/클라우드 동기화 폴더는 서명 작업 경로로 사용하지 않습니다. 서명·공증·GitHub 초안/게시 절차와 현재 검증 범위는 [배포 준비 문서](docs/release-guide.md)에 있습니다. 자격 증명이나 인증서 개인 키를 저장소에 넣지 않습니다.
